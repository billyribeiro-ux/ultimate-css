CSS Masking Mastery: mask-image, mask-composite & Gradient Masks

A mask is the alpha channel you control: an image whose pixels decide, per pixel, how visible the element is. We have used masks tactically — the spotlight in 15.14, the masked borders in 14.9 — but this lesson is the full system: gradient masks, the longhands, multi-layer compositing with mask-composite, SVG sources, and animation.

The mental model: mask vs. clip-path

Both hide parts of an element, but they are different machines. clip-path (Lesson 15.5) is geometry: a vector boundary, every pixel fully in or fully out, edges always hard. mask is imagery: a raster alpha map where every pixel can be 0%, 100%, or anything between — soft edges, feathered fades, photographic stencils. The rule of thumb:

/* hard geometric boundary → clip-path */
clip-path: polygon(0 0, 100% 0, 100% 85%, 0 100%);

/* per-pixel transparency, soft edges, image-based → mask */
mask-image: linear-gradient(to bottom, black 60%, transparent);

In a mask, opaque means visible and transparent means hidden — partial alpha gives partial visibility. The spotlight in Lesson 15.14 was exactly this: a radial gradient from solid to transparent acting as a circular alpha window.

Gradient masks: the workhorse

Because every gradient is a CSS-generated image, every gradient is a free, resolution-independent, animatable mask. Three patterns cover most production use:

/* 1 — edge-fade scroller: hint that a list keeps going */
.scroller {
  overflow-x: auto;
  mask-image: linear-gradient(to right,
    transparent, black 2.5rem, black calc(100% - 2.5rem), transparent);
}

/* 2 — vignette / spotlight (Lesson 15.14) */
.vignette {
  mask-image: radial-gradient(ellipse at center, black 55%, transparent 95%);
}

/* 3 — text fade-out "read more" */
.excerpt {
  max-block-size: 8lh;
  overflow: hidden;
  mask-image: linear-gradient(to bottom, black 60%, transparent);
}

The edge-fade pattern deserves its reputation: it replaces JavaScript scroll-shadow listeners with one declaration, and because the mask rides on the element (not the content), it stays put while the content scrolls beneath it.

The longhands, precisely

Masks are background-shaped: the longhands mirror background-* almost one-to-one.

mask-size, mask-position, mask-repeat
Exactly like their background twins — and, like them, animatable. An oversized mask plus an animated mask-position is the standard reveal mechanic (see the demo).
mask-mode: alpha | luminance | match-source
Which channel drives visibility. alpha reads the alpha channel (a transparent-to-black gradient works; white vs. black is irrelevant). luminance reads brightness (white shows, black hides — the SVG tradition). The default match-source flips per source: CSS images and SVG <mask> elements referenced by fragment default to luminance semantics for that element kind, while plain image/gradient sources are read as alpha. If a mask "mysteriously" shows everything, you are usually reading the wrong channel — set mask-mode explicitly.
mask-clip, mask-origin
The painting and positioning boxes (border-box, padding-box, content-box) — the same knobs that made the 14.9 masked-border trick possible.

Multiple layers and mask-composite

Like backgrounds, mask-image takes a comma-separated list — first layer on top. mask-composite then defines how each layer combines with the accumulated layers below it: add (union, the default), subtract (this layer minus the ones below), intersect (only where both are opaque), exclude (XOR). Subtraction is the headline act — punching holes:

/* a full rectangle, minus a circle = a notch cutout */
.ticket {
  mask-image:
    linear-gradient(black, black),                          /* everything */
    radial-gradient(circle 18px at 100% 50%, black 98%, transparent); /* the bite */
  mask-composite: subtract;
}

This is how ticket stubs, avatar status-dot cutouts, and tooltip notches are built with soft anti-aliased edges and no extra DOM. intersect is the other production value: intersect a shape mask with an edge-fade gradient to get a shaped and faded element in one element.

SVG sources and the inline-SVG aside

Gradients cannot draw a logo. For crisp arbitrary shapes, point mask-image at SVG — a file, a data URI, or an SVG <mask> fragment:

/* knockout: the element shows only inside the logo shape */
.brand-knockout {
  mask-image: url("data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' \
viewBox='0 0 24 24'><path d='M12 2 22 22 2 22Z'/></svg>");
  mask-size: contain;
  mask-repeat: no-repeat;
  mask-position: center;
}

/* or reference an SVG <mask> element (luminance by default) */
.photo { mask-image: url(#brand-mask); }

Aside — styling inline SVG: masks pair constantly with inline SVG icons, so remember that inline SVG is styleable CSS territory: fill: currentColor makes an icon inherit text color, stroke and stroke-width are plain properties, and the same custom properties that drive your mask gradients can drive the SVG's geometry colors. One color token, icon and mask in lockstep.

Animating masks

mask-position and mask-size interpolate exactly like their background counterparts — an oversized gradient mask slid across an element is the canonical "reveal sweep". For gradient stops, the gradient itself is not interpolable — unless the stop positions are @property-registered custom properties (Lesson 4.7), in which case the browser interpolates the variable and rebuilds the gradient every frame, exactly as the 15.14 spotlight animated --spot-x/--spot-y:

@property --reveal { syntax: "<percentage>"; inherits: false; initial-value: 0%; }
.reveal {
  mask-image: linear-gradient(90deg, black var(--reveal), transparent calc(var(--reveal) + 12%));
  transition: --reveal 0.8s ease;
}
.reveal.is-open { --reveal: 100%; }

This also retroactively explains Lesson 14.9's masked border: two composited mask layers carved the element down to a ring, and the conic spotlight was a third, animated layer intersected with it. You now own every part of that trick.

Performance and support

Masks rasterize at paint time — the same budget category as filters (Lesson 20.2). A static mask is cheap; an animated mask forces repaints of the masked subtree every frame, so keep animated masked regions small, prefer mask-position sweeps (the mask image itself is reused) over regenerating gradients, and silence sweeps under prefers-reduced-motion.

Support: production, unprefixed across all engines — Chrome 120+, Firefox 53+, Safari 15.4+. You will still meet -webkit-mask-image and friends in older codebases (and in this course's earlier demos, written defensively); new code targeting current browsers can drop the prefix, or keep it as a one-line courtesy to long-tail WebKit.

Try it yourself

Mini-exercise

Build a "torn ticket" card: (1) punch two circular bites (left and right edges) by adding a third mask layer and keeping mask-composite: subtract on the layers above the base. (2) Add a perforation line with a fourth layer: a repeating-linear-gradient of thin transparent slots, composited with subtract. (3) Then intersect the whole result with a bottom edge-fade so the ticket dissolves at its base — write out which mask-composite value each layer needs and verify your reasoning matches the render. Bonus: register a --bite-r with @property (Lesson 4.7) and transition the bite radius on hover.
