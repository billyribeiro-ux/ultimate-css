Blend Modes: mix-blend-mode, background-blend-mode & isolation

Every effect in this module so far changed what an element paints. Blend modes change what happens after painting: at the compositing stage, the browser recomputes each pixel of an element from the pixels already painted beneath it. Sixteen modes, three properties, and one fencing keyword (isolation) — all production-grade for years.

Blending is a compositing-stage operation

Normally an element's pixels simply replace (or alpha-composite over) whatever is behind them. With a blend mode, every result pixel becomes a function of two inputs: the source (the element's own painted color, Cs) and the backdrop (everything painted beneath it so far in the same stacking context, Cb). The mode is the function:

/* result = blend(source, backdrop), per pixel, per channel */
multiply:   C = Cs × Cb          /* can only darken            */
screen:     C = 1 − (1−Cs)(1−Cb) /* can only lighten           */
difference: C = |Cs − Cb|        /* self-inverting             */

This is why blend results are content-dependent: the same element looks different over every backdrop. That is the entire point — and, as we will see, the entire risk.

Three properties drive it. mix-blend-mode blends an element against its backdrop. background-blend-mode blends an element's own background layers against each other (no other element is involved). And isolation decides how far up the tree a blend is allowed to reach.

Sixteen modes, five families

Do not memorize sixteen formulas — memorize five families and the one representative you will actually ship from each:

Darkening — multiply, darken, color-burn
White becomes transparent in effect; black survives. multiply is the workhorse; darken takes the per-channel minimum; color-burn darkens with aggressive contrast.
Lightening — screen, lighten, color-dodge, plus-lighter
Black becomes transparent in effect; light accumulates. screen is the inverse of multiply; plus-lighter is a true additive (Porter–Duff "plus") operator, perfect for crossfades.
Contrast — overlay, soft-light, hard-light
Multiply in the shadows, screen in the highlights. overlay lets the backdrop decide; hard-light lets the source decide; soft-light is the gentle photographic variant.
Inversion / comparative — difference, exclusion
Subtract the two layers. difference gives full inversion against white; exclusion is the same idea with lower contrast.
Component (non-separable) — hue, saturation, color, luminosity
These do not mix channels independently; they swap whole perceptual components. color takes hue+saturation from the source and luminosity from the backdrop — instant tinting. luminosity is its mirror.

The signature production patterns

(a) multiply — kill the white box

A logo, signature scan, or stamp delivered as a JPEG on white. multiply makes white mathematically inert (1 × Cb = Cb) while black ink survives untouched (0 × Cb = 0) — no Photoshop round-trip:

.partner-logo img {
  mix-blend-mode: multiply; /* white pixels vanish on any light surface */
}

(b) screen — glow composites on dark

The inverse trick: on a dark theme, screen makes black inert and lets light stack up. Layer the neon glows from Lesson 15.6 with screen and overlapping halos brighten each other instead of occluding:

.glow-layer {
  mix-blend-mode: screen; /* black disappears; light adds up */
}

(c) difference — self-inverting text over unknown imagery

The classic fixed-header-over-hero problem: you cannot know what the text will sit on. White text in difference mode computes |1 − Cb| — it inverts whatever is behind it, staying light over dark imagery and flipping dark over light imagery:

.hero-title {
  color: white;
  mix-blend-mode: difference;
}

(d) color / luminosity — one-line tinting

Put a brand-colored element behind (or in front of) a photo and blend with a component mode. color paints your hue over the photo's light-and-dark structure; luminosity keeps the photo's structure and adopts the surface's hue:

.tinted-figure { background: oklch(55% 0.22 290); }
.tinted-figure img { mix-blend-mode: luminosity; }

(e) background-blend-mode — multi-layer compositing inside one element

The duotone hero with zero extra DOM: stack a gradient and an image as two background layers of the same element and blend them. Crucially, the element's text and children are not part of the blend — only the background layers are:

.hero {
  background-image:
    linear-gradient(135deg, oklch(50% 0.25 300), oklch(72% 0.18 45)),
    url("team.jpg");
  background-size: cover;
  background-blend-mode: color; /* try multiply or luminosity */
}

(f) plus-lighter — perfect crossfades

Crossfading two stacked images with plain opacity dims at the midpoint (0.5 over 0.5 ≠ 1). plus-lighter adds the premultiplied colors, so the two layers always sum to full intensity — this is the same operator the browser uses internally for view transitions:

.crossfade > img { position: absolute; inset: 0; mix-blend-mode: plus-lighter; }
.crossfade > .from { opacity: calc(1 - var(--t)); }
.crossfade > .to   { opacity: var(--t); }
/* at every --t, from + to = the original brightness — no mid-fade dip */

isolation: isolate — fencing the blend

Root cause first: a blended element composites against everything beneath it in its stacking context — including the page background, ancestors' backgrounds, and unrelated siblings. Drop a difference badge into a card component and it will happily invert the body background showing through. The blend leaks because nothing between the element and the root established a new backdrop boundary.

A stacking context is exactly that boundary: blending flattens at the nearest stacking context and cannot reach past it. isolation: isolate creates a stacking context that does nothing else — no paint, no layout change — purely to fence the blend at the component:

.card {
  isolation: isolate; /* blends inside compose against the card, not the page */
}

Debugging tip: many other properties create stacking contexts as a side effect — opacity < 1, transform, filter, will-change, position: fixed. If a blend mysteriously "stops working" after you add a hover transform to an ancestor, that transform fenced it. Conversely, if a blend leaks, the fix is one declarative line of isolation: isolate on the component root — never a structural rewrite.

Accessibility: contrast becomes content-dependent

With difference or overlay text, the rendered contrast is a runtime function of the backdrop — your design tool cannot certify it. At the exact moment a difference headline crosses a mid-gray region, |1 − 0.5| = 0.5: the text matches its backdrop and contrast collapses to zero. Test blended text against the worst-case region of every backdrop it can encounter (the WCAG procedure from Lesson 19.2), and keep a solid-color fallback path — a scrim or text-shadow — for content where legibility is non-negotiable. Decorative blends are fine; blended body text over arbitrary imagery is a contrast bug waiting to ship.

Performance: blending is paint-stage work

Blend modes are evaluated during paint/compositing of the layer tree — they are cheap in steady state but force the engine to keep the backdrop available and re-resolve the blend whenever either input changes. The budget rules from Lessons 20.1 and 20.2 apply directly: animating within a blended subtree (especially animating the blended element's position over a complex backdrop) triggers continuous repaints. Prefer animating something cheap underneath a static blended layer (as the demo below does with background-position), keep blended regions small, and never combine large blended surfaces with backdrop-filter on low-end targets.

Support: all of this is ancient, production-safe CSS — mix-blend-mode and background-blend-mode have shipped in every engine since ~2015. The one newer value, plus-lighter, is also cross-browser (Chrome 100+, Firefox 100+, Safari 15.4+). No @supports required.

Try it yourself

Mini-exercise

Build a card component containing a difference-blended price badge, and place the card on a page with a vivid gradient body background. (1) Observe the leak: the badge inverts the page gradient, not the card. (2) Fence it with isolation: isolate on the card. (3) Now add transform: translateY(-2px) on card hover and remove isolation — confirm the transform's implicit stacking context fences the blend identically, and write a one-line comment in your CSS explaining why. (4) Finally, find the worst-case backdrop pixel for the badge text and check it against the contrast procedure from Lesson 19.2.
