Lesson 18.3 · CSS Game

CSS-Only Tic-Tac-Toe

A fully playable two-player game built without JavaScript. Radio inputs track turns, ::before/::after draw X and O marks, and :has() selectors detect all eight winning combinations to display the winner.

How it works

Each of the nine cells contains two radio inputs: one for X and one for O. They share a name per cell so only one can be selected. A separate set of "turn" radios tracks whose turn it is. When a cell is clicked, CSS uses the :checked state cascade to show the appropriate mark and advance the turn.

Drawing X and O

The X mark is two pseudo-elements rotated 45 degrees in opposite directions, forming a cross. The O mark is a circle created with border-radius: 50% and a transparent center. Both are revealed only when their corresponding radio input is checked.

Turn tracking

A counter at the top of the game area uses the general sibling combinator and :has() to determine the current turn by counting how many cells have been filled. Odd fills mean it is O's turn; even fills (including zero) mean X's turn.

Win detection with :has()

The :has() selector checks for all eight winning lines (3 rows, 3 columns, 2 diagonals). When a winning combination is detected, a full-board overlay appears with the winner announced via ::after content.

Limitations

Without JavaScript there is no AI opponent, no draw detection beyond visual inspection, and resetting requires a page reload. But as a proof of concept, it demonstrates the remarkable logic CSS can express.

Accessibility limitations

This CSS-only game is a technical experiment, not a production pattern. It has significant accessibility gaps that cannot be fully resolved without JavaScript:

  • Missing input labels: The radio inputs have no visible text or aria-label attributes. A screen reader user cannot tell which cell they are activating. Each input needs a descriptive label such as "Place X in top-left cell" or "Place O in center cell" so the board position is communicated.
  • No state announcements: When a mark is placed or a winner is declared, sighted users see the visual change, but screen reader users receive no notification. Proper game state updates require aria-live regions that announce moves and outcomes — which requires JavaScript to update dynamically.
  • No semantic game structure: The board is a collection of div elements with no table or grid semantics. A screen reader cannot convey the spatial layout (row, column) that is essential to playing tic-tac-toe.

If you build a game for real users, use JavaScript to manage state, ARIA live regions for announcements, and proper labeling on all interactive elements. Treat this lesson as a demonstration of CSS selector power, not as a UI pattern to ship.
