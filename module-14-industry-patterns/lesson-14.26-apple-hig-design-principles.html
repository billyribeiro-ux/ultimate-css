Lesson 14.26 · Apple Human Interface Guidelines

Apple HIG: Design Principles in CSS

Apple's Human Interface Guidelines are not just advice — they are a complete spatial and typographic system. The 8pt grid, Dynamic Type scale, safe areas, vibrancy materials, and size classes form an architecture that CSS can express natively through custom properties, clamp(), env(), and container queries.

The 8pt spatial system

Every dimension in Apple's interfaces is a multiple of 8 points. Padding, margins, icon sizes, and component heights all snap to this grid. The half-step (4pt) exists for tight internal spacing only — label-to-icon gaps, separator insets. This creates a vertical rhythm that feels inevitable rather than designed.

In CSS, we express this as a token scale where each step doubles the intent, not the value:

:root {
  --hig-space-xxs: 0.25rem;  /* 4px  — tight only */
  --hig-space-xs:  0.5rem;   /* 8px  — icon gaps */
  --hig-space-sm:  1rem;     /* 16px — component padding */
  --hig-space-md:  1.5rem;   /* 24px — section gaps */
  --hig-space-lg:  2rem;     /* 32px — card padding */
  --hig-space-xl:  3rem;     /* 48px — section margins */
  --hig-space-xxl: 4rem;     /* 64px — page-level spacing */
}

The key insight: every value is a multiple of 8 (or 4 for xxs). No 5px, no 10px, no 14px. If something "feels off" in an HIG-compliant layout, check whether any spacing breaks this grid.

Safe areas and viewport-fit

Modern iPhones have the Dynamic Island and home indicator. The HIG requires that interactive content avoids these regions. CSS exposes them through environment variables:

/* Step 1: opt in to full-viewport rendering */
<meta name="viewport" content="..., viewport-fit=cover">

/* Step 2: respect safe areas */
.app-container {
  padding:
    env(safe-area-inset-top)
    env(safe-area-inset-right)
    env(safe-area-inset-bottom)
    env(safe-area-inset-left);
}

/* Or use logical properties */
.bottom-bar {
  padding-block-end:
    calc(0.75rem + env(safe-area-inset-bottom));
}

Without viewport-fit=cover, these variables resolve to 0px and the browser adds its own padding — you lose control of the edge-to-edge experience that HIG expects.

Dynamic Type scale

Apple defines 9 named text styles, each with a specific point size, weight, and leading. These scale when the user adjusts their system font size. In CSS, we use clamp() to approximate this scaling:

:root {
  --hig-large-title: clamp(1.75rem, 2vw + 1rem, 2.125rem);
  --hig-title1:      clamp(1.5rem, 1.5vw + 0.8rem, 1.75rem);
  --hig-title2:      clamp(1.25rem, 1vw + 0.7rem, 1.375rem);
  --hig-headline:    clamp(1rem, 0.5vw + 0.8rem, 1.0625rem);
  --hig-body:        clamp(1rem, 0.5vw + 0.8rem, 1.0625rem);
  --hig-callout:     clamp(0.9375rem, 0.4vw + 0.75rem, 1rem);
  --hig-subheadline: clamp(0.875rem, 0.3vw + 0.7rem, 0.9375rem);
  --hig-footnote:    clamp(0.75rem, 0.2vw + 0.6rem, 0.8125rem);
  --hig-caption:     clamp(0.6875rem, 0.2vw + 0.55rem, 0.75rem);
}

Headline and Body share the same size (17pt) but Headline is semibold. The type scale is not exponential — it is hand-tuned for readability at each level.

Vibrancy and materials

Apple's "materials" are translucent layers that let background content bleed through with varying intensity. The HIG defines four levels:

:root {
  --hig-material-ultra-thin: blur(2px);
  --hig-material-thin:       blur(8px);
  --hig-material-regular:    blur(20px);
  --hig-material-thick:      blur(30px);
}

.material-regular {
  backdrop-filter: saturate(180%) var(--hig-material-regular);
  background: oklch(98% 0.005 264 / 0.72);
}

@media (prefers-color-scheme: dark) {
  .material-regular {
    background: oklch(15% 0.005 264 / 0.72);
  }
}

The saturate(180%) is critical — Apple boosts saturation behind the blur to maintain color vibrancy. Without it, blurred backgrounds look washed out.

Platform-adaptive layouts: size classes

Apple uses two horizontal size classes: Compact (iPhone portrait, ~390px) and Regular (iPad, Mac). In CSS, container queries map more cleanly to this model than media queries because they respond to the component's actual available space, not the viewport:

.hig-layout {
  container-type: inline-size;
  container-name: hig-root;
}

/* Compact: single column */
@container hig-root (max-width: 599px) {
  .hig-content { grid-template-columns: 1fr; }
  .hig-sidebar { display: none; }
}

/* Regular: sidebar + content */
@container hig-root (min-width: 600px) {
  .hig-content {
    grid-template-columns: 280px 1fr;
  }
}

The 600px breakpoint approximates where iOS shifts from Compact to Regular. Using container queries means nested components adapt to their parent's size, not the window — exactly how SwiftUI's size classes work.

PE7 placement

The spacing tokens, type scale tokens, and material definitions all live in the tokens layer. Safe area padding is applied in utilities or layouts. Size-class-adaptive layouts belong in layouts. The material's backdrop-filter lives in components.

Try it yourself

Mini-exercise

Inspect every spacing value in the editor's Settings screen. Confirm that every padding, gap, and margin is a multiple of 8px (or 4px for tight gaps). Now try changing --hig-space-sm from 1rem to 0.875rem (14px) — notice how the layout immediately feels "off" even though the change is only 2px. The 8pt grid's power is in its consistency: break one value and the entire rhythm collapses.
