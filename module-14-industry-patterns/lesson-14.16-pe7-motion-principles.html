Lesson 14.16

The PE7 Motion Principles

Seven principles that separate principal-engineer-level motion from amateur animation. These are synthesized from every industry pattern in this module — the rules that Apple, Netflix, Stripe, Linear, and Vercel follow consistently, whether they write them down or not.

Principle 1: Motion has a job

Every animation must serve one of three purposes: guide attention to a change, confirm that a user action was received, or create spatial continuity between states. If the animation does not do one of these things, remove it. Decorative motion is technical debt — it adds complexity, consumes performance budget, and erodes trust with users who are sensitive to unnecessary movement.

Apple's parallax hero guides attention to the product. Netflix's hover-expand confirms the user's focus target. Stripe's tab indicator creates spatial continuity between panels. Every pattern in this module passes this test.

Principle 2: Enter is ease-out, exit is ease-in

Elements entering the viewport should decelerate into their final position — ease-out or cubic-bezier(0, 0, 0.2, 1). Elements leaving should accelerate away — ease-in or cubic-bezier(0.4, 0, 1, 1). State changes between two visible states use ease-in-out.

The physics are intuitive: an object arriving "slows down and lands." An object leaving "picks up speed and disappears." Reversing these feels wrong even if the user cannot articulate why. This principle is universal across Apple, Google Material, and every polished design system.

Principle 3: Stagger follows reading order

When multiple elements reveal in sequence, the stagger should follow the natural reading direction: top-left to bottom-right in LTR layouts. The stagger interval should be 40-100ms per element. Below 40ms and the stagger is imperceptible — the elements appear simultaneously. Above 100ms and the sequence feels sluggish — users wait instead of scanning.

Netflix's text reveal uses 80ms per word. The total animation for a 5-word headline is under 500ms. Fast enough to feel instant, slow enough to register as a cascade.

Principle 4: Scroll-driven animations must complete

If an animation is tied to scroll position, the user must be able to scroll far enough to complete it. A counter that counts up to 10,000 but only reaches 7,000 before the section scrolls past is broken. Use animation-range to ensure the animation completes within the available scroll distance. Test with short viewports.

Principle 5: Reduced motion eliminates decorative motion

prefers-reduced-motion: reduce eliminates all decorative motion — parallax, gradient cycling, shimmer, stagger reveals, spinning vinyl. Essential motion — a modal appearing, a tab panel switching, a popover opening — should still transition, but with opacity-only changes and no spatial movement. The content must remain accessible.

The test: does the page function identically with all motion removed? If yes, your reduced motion implementation is correct. If removing motion breaks functionality, you have a structural problem.

Principle 6: Animate only compositable properties

The browser can animate four categories of properties on the GPU compositor thread without triggering layout or paint: transform (including translate, rotate, scale), opacity, filter, and registered @property custom properties. Animating anything else — width, height, top, left, padding, margin, border-width — triggers layout recalculation on every frame and will drop frames.

Animatable property cheat sheet

Property Animatable? Performance Notes
transform Compositor Excellent GPU-accelerated. Use for all spatial motion.
opacity Compositor Excellent GPU-accelerated. Pair with transform for enter/exit.
filter Compositor Good GPU-accelerated. blur() and brightness() are common.
@property custom Compositor Good Registered types only. Enables gradient animation.
background-color Paint Moderate Triggers repaint. Acceptable for small elements.
box-shadow Paint Moderate Repaint on each frame. Use sparingly.
width / height Layout Poor Triggers full layout. Avoid. Use scale() instead.
top / left Layout Poor Triggers full layout. Use translate() instead.
padding / margin Layout Poor Triggers full layout. Never animate.

Principle 7: 60fps or nothing

If a CSS animation drops frames, simplify it. A smooth animation at 30fps looks worse than an instant state change. The human eye perceives dropped frames as janky, broken, or untrustworthy. An instant transition at least looks intentional.

Test with DevTools performance panel. Enable paint flashing. If you see flashing on every scroll frame, you are doing it wrong. The goal is zero layout triggers and minimal paint triggers during any animation.

If you cannot achieve 60fps with a particular effect, replace the animation with an instant transition. A clean cut is always better than a stuttering dissolve.

Synthesis

These seven principles are not rules imposed from outside — they are patterns extracted from the best work in the industry. Apple follows them. Netflix follows them. Stripe, Linear, and Vercel follow them. They are the natural consequence of taking motion seriously as an engineering discipline rather than a cosmetic afterthought.

A principal engineer does not memorize animation recipes. They internalize these principles and derive the right animation for any situation. That is the PE7 level — the level where you stop copying patterns and start understanding the system that generates them.
