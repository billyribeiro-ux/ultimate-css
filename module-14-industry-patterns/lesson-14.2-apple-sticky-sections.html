Lesson 14.2

Apple: Sticky Section Transitions

Apple's product pages pin sections to the viewport while content crossfades within them. The iPhone feature breakdown where each section sticks, the copy swaps, and the device image stays centered. This is position: sticky combined with animation-timeline: view().

What Apple does

On iPhone and Mac product pages, Apple pins a section to the top of the viewport. As you scroll, the pinned section stays put while internal content — feature headings, body copy, product images — crossfades in and out. The effect feels like a slideshow driven by scroll position rather than clicks.

The sticky foundation

position: sticky with inset-block-start: 0 pins an element to the top of its containing block while the user scrolls through that container. The element "sticks" once it reaches the top edge and "unsticks" when the container scrolls past. This is the mechanical foundation of the effect.

The trick is that the sticky container must be tall enough to create a long scroll region. Inside it, the visual viewport area is only one screen tall, but the container itself might be 3-4 screens tall — one "screen" per feature being presented.

The crossfade with view()

Each text block inside the sticky container uses animation-timeline: view(), which binds the animation to the element's visibility within its scroll container. As each text block enters the viewport, it fades in; as it exits, it fades out. The device image stays fixed in the center because it is a separate sticky element layered with z-index.

The z-index layering

The device image sits on a higher z-index than the text blocks. Text blocks scroll behind it, fading in and out as they pass through the visible area. This creates the illusion that the device stays stationary while features rotate around it.

Try it yourself

Mini-exercise

Add a fourth .feature section with your own headline. Then adjust the animation-range from entry 0% exit 100% to entry 20% exit 80% and observe how the fade timing tightens — the text stays fully visible for a shorter window. This is how Apple fine-tunes the "dwell time" for each feature.
