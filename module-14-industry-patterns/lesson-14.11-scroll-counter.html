Lesson 14.11

Vercel/GitHub: The Scroll-Triggered Counter

Animated number counters that tick up when they scroll into view. The technique uses @property to register an integer, animates it with @keyframes, triggers it with animation-timeline: view(), and displays the value via CSS counters.

What companies do

Marketing pages for Vercel, GitHub, Stripe, and many others show statistics like "10,000+ customers" or "99.9% uptime." When the stats section scrolls into view, the numbers animate from 0 to their target value, creating a satisfying counting-up effect that draws attention to the metric.

The @property integer registration

CSS cannot normally animate a number displayed as text. But if you register a custom property as an <integer>, the browser can interpolate it: @property --num { syntax: "<integer>"; inherits: false; initial-value: 0; }. A keyframe animation then transitions --num from 0 to the target value.

Displaying via CSS counters

The animated --num value is displayed using counter-set: num var(--num) and content: counter(num) on a ::after pseudo-element. As the integer interpolates, the counter updates frame by frame, creating the ticking effect.

Scroll trigger with view()

animation-timeline: view() ties the animation to the element's visibility. animation-range: entry 0% entry 60% means the counter completes its animation when the element is 60% visible — the user sees it count up as they scroll the section into view.

Fallback

Browsers without @property or animation-timeline support show the final number instantly. The CSS sets --num to the target value directly, and the @keyframes only override it when supported. Content is always accessible.

Mini-exercise

Change the customer count target from 10000 to 50000 and observe how the counter ticks faster through the higher range (because the animation duration stays the same). Then change the easing from ease-out to linear — notice how the deceleration at the end is what makes the counter feel like it "lands" on the final number.
