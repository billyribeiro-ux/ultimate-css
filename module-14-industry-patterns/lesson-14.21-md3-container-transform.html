Lesson 14.21 · Google Material Design 3

MD3: The Container Transform

When a list item is tapped, its card surface morphs into the detail view — the container stretches, the border-radius flattens, and the content crossfades. This "shared element" transition maintains spatial continuity. The View Transitions API makes it achievable in CSS.

Spatial continuity and why it matters

When a user taps a card and the detail view simply appears, the brain has to rebuild spatial context: "Where did this come from? How do I get back?" The container transform solves this by animating the card into the detail view. The surface is the same element, morphing in place. The user never loses track of where they are in the information hierarchy.

The View Transitions API

The CSS view-transition-name property assigns an identity to an element. When document.startViewTransition() is called, the browser snapshots the old state, applies the DOM change, snapshots the new state, and crossfades between them. If two elements across states share the same view-transition-name, the browser animates between their positions and sizes — a shared-element transition.

The critical CSS

/* On the card in list view */
.card { view-transition-name: card-hero; }

/* On the header in detail view */
.detail-header { view-transition-name: card-hero; }

/* Style the transition */
::view-transition-group(card-hero) {
  animation-duration: 350ms;
  animation-timing-function: cubic-bezier(0.2, 0, 0, 1);
}
::view-transition-new(card-hero) {
  animation: fade-in 200ms 150ms both;
}

Content crossfade delay

The 150ms delay on the content fade-in is deliberate. The container moves first (for 350ms), and the new content fades in partway through. This "container-first, content-second" choreography is a core MD3 principle — the surface establishes spatial context before the details arrive. Without the delay, everything moves at once and the transition feels chaotic.

Border-radius transition

The card has border-radius: 12px. The detail header has border-radius: 0. The ::view-transition-group automatically interpolates between them, so the corners animate from rounded to flat as the surface expands. This geometric morph is what makes the transition feel physical.

PE7 placement

The view-transition-name is a component property (it identifies the element). The ::view-transition-group animation styles are animations. The timing and easing reference tokens.

Mini-exercise

Change the animation-duration on ::view-transition-group(card-hero) to 800ms to see the morph in slow motion. Watch how the border-radius interpolates and the content crossfades midway. Then remove the 150ms delay on ::view-transition-new — the content appears immediately, making the transition feel rushed. The delay is what gives the container time to establish spatial context.
