Lesson 10.7

Trigonometry & Advanced Math: sin(), cos(), atan2() & pow()

CSS now ships a full scientific calculator: trigonometry, exponentials, real constants. That sounds academic until you realize what it buys — circular layouts without hand-computed coordinates, organic wave choreography, distance-based scaling, and type scales that are computed from a ratio instead of hardcoded from one. All of it production-ready.

The math CSS was missing

Lesson 13.4 covered the stepped-value functions — round(), mod(), rem(), sign(), abs() — and Lesson 21.15 put round() + clamp() to work. This lesson completes the set:

/* Trigonometric */
sin(x)  cos(x)  tan(x)          /* angle (or number = radians) in, NUMBER out */
asin(x) acos(x) atan(x)         /* number in, ANGLE out */
atan2(y, x)                     /* two values in, quadrant-correct ANGLE out */

/* Exponential */
pow(base, exp)  sqrt(x)         /* sqrt(x) === pow(x, 0.5) */
hypot(a, b, …)                  /* √(a² + b² + …) — true euclidean distance */
log(x, base?)   exp(x)          /* natural log by default; exp(x) === pow(e, x) */

/* Constants — usable anywhere a number is */
e  pi  infinity  -infinity  NaN

--circumference: calc(2 * pi * var(--radius));
inline-size: calc(infinity * 1px);   /* the "max it out" pill-radius idiom */

Types: angles in, numbers out

The mechanic everything else builds on: sin(), cos(), tan() accept an angle in any unit — deg, rad, turn, grad — or a bare number, which is treated as radians. They return a unitless number between −1 and 1. To turn that number back into geometry, multiply it by a length. This is the single most important pattern in the lesson:

:root {
  --angle: 60deg;
  --radius: 120px;
  --x: calc(cos(var(--angle)) * var(--radius));  /* number × length = length */
  --y: calc(sin(var(--angle)) * var(--radius));
}
.node { translate: var(--x) var(--y); }

The inverse functions go the other way — asin()/acos()/atan()/atan2() take numbers (or, for atan2(), two same-type values) and return an angle, ready to feed straight into rotate or a gradient direction.

Application 1 — the circular menu

The canonical use case: N items evenly distributed on a ring. One formula computes the angle from the index; cos()/sin() convert polar to cartesian. No design tool, no JS, no hand-typed coordinate table:

.menu {
  --count: 8;
  --r: 110px;
  position: relative;
}
.menu .item {
  /* −90deg starts the first item at 12 o'clock */
  --angle: calc(360deg / var(--count) * var(--i) - 90deg);
  position: absolute;
  inset: 50% auto auto 50%;
  translate:
    calc(cos(var(--angle)) * var(--r) - 50%)
    calc(sin(var(--angle)) * var(--r) - 50%);
}

/* Feed --i from sibling-index() where supported (Lesson 9.6
   used the same enhancement); per-item --i is the fallback */
@supports (width: calc(sibling-index() * 1px)) {
  .menu .item { --i: calc(sibling-index() - 1); }
}

Because everything derives from --count, adding a ninth item is a one-token change — the ring redistributes itself. Lesson 9.9's ray() achieves similar placement declaratively; use the trig version when you need the raw x/y values for shadows, gradients, or anchored decorations.

Application 2 — wave choreography with sin()

Lesson 9.6's stagger was linear: delay grows in equal steps, motion arrives as a uniform sweep. Feed the index through sin() instead and the row undulates — amplitude rises and falls organically, like a crowd wave:

.bar {
  /* one full wave across 10 items: 360° ÷ 10 = 36° per index */
  --wave: sin(calc(var(--i) * 36deg));         /* −1 … 1 */
  block-size: calc(2.5rem + var(--wave) * 2rem);
  translate: 0 calc(var(--wave) * -0.5rem);
  animation-delay: calc((var(--wave) + 1) * 150ms);
}

The shift in thinking: the index stops being a counter and becomes a sample position on a curve. Swap sin() for cos() to phase-shift, multiply the angle to add more wave cycles, sum two waves for interference patterns.

Application 3 — hypot() for true distance

hypot() returns the euclidean length of a vector — which means "distance from a focal point" becomes a pure CSS expression. Scale a grid of cells by their distance from the center cell and you get a fisheye falloff with two custom properties:

.cell {
  --dx: calc(var(--col) - 2);     /* center column = 2 */
  --dy: calc(var(--row) - 2);     /* center row    = 2 */
  --d: hypot(var(--dx), var(--dy));   /* 0 at center, √8 at corners */
  scale: calc(1 / (1 + var(--d) * 0.25));
  opacity: calc(1 - var(--d) * 0.18);
}

Compare with the naive abs(var(--col) - 2): that is Manhattan distance, and the falloff looks diamond-shaped. hypot() gives the circular falloff your eye expects.

Application 4 — pow() for computable scales

Lesson 4.5 built a modular type scale on a 1.25 ratio — with every step hardcoded, because CSS could not compute ration. Now it can. The ratio becomes a single token and the scale becomes arithmetic:

:root {
  --ratio: 1.25;                 /* one knob: try 1.2 or 1.333 */
  --step-0: 1rem;
  --step--1: calc(var(--step-0) * pow(var(--ratio), -1)); /* 0.8rem  */
  --step-1:  calc(var(--step-0) * pow(var(--ratio), 1));  /* 1.25rem */
  --step-2:  calc(var(--step-0) * pow(var(--ratio), 2));  /* 1.563rem */
  --step-3:  calc(var(--step-0) * pow(var(--ratio), 3));  /* 1.953rem */
  --step-4:  calc(var(--step-0) * pow(var(--ratio), 4));  /* 2.441rem */
}

The same trick generates exponential spacing scales and easing-like falloffs (pow(0.5, var(--i)) halves a value per index). sqrt() and log() round out the family — log() is the tool when you need "how many doublings fit", the inverse question of pow().

Application 5 — atan2() for aiming

atan2(y, x) converts a vector into the angle that points along it — quadrant-correct, and safe when x is zero (where naive atan(y / x) divides by zero). Give an element the vector to its target as two custom properties and it aims itself:

.arrow {
  /* vector to the target; same type for both args:
     two numbers, or two lengths */
  --dx: 120;
  --dy: -80;
  rotate: atan2(var(--dy), var(--dx));   /* returns an <angle> */
}

Static uses: connector arrows between cards whose offsets you know at build time. Dynamic uses: JS writes --dx/--dy from pointer position (two style writes), and CSS owns the rotation, the units, and the rendering — a clean division of labor.

Browser support

Production across the board: the trigonometric and exponential functions plus the e/pi/infinity constants shipped together in Chrome 111+, Firefox 108+, and Safari 15.4+. No @supports gate needed. The only progressive piece in this lesson is the optional sibling-index() feed for --i — keep per-item custom properties as the universal fallback, exactly as in Lesson 9.6.

Try it yourself

Mini-exercise

Build a "radar" component that uses four of the five applications at once. (1) Place 8 blips on a ring with the cos()/sin() pattern, driven by --count so the math survives a change to 12. (2) Size each blip with pow(0.85, var(--i)) so they shrink exponentially, not linearly — compare both and notice the difference. (3) Add a center "sweep" arm and aim it at blip 3 using atan2() with the blip's --dx/--dy. (4) Underneath, render a 12-bar signal strip whose heights sample sin(calc(var(--i) * 30deg)), then sum a second wave — sin(calc(var(--i) * 75deg)) * 0.5 — and watch interference appear. If you animate the sweep, gate it behind prefers-reduced-motion: no-preference.
