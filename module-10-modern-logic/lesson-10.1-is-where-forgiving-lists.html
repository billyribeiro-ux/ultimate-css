Lesson 10.1

:is() and :where(): Forgiving Lists

These two functions look identical and do almost the same thing. The one-character difference between them — specificity — is the reason every PE7 reset layer is written with :where() and every shortcut inside a layer is written with :is().

What they do

Both take a selector list and match any element that matches any selector in the list:

:is(h1, h2, h3) { font-family: var(--font-serif); }
:where(ul, ol) { padding: 0; margin: 0; }

Without :is() you would write h1, h2, h3 { ... }. That is fine for short lists. It becomes catastrophic when the list is nested: main h1, main h2, main h3, article h1, article h2, article h3 — six selectors where :is(main, article) :is(h1, h2, h3) is two.

The specificity difference

  • :is() takes the specificity of its highest-specificity argument. :is(.a, #b) scores 1,0,0.
  • :where() always scores 0,0,0, no matter what is inside it.

The PE7 rule

Use :where() when you want the rule to be easy to override. Use :is() when you want the rule to assert its own priority.

Resets use :where() because the reset must lose to every other layer. Shortcut selectors inside a component use :is() because they should behave like their longhand equivalents.

Forgiving parsing

Both functions are forgiving — if one argument is a selector the browser does not understand, the rule drops only that argument, not the whole list. This is the only safe way to use a newer pseudo-class alongside older ones:

:is(:has(img), :-webkit-any(.card)) { /* both paths tried, invalid ones skipped */ }

Without forgiving lists, a single unknown selector invalidated the entire list and you lost the whole rule. That is the old CSS behavior, and it is why polyfills existed. It is gone.

Live demo — specificity comparison

Wrapped in :where() — loses to p { color }, appears indigo.

Wrapped in :is(.class) — scores 0,1,0, wins against p, appears green.

Try it yourself

Mini-exercise

Replace :where(h1, h2, h3) with :is(h1, h2, h3) in the editor. Does the h1 { color: ... } override still work? It does — because both sides score 0,0,1. Now wrap the :is in a class: :is(.article h1, .article h2). The single-element override stops working. That is when you switch to :where().
