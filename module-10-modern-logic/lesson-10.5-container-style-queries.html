Lesson 10.5

Progressive enhancement

Container Style Queries

Container queries in Module 7 let a component react to its container's size. Style queries let it react to its container's intent: a parent declares a custom property, and any descendant can adapt. This is how you wire "parent says what it wants, child decides how to render it" without any new class names.

The pattern

.section { --layout: horizontal; container-name: section; container-type: inline-size; }
.section-vertical { --layout: vertical; }

@container section style(--layout: horizontal) {
  .card-list { display: flex; gap: 1rem; }
}
@container section style(--layout: vertical) {
  .card-list { display: grid; gap: .5rem; }
}

The parent decides its intent by setting a custom property. The child's layout adapts. No new class names leak into the child; the only contract is the property name.

Why this is better than a parent class

The traditional alternative is .section.vertical .card-list — a descendant selector that reaches down from the parent. That works, but it:

  • Tightly couples the child to a specific parent class name.
  • Increases specificity on the child, making it harder to override.
  • Cannot be set from inline style — the parent must carry the class.

Style queries invert this. The parent declares a property (which can come from inline style, a user setting, or a JavaScript state update), and the child decides independently whether that property's value matters to it.

Browser support

Chrome 111+ for custom properties, Safari 18+, Firefox 128+. Production-ready for custom-property-based style queries. Queries on arbitrary CSS properties (not just custom) are still shipping — stick to --name: value form and you are safe.
