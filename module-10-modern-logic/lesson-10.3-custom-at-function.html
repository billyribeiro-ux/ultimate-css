Lesson 10.3

Progressive enhancement

Custom @function

Sass gave us @function twelve years ago. Native CSS is finally catching up. @function lets you define a named, parameterized calculation that returns a value — the closing of a circle that started with Sass, PostCSS, and every build-step preprocessor.

The syntax

@function --fluid-size(--min, --max) {
  result: clamp(var(--min), 2vw + 1rem, var(--max));
}

h1 { font-size: --fluid-size(1.5rem, 3rem); }
h2 { font-size: --fluid-size(1.25rem, 2rem); }

Parameters are custom properties prefixed with --. The body contains normal declarations plus one required result: line that returns a value. You call the function with its name and arguments, the same way you call calc() or var().

What you'd use it for

  • Fluid typography — a single --fluid(--min, --max) function replaces dozens of hand-written clamp() calls.
  • Color tinting — @function --tint(--base, --amount) { result: color-mix(in oklch, var(--base), white var(--amount)); }.
  • Spacing scales — @function --sp(--step) { result: calc(0.25rem * var(--step)); }.

Why not just call this Sass?

Because Sass runs at build time. Native @function runs at compute time, in the browser, with access to live custom properties, live container dimensions, live media state. You can pass a CSS custom property into a function, and the function result updates when the property updates. That is not something any preprocessor can do.

Browser support

Experimental. Chrome 139+ behind a flag as of early 2026. Not for production. This lesson teaches the shape of the feature so you can adopt it the moment it ships. In the meantime, continue using hand-written clamp() and calc() — both are forward-compatible with the future @function definitions.
