Lesson 10.4

Progressive enhancement

Typed attr() — HTML Data in CSS

attr() has existed since CSS2, but until now it could only return a string for use in content:. The typed form lets it return numbers, lengths, colors, and percentages — feeding HTML data directly into any CSS property.

The old attr()

.item::after { content: attr(data-label); }

Useful, but narrow. It only works in content:. You could not do width: attr(data-width) because the browser had no way to know whether that string represented a length, a number, or nonsense.

The new typed attr()

.chart-bar {
  inline-size: attr(data-value type(<percentage>), 0%);
  background: oklch(70% 0.15 attr(data-hue type(<number>), 0));
}

The second argument of attr() is now a type() expression declaring the expected CSS syntax. The third argument is a fallback used if the attribute is missing or doesn't parse. Supported types include <number>, <length>, <percentage>, <color>, <angle>, and <length-percentage>.

What this unlocks

  • Data-driven visualizations. Bar charts, sparklines, progress indicators — all drawn purely from HTML attributes.
  • Themed components. A single <div data-hue="275"> can drive its entire color palette through oklch().
  • Animation targets. Store end-state values in HTML and animate to them without JavaScript.

Progressive, not imperative

Typed attr() is the right tool when the HTML is the source of truth for a value. When the value lives in JavaScript state, use a custom property set via element.style.setProperty(). The two approaches are complementary — the attr() path avoids a script trip.

Browser support

Chrome 133+, Edge 133+. Safari and Firefox not yet. Wrap in @supports. Fallback: set the custom property from HTML via inline style, which is widely supported.
