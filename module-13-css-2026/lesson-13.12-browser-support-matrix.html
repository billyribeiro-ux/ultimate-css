A complete decision matrix for every CSS feature covered in this course. Ship it, wrap it in @supports, or wait — the answer depends on your audience and risk tolerance.

The decision framework

Three tiers of deployment readiness:

  1. Ship it. All three engines support the feature in their last two stable releases. No wrapper needed. Use freely in production. Examples: nesting, color-mix(), @layer, OKLCH.
  2. Wrap in @supports. One or two engines support it; the feature enhances UX but is not critical to functionality. Provide a fallback path. The non-supporting browser gets a simpler but complete experience. Examples: interpolate-size, field-sizing, ::details-content.
  3. Wait. Only one engine supports it and the feature's absence would create a significantly broken or confusing UX if relied upon without a fallback. Use only if you can afford to provide a JavaScript fallback for non-supporting browsers, or if your audience is exclusively Chrome-based. Example: scroll-state queries in production-critical UI.

Interop 2026 focus areas

The Interop 2026 initiative prioritizes cross-browser alignment on:

  • Popover and dialog features — including popover="hint", closedby, and the ::backdrop transitions. Expect Firefox and Safari implementations in 2026-2027.
  • View transitions — cross-document transitions are a focus for full interop. Safari 18 shipped basic support; full feature parity is in progress.
  • Scroll-driven animations and state queries — Firefox has scroll-driven animations but not yet scroll-state container queries. Alignment is tracked.
  • Anchor positioning — Chrome shipped in 124. Firefox prototyping underway. Expect broad support by late 2026.

What is coming next (behind flags or early prototype)

  • CSS Mixins (@function) — author-defined CSS functions. Chrome has an intent to prototype. This will be the largest addition to CSS since custom properties.
  • Masonry layout — a native CSS grid mode for Pinterest-style layouts. Both Chrome and Safari have experimental implementations with different syntaxes. Spec discussion ongoing.
  • Sibling functions (sibling-count(), sibling-index()) — query position in a parent without custom properties. Chrome 133+ ships these; Firefox and Safari prototyping.
  • if() function — conditional values in CSS without @supports or media queries. Very early proposal stage.

Practical guidance for your production codebase

If a feature is in the "Ship it" column, use it today without hesitation. Every feature in the PE7 architecture (layers, container queries, scope, light-dark, OKLCH) is production-safe across all modern browsers. The new Module 13 features in the "Ship it" tier (nesting, relative colors, color-mix, math functions, :open) can be adopted immediately.

For "@supports" features: adopt them as progressive enhancements that improve the experience in Chrome. Your fallback is the feature not existing — the UI works, just without the enhancement. Never make these features load-bearing in your architecture.

Mini-exercise

Audit your current project's CSS against this table. For each feature you use: confirm it is in the "Ship it" tier. For each feature you want to adopt: check the decision column and write an @supports wrapper if needed. Document your support baseline (e.g., "last 2 versions of Chrome, Firefox, Safari") and use it as the gate for all CSS decisions going forward.
