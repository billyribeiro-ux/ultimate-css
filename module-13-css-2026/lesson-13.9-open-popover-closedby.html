Lesson 13.9

:open, popover="hint", and closedby (Interop 2026)

:open is Chrome 114+, Firefox 133+, Safari 17.2+. popover="hint" and closedby are Chrome 133+. Unified open-state styling, tooltip-level popovers that auto-dismiss, and declarative dialog close behavior.

:open — one pseudo-class for all open states

The :open pseudo-class matches any element in its "open" state: <details> when expanded, <dialog> when shown, popovers when visible. It replaces the older :popover-open (now an alias) and provides a single, memorable selector for conditional styling.

Use :open instead of [open] for attribute-based states — it is more specific about intent and works across element types.

popover="hint" — tooltip-grade popovers

popover="auto" dismisses when you click outside or open another auto popover. popover="hint" adds a further constraint: only one hint can be open at a time, and opening any other popover (auto or hint) closes the existing hint. This is the correct behavior for tooltips — you hover over a button, see its tooltip, move to another button, and the first tooltip disappears.

Hint popovers are subordinate to auto popovers: opening an auto popover closes all hints, but opening a hint does not close an auto popover (like a dropdown menu).

closedby — declarative dialog dismissal

<dialog closedby="any"> closes on click-outside, Escape, or explicit close. closedby="closerequest" closes only on Escape or the close button (not click-outside). closedby="none" requires explicit programmatic closing. This replaces the common JavaScript pattern of listening for clicks on the backdrop.

Real-world: tooltip system + controlled modal

A toolbar with multiple icon buttons, each showing a hint popover tooltip on hover/focus. Only one tooltip appears at a time. Combined with a modal dialog that uses closedby="closerequest" — clicking outside the modal does nothing (preventing accidental data loss in forms), but Escape still works as an escape hatch.
