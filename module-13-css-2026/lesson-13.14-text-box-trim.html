Lesson 13.14

text-box-trim: Precision Typography

text-box-trim and text-box-edge remove the invisible extra space above and below text — the "half-leading" that makes vertical alignment of text next to icons, images, and other elements an exercise in pixel nudging.

The problem

Every font has built-in vertical space above the tallest ascender and below the deepest descender. This space is invisible, but it affects layout. A heading inside a card with padding: 1rem does not sit exactly 1rem from the top — there is extra invisible space. Designers notice. Developers compensate with margin-top: -4px hacks that break when the font changes.

The fix

h1 {
  text-box-trim: both;
  text-box-edge: cap alphabetic;
}

text-box-trim: both trims the extra space from both the block-start and block-end of the text box. text-box-edge: cap alphabetic defines the trim boundaries — the cap height (top of capital letters) and the alphabetic baseline (bottom of lowercase letters without descenders).

Real-world: centering text next to an icon

.btn {
  display: inline-flex;
  align-items: center;
  gap: var(--space-xs);
  text-box-trim: both;
  text-box-edge: cap alphabetic;
}

Without text-box-trim, the text sits slightly higher than the icon because of the invisible half-leading. With it, the text and icon are perfectly centered on the cap height.

Browser support

Chrome 133+, Safari 18.2+, Edge 133+. Firefox has it implemented behind a flag. Use @supports (text-box-trim: both). Unsupported browsers show the normal spacing — a visual refinement, not a layout break.

Mini-exercise

Uncomment the text-box-trim lines. Watch the purple background on the heading shrink — that removed space was always there, pushing the text away from the padding edge. Now try changing text-box-edge to ex alphabetic — the trim changes to x-height instead of cap-height.
