shape(): Responsive Curved Clip Paths

Until now you had to choose: polygon() scales responsively but only draws straight lines; path() draws curves but is frozen in pixels. shape() closes the gap — an author-friendly drawing syntax with lines, Bézier curves, and arcs where every coordinate accepts percentages, lengths, calc(), and custom properties.

The gap, precisely: why path() clip-paths break responsively

clip-path: path() takes an SVG path-data string — and SVG path data is a sequence of unitless numbers. CSS has to interpret them somehow, so it maps them 1:1 to pixels in the element's coordinate space. There is no percentage syntax in path data, no calc(), no custom properties — the grammar predates all of them. The consequence: a curve drawn for a 400px card is a 400px curve forever. Resize the element and the clip does not stretch with it; it stays anchored at the top-left while the element grows out from under it. polygon() never had this problem (every vertex is a full CSS <length-percentage>) — but polygons cannot curve. That asymmetry is the entire reason curved section dividers shipped as SVG markup for a decade.

The shape() command syntax

shape() is a command list, like path data rewritten as CSS. Every coordinate is a real CSS value:

clip-path: shape(
  from <position>,        /* moveto — the starting point        */
  line  to 100% 0%,        /* straight segment to a point        */
  hline to 50%,            /* horizontal — only the x changes    */
  vline to 80%,            /* vertical — only the y changes      */
  curve to 0% 100%         /* cubic/quadratic Bézier...          */
    with 50% 80%,          /* ...with one or two control points  */
  smooth to 20% 50%,       /* Bézier mirroring the last control  */
  arc to 0% 20% of 16px,   /* elliptical arc of given radii      */
  close                    /* seal the outline                   */
);

Three details matter in production. First, by variants (line by, arc by) move relative to the current point. Second, arc takes the SVG arc options as keywords: cw/ccw for sweep, large/small for which of the two candidate arcs. Third — the headline — every coordinate slot takes %, lengths, calc(), and var(). Mixed units like calc(100% - 2rem) are exactly how you make fixed-size features (a 16px bite, a 2rem tail) survive on a fluid box.

Worked example 1: a responsive speech-bubble tail

The bubble body scales with content; the tail stays a crisp fixed size because its points mix percentages with pixel offsets:

.bubble {
  --tail: 14px;
  clip-path: shape(
    from 0% 0%,
    hline to 100%,
    vline to calc(100% - var(--tail)),
    hline to 48px,                          /* tail right edge   */
    line  to 24px 100%,                     /* tail tip          */
    line  to 24px calc(100% - var(--tail)), /* tail left edge    */
    hline to 0%,
    close
  );
  padding-block-end: calc(var(--tail) + 1rem);
}

Resize the bubble to any width: the body tracks 0–100%, the tail keeps its 24px geometry. With path() this required regenerating the string in JavaScript on every resize.

Worked example 2: a ticket with proportional arc bites

Two semicircular bites at the vertical midpoint of each edge — calc(50% ± radius) keeps them centered at any height, while the radius stays a fixed length:

.ticket {
  --bite: 12px;
  clip-path: shape(
    from 0% 0%,
    hline to 100%,
    vline to calc(50% - var(--bite)),
    arc to 100% calc(50% + var(--bite)) of var(--bite) small ccw,
    vline to 100%,
    hline to 0%,
    vline to calc(50% + var(--bite)),
    arc to 0% calc(50% - var(--bite)) of var(--bite) small ccw,
    close
  );
}

Worked example 3: the angled hero, now with a real curve

The standard angled-hero polygon gains a curved sweep — one curve to replaces the straight diagonal, with the control point pulled in rem so the curve depth is typographically stable:

.hero {
  clip-path: shape(
    from 0% 0%,
    hline to 100%,
    vline to 82%,
    curve to 0% 100% with 55% calc(100% - 5rem),
    close
  );
}

Animating shape()

Two shape() values interpolate when their command lists are compatible — same number of commands, same command types in the same order. This is the identical contract you learned for polygon() morphing in Lesson 15.5 (matching vertex counts), extended to curves: the browser interpolates endpoints and control points numerically. Keep a hover-state shape structurally identical to the rest state — pad with degenerate segments if necessary — and transition clip-path directly, or drive individual coordinates through registered custom properties.

Beyond clip-path

shape() is a <basic-shape>, not a clip-path special. It already works in offset-path — the motion-path property from Lesson 9.9 — which means responsive, percentage-based motion trajectories that previously demanded a frozen path(). Mask contexts (mask-clip shapes and friends) are specified to accept it as engines catch up. Learn the syntax once; apply it to clipping, motion, and masking.

The fallback chain

The production pattern is a two-step ladder: ship a straight-line polygon() approximation unconditionally, then upgrade to the curved shape() behind @supports. Unsupporting engines get the angled hero we have shipped for years; supporting engines get the curve:

.hero {
  /* baseline: every browser, straight diagonal */
  clip-path: polygon(0 0, 100% 0, 100% 82%, 0 100%);
}
@supports (clip-path: shape(from 0 0, close)) {
  .hero {
    clip-path: shape(
      from 0% 0%, hline to 100%, vline to 82%,
      curve to 0% 100% with 55% calc(100% - 5rem), close
    );
  }
}

Note the probe value: shape(from 0 0, close) is the smallest valid shape() — a cheap, future-proof feature test.

Browser support

Chrome 135+ and Safari 18.4+ for clip-path: shape(); Firefox: planned. Treat it as a progressive enhancement over a polygon() baseline as shown above — the fallback is the well-understood straight-edged version of the same design, so nothing is at risk in trailing engines.

Try it yourself

Mini-exercise

Convert one SVG section divider from a real project into pure CSS. (1) Recreate it as clip-path: shape(), using percentages for the structural points and rem/px via calc() for fixed-depth details. (2) Ship the polygon() approximation as the unconditional baseline and the shape() behind @supports (clip-path: shape(from 0 0, close)). (3) Add a hover transition that deepens the curve — keep the command list structurally identical so it interpolates (the 15.5 rule). (4) Bonus: reuse the same shape() as an offset-path (Lesson 9.9) and run a marker dot along your divider's edge.
