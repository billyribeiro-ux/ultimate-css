Lesson 13.13

contrast-color(): Automatic Accessible Text

contrast-color() takes any background color and returns either black or white — whichever meets WCAG AA contrast. The single most impactful accessibility function CSS has ever shipped.

The problem it solves

Design systems generate dozens of background colors from a single brand hue — 100 through 900 scale stops, semantic surfaces, component variants. For every background, a developer must manually choose a text color that passes contrast. Light backgrounds get dark text. Dark backgrounds get light text. Middle-value backgrounds are a judgment call that someone inevitably gets wrong.

contrast-color() eliminates this entire category of work. The browser does the WCAG math for you.

The syntax

color: contrast-color(var(--bg-color));

That is the entire API. Pass it a color. It returns black or white — whichever has higher contrast against the input. The browser evaluates against WCAG AA (4.5:1 for normal text).

Real-world: badge component with any background

@layer components {
  .badge {
    --badge-bg: var(--color-primary);
    background-color: var(--badge-bg);
    color: contrast-color(var(--badge-bg));
    padding: var(--space-2xs) var(--space-sm);
    border-radius: var(--radius-full);
    font-size: var(--size-xs);
    font-weight: var(--weight-semibold);
  }
  .badge-success { --badge-bg: var(--color-success); }
  .badge-warning { --badge-bg: var(--color-warning); }
  .badge-danger  { --badge-bg: var(--color-danger); }
}

Every variant gets correct text color automatically. Add a new .badge-ocean with any background — the text color is always readable. Zero manual contrast checking.

Why this matters for token systems

In Module 4, we manually defined --color-text-on-primary as a separate token. With contrast-color(), the "on" tokens can be derived:

:root {
  --color-primary: oklch(48% 0.22 275);
  --color-on-primary: contrast-color(var(--color-primary));
}

Change the brand color to anything — the text color adapts. This is the production-ready version of the --contrast-safe() function we imagined in Module 10.

Fallback pattern

Not every user is on the latest browser. Always provide a safe static color before the contrast-color() declaration. Browsers that do not understand contrast-color() will ignore the second line and use the fallback.

/* Fallback for browsers without contrast-color() */
color: oklch(98% 0 0);
color: contrast-color(var(--bg));
