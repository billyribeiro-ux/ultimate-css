scroll-state(scrolled): Directional Scroll Detection

Chrome 144+. Others not yet. Detect scroll position and direction in CSS using container scroll-state queries. No JavaScript scroll listeners, no IntersectionObserver, no requestAnimationFrame hacks.

What scroll-state queries are

Scroll-state container queries let you style elements based on the scroll state of their container. The syntax mirrors container queries: @container scroll-state(...). The container must be a scroll container (has overflow that can scroll).

scroll-state(scrolled: top)

@container scroll-state(scrolled: top) matches when the container has been scrolled away from the top — meaning the user has scrolled down. scrolled: bottom matches when scrolled away from the bottom. scrolled: left and scrolled: right work for horizontal scroll.

This enables pure-CSS "back to top" buttons, headers that shrink on scroll, and shadow indicators that appear when content is scrollable.

Related scroll-state queries

Chrome 133+ also shipped scroll-state(stuck: top) for sticky elements that are currently stuck, scroll-state(snapped: x) for snap-scrolled items, and scroll-state(scrollable: top) to detect if more content exists in a direction. Together these replace almost all JavaScript scroll-detection patterns.

Real-world: shrinking header on scroll

A sticky header that starts tall (logo + navigation) and shrinks to a compact bar once the user scrolls past a threshold. Previously required a scroll listener + class toggle. Now it is pure CSS: the page is the scroll container, the header checks scroll-state(scrolled: top) and applies compact styles.

Fallback

Wrap in @supports (container-type: scroll-state). Without support, the header stays in its default state — still functional, just not responsive to scroll position. The enhancement is non-critical: it improves space efficiency but is not required for usability.

The sticky header detects when its scroll container has scrolled away from the top. This is the signal to switch to "compact" mode, reclaiming vertical space for content.

Previously, this pattern required an IntersectionObserver or a scroll event listener with throttling, a class toggle, and careful cleanup to avoid memory leaks. Now it is a CSS container query.

The transition properties ensure the size change is smooth rather than jarring. Combined with the box-shadow that appears on scroll, the user gets clear visual feedback about their position in the document.

This pattern works for any scrollable container — not just the viewport. Dashboard panels, chat windows, documentation sidebars, and modal dialogs can all benefit from scroll-aware headers.
