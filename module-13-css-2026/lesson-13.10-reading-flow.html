Lesson 13.10

reading-flow: Accessible Visual Order

Chrome 137+. Others not yet. Finally solve the accessibility problem caused by CSS order — make keyboard tab order and screen reader order follow the visual layout, not the DOM source order.

The problem with CSS order

When you use order on flex or grid items to rearrange them visually, the DOM order stays unchanged. Screen readers announce items in DOM order. Keyboard Tab follows DOM order. The visual layout and the accessible reading sequence diverge — a WCAG failure that has existed since Flexbox shipped.

reading-flow fixes the disconnect

Set reading-flow: flex-visual on a flex container, and the browser's focus navigation order follows the visual order created by order and flex-direction. For grid, use reading-flow: grid-rows (row by row), grid-columns (column by column), or grid-order (by the order property).

Values for flex containers

reading-flow: flex-visual — follow the visual order that flex layout produces (accounting for order, flex-direction, and wrapping).

reading-flow: flex-flow — follow the flow direction defined by flex-flow.

Values for grid containers

reading-flow: grid-rows — read left to right, top to bottom, based on where items are placed in the grid.

reading-flow: grid-columns — read top to bottom, left to right (column-major order).

reading-flow: grid-order — follow the order property on grid items.

Real-world: responsive nav with reordered logo

A navigation bar where the logo is moved to the visual center using order on mobile but stays at the start on desktop. Without reading-flow, a keyboard user tabs to the logo first (DOM order) even though it appears in the middle. With reading-flow: flex-visual, tab order matches what the user sees.

Mini-exercise

Remove reading-flow: flex-visual and Tab through the nav. Notice how focus jumps to the logo first (it is first in the DOM), then to links, even though the logo appears in the center.
