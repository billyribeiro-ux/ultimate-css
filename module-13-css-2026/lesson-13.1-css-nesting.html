Lesson 13.1

CSS Nesting: Native, No Preprocessor

Chrome 120+, Firefox 117+, Safari 17.2+. Every modern browser ships native CSS nesting today. The preprocessor tax is over — write nested rules directly in your stylesheets with zero build step.

The & nesting selector

The & selector represents the parent rule's selector list. It works exactly like Sass's &, but it runs in the browser — no compilation required.

Any rule written inside another rule is a nested rule. The browser expands it by prepending the parent selector. .card { & h2 { ... } } becomes .card h2 { ... } in the resolved stylesheet.

Nested rules, nested media, nested @layer

You can nest media queries inside selectors — the browser scopes them automatically. You can also nest @layer blocks inside selectors, though this is rarely useful in practice.

Nested @media is the real win: instead of repeating a selector inside a media query block, you write the query inside the selector. The component stays together in one place.

When nesting helps vs when it hurts

Nesting is a readability tool, not a specificity tool. The output CSS has the same specificity whether you nest or not. The rule: never nest more than 2-3 levels deep. Beyond that, you are creating the same unreadable selectors that Sass enabled for a decade.

Good nesting groups a component's internal styles. Bad nesting recreates the DOM tree in CSS.
