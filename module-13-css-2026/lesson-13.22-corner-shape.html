Lesson 13.22

corner-shape & superellipse(): Native Squircles

For twenty years border-radius has drawn quarter-circles — and quarter-circles are why your "rounded" cards never quite look like Apple's. corner-shape changes the curve character of every corner: squircles, bevels, scoops, and notches, all riding on the radii you already declare, with automatic graceful degradation.

Why border-radius corners look "pinched"

Root cause: border-radius joins each straight edge to a quarter-circle arc. At the join point the two pieces share a tangent (no visible kink), but the curvature jumps instantly from zero (straight line) to 1/r (circle). Your eye is remarkably good at detecting that discontinuity — it reads as a subtle "pinch" where the corner begins, especially at large radii. Industrial designers call the fix curvature continuity: the curvature itself must ramp smoothly from zero into the corner and back out. That is what a squircle does, and a circle, by definition, cannot.

A decade of hacks, now obsolete

Apple's continuous-curvature corners (iOS icons, hardware bezels) are superellipse-derived, and the web spent a decade approximating them: 9-slice image masks (blurry, unscalable), clip-path: polygon() with 40–80 hand-computed points (hard edges, clipped shadows), inline SVG path wrappers (extra DOM, no border/outline integration). Every one of those techniques is now legacy. The native property is one declaration and inherits everything the border system already knows.

The corner-shape property

The key mental split: border-radius sets the size of the corner region; corner-shape sets the curve drawn inside it. They compose — without a radius, corner-shape has no region to shape:

.card {
  border-radius: 24px;       /* how big the corner is   */
  corner-shape: squircle;    /* what curve fills it     */
}

/* the value space */
corner-shape: round;            /* default — today's quarter-circle */
corner-shape: squircle;         /* continuous curvature, iOS-style  */
corner-shape: bevel;            /* straight 45° cut                 */
corner-shape: scoop;            /* concave quarter-circle (inward)  */
corner-shape: notch;            /* square step cut into the box     */
corner-shape: superellipse(4);  /* parametric — see below           */

Per-corner control mirrors border-radius's longhands — mix characters in one box:

.ticket {
  border-radius: 1rem;
  corner-top-left-shape: squircle;
  corner-top-right-shape: squircle;
  corner-bottom-left-shape: scoop;   /* the torn-stub bites */
  corner-bottom-right-shape: scoop;
}

superellipse(k): the exponent, precisely

The keywords are presets on one mathematical dial. A superellipse is the curve |x|k + |y|k = 1, and superellipse(k) hands you the exponent directly:

  • k = 2 — a circle: exactly today's round behavior, curvature discontinuity included.
  • k = 4 — approximately the iOS squircle: curvature eases in from the straight edge, peaks mid-corner, eases out. The "pinch" disappears.
  • k → ∞ — the curve approaches a square corner; large finite values give barely-softened rectangles.
  • k < 1 — the curve inverts inward: concave, scoop-like corners from the same dial.
.btn   { border-radius: 14px; corner-shape: superellipse(4); }
.chip  { border-radius: 12px; corner-shape: superellipse(8); }  /* squarer */
.scoop { border-radius: 16px; corner-shape: superellipse(0.6); } /* concave */

A design-system token: --corner-character

Because the curve character is now independent of the radius, it belongs in your token layer (Lesson 4.1) next to — not inside — your radius scale. One custom property gives an entire product its corner personality, the same way Material 3's shape scale (Lesson 14.19) and Apple's HIG concentricity rules (Lesson 14.26) treat shape as a system-level decision:

:root {
  --corner-character: superellipse(4);  /* the brand's curve */
}
.button, .card, .modal, .input {
  corner-shape: var(--corner-character);
  /* radii still come from the existing scale: --radius-s/m/l */
}
/* rebrand to sharp-tech? one line: */
:root.theme-angular { --corner-character: bevel; }

bevel, scoop, notch: shapes without clip-path

bevel gives cyberpunk/HUD panels and cut-corner tags; scoop gives ticket-stub bites and bracket shapes; notch gives stepped, machined corners. Previously these were clip-path territory — which brings us to the decisive advantage:

.tag {
  border-radius: 0 12px 0 12px;
  corner-shape: bevel;
  border: 1px solid oklch(70% 0.15 200);
  box-shadow: 0 8px 24px oklch(20% 0.05 270 / 0.4);
  outline-offset: 2px; /* focus ring also follows the bevel */
}

Borders, shadows, and outlines follow the shape. corner-shape redefines the box's actual contour, so the border traces the squircle, box-shadow is cast by the squircle, and the focus outline hugs it. A clip-path hack does none of that — it clips the shadow off entirely and leaves the focus ring rectangular. This is the difference between styling a shape and faking one.

Graceful degradation is automatic — often without @supports

Here is the rare and valuable nuance: a browser that does not understand corner-shape simply ignores the declaration and renders the border-radius you already set — ordinary rounded corners. For squircles and most bevels that fallback is aesthetically acceptable as-is, so unlike almost every feature in this module, you frequently need no @supports block at all. Reserve @supports (corner-shape: squircle) for cases where the shape is load-bearing — e.g. a notch that must align with an adjacent cut, where falling back to round would misalign the seam.

Browser support

Chrome 139+ (and Chromium-based browsers). Firefox: planned. Safari: planned. Treat it as a progressive enhancement with a built-in fallback — unsupporting engines render standard rounded corners from your border-radius, which is exactly the pre-2026 status quo. No polyfill exists or is needed.

Try it yourself

Mini-exercise

Add a --corner-character token to the design system you built in Lesson 4.1 and wire it into your button, card, and modal components alongside the existing radius scale. (1) Ship it with superellipse(4) and confirm in an unsupporting browser that the round fallback needs no @supports. (2) Build one ticket-stub component mixing corner-*-shape longhands (squircle on top, scoop on the bottom corners) and verify its box-shadow traces the scoops. (3) Identify the one case in your UI where falling back to round would misalign with a neighbor — and gate only that rule behind @supports (corner-shape: notch).
