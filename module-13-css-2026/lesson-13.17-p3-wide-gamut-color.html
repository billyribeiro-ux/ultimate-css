Lesson 13.17

Wide-Gamut P3 Color: Beyond sRGB

The color(display-p3 1 0.5 0) function accesses the full P3 color gamut — 50% more colors than sRGB. Vivid reds, deep greens, electric blues that sRGB literally cannot display are now one CSS function away.

Why P3 matters

sRGB was standardized in 1996 for CRT monitors. It covers roughly 35% of the colors the human eye can perceive. The Display P3 gamut — used by every Apple device since 2016, most flagship Android phones, and an increasing number of desktop monitors — covers about 50% more colors than sRGB. That means vivid, saturated reds, greens, and blues that were previously impossible in CSS are now available.

The difference is not subtle. A P3 red is noticeably more vivid than the most saturated red sRGB can produce. A P3 green is richer and deeper. Brands that demand "that exact red" on Apple devices can finally deliver it.

The color() function

/* Explicit P3 coordinates */
.brand-hero {
  background: color(display-p3 1 0.2 0.1);
}

/* Fallback pattern for older browsers */
.brand-hero {
  background: oklch(63% 0.26 25);              /* sRGB fallback */
  background: color(display-p3 1 0.2 0.1);     /* P3 override */
}

The color() function takes a color space name followed by channel values in the 0-1 range. For display-p3, the three channels are red, green, and blue — same conceptual model as sRGB, but the gamut boundaries are wider.

Progressive enhancement with @media

:root {
  --accent: oklch(65% 0.22 25);
}

@media (color-gamut: p3) {
  :root {
    --accent: oklch(65% 0.29 25);
  }
}

The color-gamut: p3 media query detects whether the display supports P3. Use it to serve higher-chroma values only to screens that can render them. On sRGB displays, the browser would clamp the extra chroma anyway — but the media query lets you choose intentionally rather than relying on gamut mapping.

color-mix() in P3

/* Mix two P3 colors in the display-p3 space */
.overlay {
  background: color-mix(in display-p3,
    color(display-p3 1 0.2 0.1) 60%,
    color(display-p3 0.1 0.1 0.9));
}

The color-mix() function accepts any color space as its interpolation space. Mixing in display-p3 keeps the result within the P3 gamut and avoids unintended sRGB clamping during interpolation.

OKLCH already supports P3

Here is the key insight: OKLCH is a gamut-agnostic color model. When you write oklch(65% 0.29 25), that color may already be outside sRGB. If the display supports P3, the browser renders it in P3 automatically. You do not need color(display-p3 ...) at all — just increase the chroma value in OKLCH beyond what sRGB can hold.

/* sRGB-safe red */
--red-srgb: oklch(63% 0.22 25);

/* P3-gamut red — higher chroma, same hue */
--red-p3:   oklch(63% 0.29 25);

The practical difference: color(display-p3 ...) is useful when you have exact P3 coordinates from a design tool. OKLCH with high chroma is useful when you want to push saturation beyond sRGB without leaving a perceptually uniform space.

Real-world: brand color on Apple devices

A client delivers a brand color spec: "Display P3 red, coordinates (1.0, 0.15, 0.1)". In sRGB, the closest approximation is a duller, less vivid red. With the color() function, you can match the brand spec exactly on every P3-capable screen — which includes every iPhone, iPad, and Mac sold in the last decade.

@layer tokens {
  :root {
    --brand-red: oklch(60% 0.24 25);
  }
  @media (color-gamut: p3) {
    :root {
      --brand-red: color(display-p3 1 0.15 0.1);
    }
  }
}

Browser support

The color() function and display-p3 color space are supported in Chrome 111+, Firefox 113+, Safari 15+. The color-gamut media query is supported in all modern browsers. Ship with an sRGB fallback for older browsers.
