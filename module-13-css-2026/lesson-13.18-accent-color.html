Lesson 13.18

accent-color: One-Line Form Theming

accent-color: oklch(55% 0.22 275) — one property, one line, every form control themed: checkboxes, radio buttons, range sliders, progress bars. The end of checkbox-rebuilding hacks.

The problem it solves

Before accent-color, theming a checkbox required hiding the native control with appearance: none, rebuilding it from scratch with pseudo-elements, managing focus states, handling keyboard accessibility, and testing across browsers. A single themed checkbox could require 30+ lines of CSS. Multiply that by every form control type and every brand color variant.

accent-color replaces all of that with one line.

The syntax

/* Theme every form control on the page */
:root {
  accent-color: oklch(55% 0.22 275);
}

/* Or scope to a specific form */
.settings-form {
  accent-color: oklch(65% 0.20 150);
}

The browser applies the accent color to the "accented" parts of form controls: the checked state of checkboxes and radio buttons, the filled portion of range sliders and progress bars. The browser automatically handles contrast for checkmark colors and other internal elements.

What it themes

  • Checkboxes — the checked background fill
  • Radio buttons — the selected dot and ring
  • Range sliders — the filled track portion
  • Progress bars — the filled bar

Combined with color-scheme

:root {
  accent-color: oklch(55% 0.22 275);
  color-scheme: light dark;
}

When you combine accent-color with color-scheme: light dark, the form controls adapt to both light and dark modes automatically. The browser adjusts the accent color's contrast relationships for each scheme. Zero media queries needed for form control theming.

When accent-color is not enough

Use custom controls instead of accent-color when you need:

  • Custom shapes (a toggle switch instead of a checkbox)
  • Animation on state change
  • Multiple colors within a single control
  • Custom icons inside the control (a brand-specific checkmark)

For everything else — settings pages, admin panels, consent forms, surveys — accent-color is the right tool. It preserves native accessibility, keyboard behavior, and platform conventions.

In the PE7 layer stack

@layer reset {
  :root {
    accent-color: var(--color-primary);
    color-scheme: light dark;
  }
}

Place it in the reset layer. It is a global default that components can override when needed.

Browser support

Chrome 93+, Firefox 92+, Safari 15.4+. All modern browsers. Ship without fallback — browsers that do not support it simply render the default OS accent color.

Mini-exercise

Change the accent-color value to three different OKLCH colors and watch every control update simultaneously. Then remove accent-color entirely and observe the browser's default — that is what your users see when you do not set it. One line versus thirty lines of checkbox hacks. The choice is clear.
