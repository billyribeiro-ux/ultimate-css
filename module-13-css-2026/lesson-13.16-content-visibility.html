Lesson 13.16

content-visibility: Rendering Performance

content-visibility: auto tells the browser to skip layout and paint for off-screen content. On long pages, this can reduce initial rendering time by up to 7x — with one line of CSS.

The problem

A documentation page with 50 sections. The browser renders all 50 sections before showing anything — even though only 3 are visible in the viewport. Every section's layout, paint, and composite must complete before the first frame. On a mid-range phone, this can take several hundred milliseconds.

The fix

section {
  content-visibility: auto;
  contain-intrinsic-size: auto 500px;
}

content-visibility: auto tells the browser: if this element is off-screen, skip its layout and paint entirely. Render it only when it is about to scroll into view.

contain-intrinsic-size: auto 500px provides an estimated height for the off-screen element so the scrollbar is correctly sized. The auto keyword means the browser remembers the real height after the element is first rendered and uses it on subsequent relayouts.

Where it fits in the PE7 stack

content-visibility is a layout-layer concern. It affects rendering, not visual styling. In a PE7 project, it lives in the layout layer alongside your structural primitives:

@layer layout {
  .section {
    content-visibility: auto;
    contain-intrinsic-size: auto 600px;
  }
}

What not to do

  • Do not apply to elements that are always visible (nav, hero). It adds overhead for elements the browser would render anyway.
  • Do not use on elements that need to be found by in-page search (Ctrl+F) — content-visibility: auto can prevent text from being searchable until rendered. This is a known limitation being addressed by browsers.
  • Do not use without contain-intrinsic-size — the scrollbar will jump as off-screen sections get heights of zero.

Browser support

Baseline since September 2025. Chrome 85+, Firefox 125+, Safari 18+. Ship without @supports.

Mini-exercise
