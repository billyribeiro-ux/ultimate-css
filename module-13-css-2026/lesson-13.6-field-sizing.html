Lesson 13.6

field-sizing: content (Auto-Sizing Form Fields)

Chrome 123+, Edge 123+. Firefox and Safari not yet. A single CSS property makes textareas, inputs, and selects grow to fit their content — replacing every JavaScript autosize library ever written.

The property

field-sizing: content tells a form field to size itself based on its content rather than a fixed number of rows/columns. As the user types, the field grows. When content is deleted, it shrinks. No JavaScript event listeners, no hidden measurement elements, no layout thrashing.

Where it works

Apply it to <textarea> (the primary use case), <input> (text, number, email — the width adjusts to content length), and <select> (width adjusts to the selected option text). The most impactful use is textarea height auto-sizing.

Respecting bounds

min-height and max-height still work as expected. Set min-height: 3rem for a minimum visible area and max-height: 20rem to cap growth. The field auto-sizes within those bounds and scrolls if content exceeds the max.

The chat input pattern

The most common real-world use: a message composer that starts as a single line (like an input) and grows vertically as the user types a longer message. Previously this required an input event listener, a hidden clone element, and manual height assignment. Now it is one CSS declaration.

Fallback

Without support, the field uses its default fixed size. The form remains fully functional — just not auto-sized. No @supports wrapper needed unless you want to adjust other layout properties when the feature is absent.

Mini-exercise

Remove field-sizing: content from the message input and observe the difference — the textarea stays at one row regardless of content. Then add it back and set max-height: 5rem to see it cap at a reasonable size and start scrolling. This is the production pattern: always set bounds.
