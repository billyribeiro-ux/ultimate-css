Progressive enhancement

Lesson 13.5

interpolate-size: Animate to auto

Chrome 129+. Firefox and Safari not yet. The single most requested CSS feature for decades: smoothly transition an element's height from 0 to its natural content height — no JavaScript measurement required.

The problem it solves

CSS has never been able to animate to height: auto. You could transition from 0 to a fixed pixel value, but if the content changes length you get clipping or empty space. Every accordion, collapsible panel, and disclosure widget needed JavaScript to measure the content and set an explicit target height.

interpolate-size: allow-keywords

Set interpolate-size: allow-keywords on :root or any container. This opts the element (and its descendants) into treating keyword sizes like auto, min-content, max-content as interpolable — meaning CSS transitions and animations can target them.

calc-size() for explicit calculations

calc-size(auto, size) lets you reference the auto size in a calculation. For example, calc-size(auto, size - 2rem) subtracts 2rem from whatever the natural height would be. In most cases you just need the opt-in property and a simple transition.

The pattern

Enable the opt-in globally, then transition height from 0 to auto with a standard transition property. The browser interpolates between the two values smoothly.

Fallback strategy

Wrap in @supports (interpolate-size: allow-keywords). Without support, the element snaps open/closed instantly — still functional, just not animated. This is textbook progressive enhancement.

Demo — animated accordion panel

What is interpolate-size?
A CSS property that enables smooth transitions to keyword sizes like auto, min-content, and max-content. It eliminates the need for JavaScript-based height measurement in accordions and collapsible panels.
Which browsers support it?
Chrome 129+ (shipped September 2024). Firefox and Safari are actively implementing it. Use @supports for progressive enhancement — the content remains accessible without the animation.
Do I need JavaScript?
No. That is the entire point. Previously, animating to an unknown height required measuring the element with JavaScript and setting a pixel value. With interpolate-size: allow-keywords, the browser handles interpolation natively. Zero JavaScript, zero layout thrashing.

Try it yourself

Mini-exercise

Modify the transition timing from 0.3s ease-out to 0.5s cubic-bezier(0.4, 0, 0.2, 1) and observe how the easing curve affects the perceived speed. Then try adding transition: height 0.3s, opacity 0.3s 0.1s; with opacity going from 0 to 1 — a content fade-in that starts slightly after the height animation begins.
