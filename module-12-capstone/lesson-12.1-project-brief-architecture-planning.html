Lesson 12.1

Project Brief and Architecture Planning

Before writing a single line of CSS, the architecture is planned completely. A senior engineer plans in prose first — the code writes itself afterwards.

The brief

Your fictional product is Prism — a design-system hosting SaaS for engineering teams. The marketing page must have:

  • Sticky navigation with an anchor-positioned dropdown
  • Hero section with a gradient accent, headline, subheadline, and CTA pair
  • Features grid (3 columns on desktop, auto-reflowing via auto-fit)
  • Testimonial section with carousel
  • Pricing table (three tiers)
  • FAQ accordion using <details>
  • Cookie consent banner via the popover API
  • Footer with cluster layout

Mapping the brief to PE7 layers

Before code, answer these questions in writing:

  1. What token categories and names? Brand indigo + neutral scales, 9-stop spacing, 6-stop type, 5 motion durations, 4 easings, 3 radii.
  2. What layout primitives? Container, stack, cluster, grid, cover — all from Module 7.
  3. What components? nav, hero, feature-card, pricing-card, testimonial-slide, faq-item, cookie-banner, footer.
  4. What animations and which technique? Hero headline uses @starting-style, scroll reveals use animation-timeline: view(), sticky nav uses scroll-state(stuck: top), card stagger uses sibling-index().
  5. What modern features with fallbacks? Every scroll-driven / experimental feature wrapped in @supports.
  6. What requires JS? Zero JavaScript. The capstone is a no-JS deliverable (except for editor.js on the lesson pages themselves).
