Lesson 12.6

Motion System Build

Add the animation layer to Prism. Every motion the design requires has a dedicated CSS technique — and every scroll-driven / experimental feature is wrapped in @supports with an invisible graceful fallback.

What you are building

  • Hero entrance — headline + CTAs animate in via @starting-style (Module 9.2).
  • Section reveals — feature and testimonial sections fade-up using animation-timeline: view() with animation-range: entry 0% entry 40%.
  • Card stagger — feature cards delay via sibling-index().
  • Sticky nav shadow — @container scroll-state(stuck: top) adds a shadow when the nav is stuck.
  • FAQ open — details[open] animates its content via @starting-style.
  • Reduced motion override — global prefers-reduced-motion rule in the animations layer disables all of the above with the one legitimate !important.

The support wrapper

Every modern motion feature in the capstone is wrapped:

@supports (animation-timeline: view()) {
  .feature-card { animation: fade-up var(--dur-moderate) var(--ease-out) both; animation-timeline: view(); animation-range: entry 0% entry 40%; }
}

In Firefox (which does not yet ship scroll timelines at the time of writing), the supports block is skipped. The cards still render — just without the reveal. That is the entire point of progressive enhancement.
