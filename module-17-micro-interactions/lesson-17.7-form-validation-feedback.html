Lesson 17.7 · Micro-Interactions

Real-Time Validation Feedback

Five input states (empty, focus, valid, invalid, disabled) with animated icons, a shake effect on invalid submission, and a password strength meter. All powered by native :valid, :invalid, and :placeholder-shown pseudo-classes.

The pseudo-class strategy

Native HTML validation pseudo-classes let us style inputs based on their validity without JavaScript. The trick is combining them: :not(:placeholder-shown):valid means "has content and is valid." :not(:placeholder-shown):invalid means "has content and is invalid." This prevents showing error states on empty fields the user hasn't touched yet.

State machine

Each input cycles through states: empty (neutral border), focus (primary ring), valid (green border + checkmark), invalid (red border + X icon + shake), disabled (muted, no interaction). The transitions between states use 200ms ease for border-color and box-shadow.

Icon feedback

The ::after pseudo-element on the input wrapper shows a checkmark (clip-path polygon) or error X depending on validity. This element transitions opacity and scale so the icon pops in smoothly when the state changes. We position it absolutely at the right edge of the input.

The shake animation

When an invalid field is focused (simulating a submission attempt), a subtle shake animation fires: translateX alternating between -4px and 4px over 300ms. We trigger this with @starting-style on the invalid state so it only plays once when entering the invalid state, not continuously.

Password strength meter

A gradient bar below the password field fills based on content length. Using :placeholder-shown to detect empty vs. non-empty, and pattern attributes for strength thresholds. The bar transitions width and background-color simultaneously, shifting from red through yellow to green.
