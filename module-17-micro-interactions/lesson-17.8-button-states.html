Lesson 17.8 · Micro-Interactions

Every Button State, Animated

The full button lifecycle: default, hover, active, focus-visible, loading, success, and disabled. A loading spinner replaces text, a green flash confirms success, and the whole system is token-driven across primary, secondary, ghost, danger, and icon-only variants.

Button as state machine

A button isn't one thing. It's a state machine with at least seven states, each requiring distinct visual treatment. The trick is making transitions between states feel intentional: hover should be instant (50ms), active should be snappy, but loading-to-success should feel deliberate (300ms).

The loading state

When loading, the button text fades to opacity: 0 and a CSS spinner appears in its place. The button width is fixed with min-width before the transition so it doesn't collapse when text disappears. The spinner is a ::after pseudo-element with a border-based animation.

The success state

After loading completes, the background flashes green and a checkmark appears. This uses a class toggle with animation: success-flash 600ms ease that scales the button slightly, changes background, and fades back. The checkmark is a clip-path polygon that scales in from 0.

Token-driven variants

Each variant sets three custom properties: --btn-bg, --btn-text, and --btn-border. All hover/active/focus states derive from these tokens using OKLCH lightness shifts. This means adding a new variant is just three lines of code.

Focus-visible vs focus

We use :focus-visible exclusively, not :focus. This shows the focus ring only on keyboard navigation, not on mouse clicks. The ring is outline: 2px solid with outline-offset: 2px, matching the brand color.
