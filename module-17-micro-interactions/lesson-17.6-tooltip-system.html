Lesson 17.6 · Micro-Interactions

A Complete Tooltip System

Four positions, animated entrance, arrow via clip-path, accessible markup with role="tooltip" and aria-describedby, plus anchor positioning with a graceful fallback. A production tooltip with zero JavaScript.

Tooltip architecture

The tooltip is a <span> with role="tooltip" nested inside the trigger element. The trigger gets aria-describedby pointing to the tooltip's ID. On hover or focus, the tooltip becomes visible. This structure ensures screen readers announce the tooltip content when the trigger is focused.

Position via data attribute

A data-tooltip-position attribute on the trigger determines placement: top, bottom, left, or right. Each position sets different inset values and transform-origin for the entrance animation. The arrow (via ::before) rotates accordingly.

The arrow

The arrow is a ::before pseudo-element with clip-path: polygon(0 100%, 50% 0, 100% 100%) creating a triangle. For bottom tooltips, the polygon flips. For left/right, it rotates 90 degrees. The arrow inherits the tooltip's background color for seamless connection.

Enter animation

On enter, the tooltip transitions from opacity: 0; scale: 0.9 to opacity: 1; scale: 1 over 150ms. A transition-delay of 150ms on the hover state prevents accidental triggers. On exit, the delay is removed so the tooltip disappears instantly, preventing the tooltip from "chasing" the cursor.

Anchor positioning

Where supported, CSS anchor positioning (anchor-name on the trigger, position-anchor on the tooltip) provides true dynamic positioning that avoids overflow. We wrap this in @supports (anchor-name: --tip) with a transform-based fallback for older browsers.

Mini-exercise

Add a "multi-line" tooltip variant that allows wrapping text (remove white-space: nowrap and set a max-width: 12rem). Then add a "danger" tooltip that uses a red background (oklch(45% 0.2 25)) when the trigger has a data-tooltip-variant="danger" attribute. Make sure the arrow color matches.
