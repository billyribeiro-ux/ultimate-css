Lesson 17.10 · Micro-Interactions

Smooth Page-Level Transitions

Four transition patterns — crossfade, slide left/right, scale zoom, and shared-element morph — using the View Transitions API. A mini 3-view "app" demonstrates each pattern with pure CSS animation control.

The View Transitions API

The View Transitions API captures a screenshot of the current state, updates the DOM, then animates between old and new states. In CSS, we define ::view-transition-old(root) and ::view-transition-new(root) animations. No JavaScript animation logic needed — just declare how old exits and new enters.

Pattern 1: Crossfade

The simplest transition. The old view fades out while the new view fades in. This is the browser's default view transition behavior. We can customize the duration and easing: ::view-transition-old(root) { animation: fade-out 250ms ease; }

Pattern 2: Slide

For forward navigation, the old view slides left while the new slides in from the right. For backward navigation, the reverse. We use view-transition-name and custom animations with translateX(-100%) and translateX(100%).

Pattern 3: Scale zoom

The old view scales down and fades while the new view scales up from a smaller size. This creates a "zoom into content" feel, common in master-detail patterns. The old gets scale(0.9); opacity: 0 and the new starts at scale(1.1); opacity: 0.

Pattern 4: Shared-element morph

Give matching elements the same view-transition-name value. The browser automatically morphs position, size, and appearance between them. A card thumbnail can morph into a full-width hero image. This is the most powerful pattern and requires the least CSS.

The @view-transition at-rule

For same-document transitions, we use @view-transition { navigation: auto; }. For cross-document (MPA), this enables transitions between page loads. We wrap in @supports for graceful degradation.
