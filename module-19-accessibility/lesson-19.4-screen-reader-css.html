Lesson 19.4 · Inclusive Design

CSS That Helps (and Hurts) Screen Readers

CSS can make content invisible to screen readers without you realizing it. display:none, visibility:hidden, and even certain transforms remove elements from the accessibility tree. Understanding which CSS properties affect assistive technology is essential for inclusive design.

What screen readers see

Screen readers consume the accessibility tree, which is built from the DOM, ARIA attributes, and — crucially — certain CSS properties. Not all CSS is visual-only. Some properties actively modify what assistive tech can access.

Properties that REMOVE from the a11y tree

  • display: none — completely removed. Not rendered, not accessible.
  • visibility: hidden — not visible, not accessible, but still occupies layout space.
  • content-visibility: hidden — same as display:none for a11y purposes.

Properties that DO NOT affect the a11y tree

  • opacity: 0 — invisible but still in the a11y tree and still focusable.
  • transform: scale(0) — visually gone but still accessible.
  • clip-path: inset(100%) — visually clipped but still accessible.
  • position: absolute with offscreen coordinates — still accessible.

The .sr-only pattern

This is the industry standard for visually hiding content while keeping it accessible to screen readers:

.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}

Why not just position: absolute; left: -9999px? That approach causes a scroll jump in RTL layouts and creates a very large scroll area in some browsers. The clip-based pattern avoids these issues.

::before/::after content

Content added via content: "..." on pseudo-elements IS read by most screen readers (VoiceOver, NVDA, JAWS). This means decorative text in pseudo-elements can confuse users. Use content: "" / "" (alt text syntax) or add aria-hidden="true" to the parent if the pseudo-element content is purely decorative.

aria-hidden vs CSS hiding

aria-hidden="true" removes from the a11y tree but keeps the element visually present. The opposite of .sr-only. Use case: decorative icons next to text labels — the icon is visible but the screen reader only reads the label.

Use your browser accessibility inspector (DevTools > Accessibility tab) to verify which elements appear in the accessibility tree. Elements marked "SR: Visible" will be announced; "SR: Hidden" will not.

Try it yourself

Mini-exercise

Open DevTools, go to the Accessibility tab, and inspect each element in the preview. The icon with aria-hidden="true" should not appear in the accessibility tree. The .sr-only text should appear. Add a third button that has only an icon (no visible text) and use .sr-only to give it an accessible name.
