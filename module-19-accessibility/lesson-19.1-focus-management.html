Lesson 19.1 · Inclusive Design

Focus Indicators That Actually Work

Every keyboard user needs to know where they are on the page. The default browser focus ring is functional but ugly — so designers remove it and break accessibility. The correct move: replace it with something better. Here is how.

:focus vs :focus-visible

:focus fires on every focus event — mouse click, keyboard tab, or programmatic focus. This is why designers hate it: clicking a button shows a ring the user does not need. :focus-visible fires only when the browser detects keyboard navigation. This is the selector you want for custom focus rings.

/* Remove the default, add a better one for keyboard */
:focus { outline: none; }
:focus-visible {
  outline: 3px solid oklch(65% 0.25 275);
  outline-offset: 3px;
  border-radius: 4px;
}

Custom focus rings

The ideal focus ring has three properties: high contrast against the background, enough thickness to be visible (at least 2px), and offset so it does not overlap the element content. The outline-offset property creates breathing room. Combined with border-radius, you get a ring that hugs the element shape.

Focus-within for parent highlighting

:focus-within fires on any ancestor of the focused element. This lets you highlight an entire form group when any input inside it has focus — a powerful visual cue that says "you are working in this section."

.form-group:focus-within {
  background: oklch(95% 0.02 275);
  border-inline-start: 3px solid oklch(65% 0.25 275);
}

Skip links

A skip link is the first focusable element on the page. It is visually hidden until focused, then appears to let keyboard users jump past the navigation. The pattern: position: absolute off-screen, then :focus brings it on-screen.

.skip-link {
  position: absolute;
  inset-block-start: -100%;
  inset-inline-start: 1rem;
  padding: 0.75rem 1.5rem;
  background: oklch(20% 0.02 275);
  color: oklch(95% 0 0);
  z-index: 1000;
}
.skip-link:focus {
  inset-block-start: 1rem;
}

Focus trapping: inert + popover

When a modal is open, keyboard focus must stay inside it. The HTML inert attribute disables interaction on everything outside the modal. Combined with the popover attribute, you get browser-native focus trapping without a line of JS. The CSS role: ensure the backdrop and the modal itself have correct stacking and visibility transitions.

WCAG 2.4.7 — Focus visible

The requirement: any keyboard-operable UI component must have a visible focus indicator. The focus indicator must have a contrast ratio of at least 3:1 against the unfocused state. A 3px solid outline in a contrasting color meets this effortlessly.
