Lesson 1.5

The !important Death Spiral

!important is the nuclear option. It feels like a solution. It is an escalation.

How !important inverts the cascade

An !important declaration beats all non-!important declarations regardless of specificity. An !important in a low-specificity rule beats a non-!important in a high-specificity rule. The hierarchy is flipped.

The trap

When !important is used to fix a specificity problem, the only way to override it is with another !important. Which requires a higher-specificity selector to break ties between the two !important declarations. Which creates an arms race with no winner.

Legitimate uses

  • Accessibility overrides. prefers-reduced-motion disabling all animations — Module 3, Lesson 3.8.
  • User stylesheets. End users overriding author styles for readability.
  • Utility-first systems that explicitly design for it.

The architectural fix

If you find yourself reaching for !important to make something work, you are not fixing the problem — you are adding debt. The problem is that the cascade has no way to understand your authoring intent. @layer is the fix.

Live demo — the arms race

ID + class (1,1,0) should win over .banner (0,1,0)… but !important on the class wins anyway.

Try it yourself

Mini-exercise

Count the !important declarations in a CSS file from a project you have worked on. For each one, write down what it was overriding. How many of them exist purely to fight another !important? That ratio is a proxy for how much the codebase would benefit from @layer.
