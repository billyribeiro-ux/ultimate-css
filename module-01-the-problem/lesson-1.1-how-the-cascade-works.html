Lesson 1.1

How the Cascade Actually Works

Most developers think CSS is simple until it isn't. The cascade is a priority resolution system with four independent layers, and most developers only know one of them.

The four layers of the cascade

When two CSS rules both match an element and set the same property, the browser resolves the conflict by asking four questions in order. The first question that produces a clear winner decides which rule wins. Only if all four are tied does a later rule get applied.

  1. Origin & importance. Is the rule in the user agent stylesheet, the author stylesheet, or a user override? Is it !important? The importance chain flips depending on origin.
  2. Layer priority. Is the rule in a @layer? Higher layers win over lower layers. Unlayered styles beat layered ones.
  3. Specificity. The A,B,C column score — discussed in detail in Lesson 1.2.
  4. Source order. The tiebreaker everyone thinks is the only rule.

The key insight

Source order is the last resort, not the main event. Most developers write CSS assuming source order decides everything. It does not. That assumption is why things break in ways that seem inexplicable.

UA styles are already running

Before you write a single line of CSS, your HTML page is already styled — by the browser's user-agent stylesheet. Headings have margins. Lists have bullets. Buttons have chrome. Your author styles need to cooperate with those defaults, not override them blindly.
