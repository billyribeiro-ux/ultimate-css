Module 1 · Project

Diagnose the Disaster

A 600-line broken stylesheet. Six visual outcomes that shouldn't happen. Your deliverable is a written audit — no code changes.

The brief

Below is a deliberately broken stylesheet applied to a page. Six things are visually wrong compared to what the author intended. For each broken outcome, you will identify:

  1. Which selector was supposed to win.
  2. Which selector actually won.
  3. Which cascade rule caused the conflict (origin, importance, specificity, or source order).
  4. Why the developer who wrote the losing rule probably thought it would work.

This is diagnosis only. The fix comes in Module 2, where you will refactor this exact stylesheet using @layer — without changing a single selector.

Your audit deliverable

For each of the six numbered outcomes below, write a diagnosis in the format described above. Then continue to Module 2 — your audit will drive the refactor.

  1. Primary button is amber, not indigo. Two rules with identical specificity; source order decided the winner.
  2. Card titles are red globally. A late-added !important flipped the cascade.
  3. Hero card title is still red, not green. A higher-specificity rule #hero .card-title exists but loses to a lower-specificity !important.
  4. Sidebar card background is the wrong shade. Two identical selectors, different values — source order decides.
  5. Doubled-class !important rule attempts to reclaim .card-title. Another arms race.
  6. Header UI button is green, not slate. Third-party library uses #site-header .ui-btn with !important.
