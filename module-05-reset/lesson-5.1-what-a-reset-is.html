Lesson 5.1

What a Reset Actually Is

Reset, normalize, and baseline are three different tools with three different jobs. Pick the wrong one and you will spend the rest of the project fighting your own foundation. In PE7 we want a reset — specifically, a subtractive reset with zero specificity.

Three strategies, one foundation

  • Reset — remove everything the browser gives you. Margins, padding, list styles, heading sizes: gone. You rebuild the world in the base layer. Eric Meyer's reset is the classic example.
  • Normalize — keep the browser's decisions but smooth out the differences between vendors. This is addition, not subtraction, and it bakes opinions into the foundation.
  • Baseline — a reset plus a few opinionated defaults (sensible typography, sensible form chrome). Halfway between the other two.

Why PE7 picks reset

Normalize hides the user agent stylesheet behind a layer of "sensible" author decisions. That is exactly the wrong thing for a layered architecture: every layer above reset now has to reason about both the UA styles and normalize's patches. A pure reset leaves only one question for the base layer to answer: "what should this element look like in this project?"

Reset is subtraction

If a rule in your reset adds a color, a shadow, a font family, or any visual opinion, it does not belong in reset. It belongs in base. The reset layer exists to remove, not to decorate. This is the rule that keeps the architecture honest.

:where() and zero specificity

Every rule in the PE7 reset wraps its selector list in :where(). The functional pseudo-class :where() evaluates to specificity 0,0,0 regardless of what it contains. That means a plain .card in your components layer — specificity 0,1,0 — always outranks the reset, even without @layer priority doing any work. :where() is a belt-and-suspenders guarantee.

A concrete contrast

/* Bad: reset that will fight you later */
* { margin: 0; padding: 0; }
ul { list-style: none; }

/* PE7 reset: zero specificity, layered, deliberate */
@layer reset {
  :where(*, *::before, *::after) { box-sizing: border-box; }
  :where(h1, h2, h3, p) { margin: 0; }
  :where(ul[role="list"]) { list-style: none; padding: 0; }
}

The first form forces unauthored <ul> elements in article content to lose their bullets — an accessibility regression. The PE7 form only strips lists that are semantically marked as non-list UI (the role="list" opt-in), and it costs zero specificity so overriding it is trivial.

Try it yourself

Mini-exercise

Take any reset you have used in a previous project. For every rule in it, decide: does this rule subtract a browser default, or does it add a visual opinion? Every rule that adds an opinion belongs in base, not reset. Count how many rules you need to move. That count is a measure of how much architectural debt your old foundation carries.
