Placing Items: Lines, Spans, and Named Lines

Grid lines are the invisible boundaries between tracks. You place items by referencing these lines — by number, by span count, or by name. Mastering placement is what separates basic grids from precise layouts.

Line numbers

A 3-column grid has 4 column lines (1, 2, 3, 4). Items are placed using start/end lines:

.item {
  grid-column: 1 / 3;   /* spans from line 1 to line 3 (2 columns) */
  grid-row: 1 / 2;      /* occupies first row */
}

The span keyword

Instead of specifying end lines, use span to say "take N tracks":

.item {
  grid-column: span 2;  /* span 2 columns from auto-placed position */
  grid-row: span 3;     /* span 3 rows */
}

The -1 trick

Negative line numbers count from the end of the explicit grid. -1 is always the last line:

.full-width {
  grid-column: 1 / -1;  /* spans entire grid width */
}

Named lines

You can name lines in your template definition using square brackets:

.grid {
  grid-template-columns:
    [sidebar-start] 20rem
    [sidebar-end content-start] 1fr
    [content-end];
}
.sidebar { grid-column: sidebar-start / sidebar-end; }
.main    { grid-column: content-start / content-end; }

Named lines make layouts self-documenting. When you read grid-column: content-start / content-end, the intent is obvious without counting line numbers.

Repeat with named lines

grid-template-columns: repeat(3, [col-start] 1fr [col-end]);
/* Creates: [col-start] 1fr [col-end col-start] 1fr [col-end col-start] 1fr [col-end] */
/* Reference: col-start 2 = second line named "col-start" */

grid-row + grid-column shorthands

grid-column: 1 / 3 is shorthand for grid-column-start: 1; grid-column-end: 3;. The grid-area shorthand packs all four: grid-area: row-start / col-start / row-end / col-end.

Placement strategies compared

Line numbers

grid-column: 2 / 4;   /* from line 2 to line 4 */
grid-column: 2 / -1;  /* from line 2 to the end */
grid-row: 1 / 3;      /* first two rows */

Best for: fixed layouts where you know the exact grid structure.

Span

grid-column: span 2;       /* take 2 columns from auto position */
grid-column: 2 / span 3;  /* start at line 2, take 3 columns */

Best for: items that need a specific width regardless of where they're placed.

Named lines

grid-column: content-start / content-end;

Best for: self-documenting layouts where intent matters more than position.

Overlapping items

Multiple items can occupy the same cells. Later items in source order stack on top (like z-index: auto). Use explicit z-index to control stacking:

.item-a { grid-area: 1 / 1 / 3 / 3; }
.item-b { grid-area: 2 / 2 / 4 / 4; z-index: 1; }
/* item-b overlaps item-a and sits on top */

Common mistakes

  • Forgetting that -1 only works with the explicit grid (not implicit tracks)
  • Using grid-column: 1 / 4 on a 3-column grid — that's line 4, which is valid (end of column 3)
  • Confusing track numbers with line numbers — track 1 is between lines 1 and 2

Mini-exercise

Make the sidebar span 2 rows using grid-row: 2 / span 2. Then try making the content area span from content-start all the way to aside-end (removing the aside). Experiment with grid-column: 2 / -1 as an alternative way to achieve full remaining width.

Next, add a banner element after the header that spans the full width using named lines: grid-column: sidebar-start / aside-end. Compare this with grid-column: 1 / -1 — both achieve the same result here, but named lines are more readable.

Finally, try placing an item at grid-column: 2 / span 2 — it starts at line 2 and spans 2 columns. Notice how span and line numbers can be combined for flexible placement.

Key takeaways

  • Grid lines are numbered starting at 1 (not 0)
  • -1 refers to the last line of the explicit grid
  • span N takes N tracks from the current position
  • Named lines make layouts self-documenting
  • Multiple items can occupy the same cell (they overlap)
  • grid-area is the shorthand for all four placement properties
