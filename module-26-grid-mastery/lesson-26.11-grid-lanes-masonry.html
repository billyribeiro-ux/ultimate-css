Lesson 26.11 · Layout

Grid Lanes (Masonry) Layout

The masonry layout — where items pack into the shortest column like Pinterest — is coming to CSS Grid natively. Items of varying heights fill vertical space without gaps, creating the dense, organic layout previously only possible with JavaScript.

The native syntax

.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(14rem, 1fr));
  grid-template-rows: masonry;
}

When grid-template-rows: masonry is set, items no longer align to row tracks. Instead, each item packs into the shortest column, creating a masonry effect.

Browser support

As of 2026, masonry is supported in Safari 26+ and behind flags in other browsers. The CSS Grid Level 3 specification defines this behavior. Always provide a fallback.

The @supports fallback strategy

/* Fallback: standard grid (items align to rows) */
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(14rem, 1fr));
  gap: 1rem;
}

/* Enhanced: masonry where supported */
@supports (grid-template-rows: masonry) {
  .gallery {
    grid-template-rows: masonry;
  }
}

CSS columns fallback

For browsers without grid masonry, CSS columns provide a similar visual result:

/* Fallback with columns */
.gallery {
  columns: 14rem;
  column-gap: 1rem;
}
.gallery > * {
  break-inside: avoid;
  margin-bottom: 1rem;
}

/* Upgrade to grid masonry */
@supports (grid-template-rows: masonry) {
  .gallery {
    columns: unset;
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(14rem, 1fr));
    grid-template-rows: masonry;
    gap: 1rem;
  }
  .gallery > * { margin-bottom: 0; }
}

Key differences from JS masonry

  • No layout shift — browser calculates positions before paint
  • Works with all grid features (spans, alignment, auto-fit)
  • Respects order property
  • No resize observers or mutation observers needed

Masonry axis options

grid-template-rows: masonry creates columns that fill top-to-bottom (most common, like Pinterest). grid-template-columns: masonry creates rows that fill left-to-right (items pack into the shortest row). The masonry axis is always the one set to masonry.

Spanning in masonry

.wide-item { grid-column: span 2; }
/* Works! Item spans 2 columns in the masonry grid */

Items can span multiple tracks on the non-masonry axis. The masonry algorithm places them in the shortest column group that has space.

The progressive enhancement strategy

Ship with CSS columns today, upgrade to grid masonry when supported. The visual result is nearly identical — columns gives you the packed layout, masonry adds proper grid features (spans, alignment, gap instead of margins).

/* Phase 1: works everywhere */
.gallery { columns: 15rem; column-gap: 1rem; }
.gallery > * { break-inside: avoid; margin-bottom: 1rem; }

/* Phase 2: better with grid */
@supports (grid-template-rows: masonry) {
  .gallery {
    columns: unset;
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(15rem, 1fr));
    grid-template-rows: masonry;
    gap: 1rem;
  }
  .gallery > * { margin-bottom: 0; }
}

Try it yourself

Mini-exercise

The demo uses CSS columns as a fallback. Open the browser DevTools and force the @supports block to apply (if your browser supports it). Notice the items may reorder differently between columns and masonry. Try adding more items with varying heights to see how both approaches handle them.

Change the column width in the fallback from 12rem to 8rem and observe more columns appear. Then try giving one item grid-column: span 2 inside the @supports block — it should span two columns in the masonry layout.

Key takeaways

  • grid-template-rows: masonry enables Pinterest-style packing
  • Items fill the shortest column automatically — no JS needed
  • Use @supports for progressive enhancement with CSS columns fallback
  • Masonry works with grid features: spans, gap, auto-fill/fit, alignment
  • Browser support is growing — ship with fallback, upgrade when available
  • Reading order follows source order (not visual column order)
