Grid vs Flexbox: When to Use Which

Grid is 2D (rows AND columns simultaneously). Flexbox is 1D (one axis at a time). They're complementary — not competing. The composition pattern: grid for the page layout, flexbox inside the cells.

The fundamental difference

  • Grid — you define the layout, then place items into it. The container controls structure.
  • Flexbox — items determine their own size, then the container distributes space. Content drives structure.

When to use Grid

  • Page-level layouts (header/sidebar/content/footer)
  • Card grids where equal heights matter
  • Any layout that needs alignment on BOTH axes
  • Complex overlapping layouts
  • When you know the structure ahead of time

When to use Flexbox

  • Navigation bars with dynamic items
  • Button groups
  • Centering a single item
  • Content where items should wrap naturally based on their intrinsic size
  • When the number of items is unknown and order doesn't need 2D control

The composition pattern

/* Grid for the section layout */
.dashboard {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(20rem, 1fr));
  gap: 1.5rem;
}

/* Flexbox inside each card */
.dashboard-card {
  display: flex;
  flex-direction: column;
  gap: 0.75rem;
}
.dashboard-card .actions {
  display: flex;
  gap: 0.5rem;
  margin-top: auto; /* push to bottom */
}

Cases where either works

A row of equal-width columns: grid: repeat(3, 1fr) or flex: flex: 1 1 0 on children. Grid is cleaner because you declare the layout on the parent. With flexbox, you must set properties on every child.

Try it yourself

Mini-exercise

In the editor above, the page uses grid for layout and flexbox for the nav. Try converting the nav to grid — you'll find it's more verbose and less flexible. Then try converting the page layout to flexbox only — you'll need nested flex containers and it won't align both axes cleanly. This demonstrates the complementary strengths.

Add a card section inside the main content area using display: grid; grid-template-columns: repeat(auto-fit, minmax(12rem, 1fr)). Inside each card, use display: flex; flex-direction: column with margin-top: auto on the button. This is the composition pattern in action.

Decision framework

  • Need rows AND columns aligned? Grid.
  • Need items to wrap based on their own size? Flexbox.
  • Fixed structure known ahead of time? Grid.
  • Dynamic number of items in a single row/column? Flexbox.
  • Need overlap without absolute positioning? Grid.
  • Need one item to push to the end (margin-auto)? Either works (both support it).

Key takeaways

  • Grid is 2D (controls both axes simultaneously); Flexbox is 1D
  • Grid is container-driven; Flexbox is content-driven
  • Compose them: grid for layout structure, flexbox for component internals
  • When either works, grid often results in less code (layout defined on parent only)
  • Both support gap, alignment, and order — they share the same alignment spec

The hybrid pattern in production

/* Page: grid for structure */
.app { display: grid; grid-template: "nav main" / 16rem 1fr; }

/* Section: grid for card layout */
.cards { display: grid; grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr)); }

/* Component: flex for internal layout */
.card { display: flex; flex-direction: column; }
.card .actions { margin-top: auto; display: flex; gap: 0.5rem; }

This three-level composition (grid > grid > flex) is the standard architecture for modern web applications.
