Lesson 26.3 · Layout

Named Grid Areas: Visual Layout in CSS

grid-template-areas lets you draw your layout as ASCII art directly in CSS. It is the most readable layout pattern ever created — you can see the page structure at a glance.

The syntax

.page {
  display: grid;
  grid-template-columns: 16rem 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header"
    "sidebar content"
    "footer  footer";
}
.page-header  { grid-area: header; }
.page-sidebar { grid-area: sidebar; }
.page-content { grid-area: content; }
.page-footer  { grid-area: footer; }

Each quoted string is a row. Area names must form rectangles. A . denotes an empty cell.

Empty cells

grid-template-areas:
  "header header header"
  "sidebar . content"
  "footer footer footer";

The . leaves the middle cell of row 2 empty. Multiple dots (...) work too for visual alignment.

Responsive restructuring

The magic: change grid-template-areas in a media query or container query to completely restructure your layout without touching HTML:

@container (max-width: 40rem) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "content"
      "sidebar"
      "footer";
  }
}

Implicit named lines

When you create an area named content, the browser automatically creates lines named content-start and content-end on both axes. You can reference these lines for placement too.

Rules for valid areas

  • Areas must be rectangular — no L-shapes or T-shapes
  • Each row string must have the same number of cells
  • Area names must be valid CSS identifiers (no spaces, no starting with numbers)
  • The same name in non-rectangular positions is invalid and the entire declaration is ignored

Invalid example

/* INVALID — "nav" forms an L-shape */
grid-template-areas:
  "nav  header header"
  "nav  content aside"
  "nav  content nav";   /* nav can't be here AND in column 1 */

Why named areas are the best approach

For page-level layouts, named areas win over line-based placement because:

  • The layout is visible in the CSS — you can read the structure like a wireframe
  • Responsive restructuring requires changing only grid-template-areas
  • Child elements use simple grid-area: name — no line math
  • Adding or removing columns doesn't break child placement

Combining areas with explicit sizing

.page {
  grid-template-columns: 16rem 1fr 12rem;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header  header"
    "sidebar content aside"
    "footer  footer  footer";
}

The column and row definitions control sizing; the areas map names to the resulting cells.

The grid shorthand

You can combine rows, columns, and areas into the grid shorthand, though it's rarely used due to complexity:

.page {
  grid:
    "header  header" auto
    "sidebar content" 1fr
    "footer  footer" auto
    / 16rem 1fr;
}

Each line defines a row's area names and height, and the / section defines columns. Most developers prefer the explicit properties for clarity.

Try it yourself

Mini-exercise

Add a container query at max-width: 35rem that stacks the layout into a single column in this order: header, nav, main, aside, footer. Then try using . to leave an empty cell — for instance "nav . side" creates a gap between nav and side.

Next, create a 4-column layout with areas: "logo nav nav nav" "side main main aside" "ftr ftr ftr ftr". Assign each area to an element and observe how the header splits into logo and nav sections. This shows how areas can represent unequal column spans without line math.

Key takeaways

  • grid-template-areas defines layout as ASCII art — most readable layout tool
  • Areas must form rectangles; . represents empty cells
  • Children use grid-area: name for simple placement
  • Change areas in media/container queries for responsive restructuring
  • Areas auto-create named lines: name-start and name-end
  • Combine with explicit column/row sizing for full control
