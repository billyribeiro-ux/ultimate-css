auto-fit vs auto-fill: The Responsive Grid Secret

One line of CSS creates a fully responsive grid with no media queries: repeat(auto-fit, minmax(18rem, 1fr)). Understanding the difference between auto-fit and auto-fill unlocks layouts that adapt to any container width.

The pattern

.grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(18rem, 1fr));
  gap: 1rem;
}

This creates as many columns as fit, each at least 18rem wide. When space permits more columns, they appear. When it doesn't, columns drop to the next row. No breakpoints needed.

auto-fit vs auto-fill

The difference only matters when there are fewer items than available columns:

  • auto-fit — collapses empty tracks to zero width. Items stretch to fill the container.
  • auto-fill — keeps empty tracks at their minmax size. Items stay at the minimum width, leaving visible empty space.

With 3 items in a container wide enough for 5: auto-fit gives you 3 stretched columns; auto-fill gives you 3 minimum-width columns with empty tracks on the right.

When to use each

  • auto-fit — card grids, image galleries, any layout where items should stretch to fill available space.
  • auto-fill — layouts where items must maintain a specific maximum width regardless of container size (e.g., a form with fixed-width input groups).

Combining with min()

grid-template-columns: repeat(auto-fit, minmax(min(18rem, 100%), 1fr));

The min(18rem, 100%) prevents overflow on containers narrower than 18rem — the minimum becomes 100% of the container instead.

Common patterns

Card grid (most common)

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(18rem, 100%), 1fr));
  gap: 1.5rem;
}

This single rule creates a fully responsive card grid. Cards are at least 18rem, stretch to fill, and wrap to new rows automatically.

Fixed minimum, capped maximum

grid-template-columns: repeat(auto-fill, minmax(15rem, 25rem));

Items stay between 15rem and 25rem. Extra space goes unused (items don't stretch to fill). Useful when you want a consistent card size.

Combining with explicit tracks

grid-template-columns: 16rem repeat(auto-fit, minmax(12rem, 1fr));

A fixed sidebar followed by auto-fitting content columns. The sidebar stays at 16rem; the content area adapts.

The "1 column on mobile" problem

Without min(), if the container is narrower than your minmax minimum, the grid overflows. Always use the min(value, 100%) pattern for production grids to prevent horizontal scroll on small screens.

Performance note

auto-fit and auto-fill are calculated once per layout pass. They don't cause layout thrashing — the browser determines the column count from the container width and minmax values in a single calculation.

Debugging auto-fit/auto-fill

When your grid doesn't behave as expected:

  • Open DevTools grid inspector — it shows empty tracks (visible with auto-fill, collapsed with auto-fit)
  • Check if your container has a constrained width — auto-fit/fill need a definite width to calculate column count
  • Ensure the minmax minimum isn't larger than the container — items will overflow
  • Remember: auto-fit and auto-fill cannot be combined with explicit track counts like repeat(3, ...) — use one or the other

Container queries + auto-fit

For fine-tuned control, combine auto-fit with container queries to adjust the minimum size at different container widths:

.cards {
  grid-template-columns: repeat(auto-fit, minmax(min(18rem, 100%), 1fr));
}
@container (max-width: 30rem) {
  .cards {
    grid-template-columns: 1fr; /* force single column */
  }
}

auto-fit/fill with named lines

You can name the lines inside repeat with auto-fit/fill:

grid-template-columns: repeat(auto-fit, [card-start] minmax(15rem, 1fr) [card-end]);

Each generated track has named start and end lines. Reference them with card-start 2 for the second instance.

Real-world sizing recommendations

  • Cards: minmax(min(18rem, 100%), 1fr) — readable width, responsive
  • Thumbnails: minmax(8rem, 1fr) — compact, many columns
  • Form fields: minmax(20rem, 30rem) — capped max for input readability
  • Dashboard widgets: minmax(15rem, 1fr) — flexible but usable

Key takeaways

  • auto-fit collapses empty tracks — items stretch to fill
  • auto-fill keeps empty tracks — items stay at minmax size
  • The difference only matters when items don't fill all available columns
  • Always wrap the min value with min(value, 100%) for narrow containers
  • This is the single most useful responsive grid pattern — memorize it
