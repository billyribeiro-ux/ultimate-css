Progressive enhancement

Navigation & Scroll Marker Carousels

Two of the most common UI patterns — a primary nav with dropdowns and a horizontal carousel with dots — are both now native CSS. The nav uses :has(). The carousel uses scroll-marker-group, ::scroll-button(), ::scroll-marker, and :target-current.

Nav dropdowns with :has()

A navigation bar with a <details>-powered dropdown:

nav:has(details[open]) { /* dim other items, raise z-index, etc. */ }
nav details[open] > summary { color: var(--color-primary); }

The entire nav responds to the open state of any descendant dropdown. No event listener, no "is-dropdown-open" class, no state machine.

Native carousels: the four new primitives

The 2025 CSS carousel feature set turns a plain scroll container into a dotted, buttoned carousel with zero JavaScript:

  1. scroll-marker-group: after on the scroller. The browser generates a marker group after the scroller.
  2. ::scroll-marker pseudo-elements on each snap child become the dots.
  3. ::scroll-button(left) and ::scroll-button(right) generate prev/next buttons.
  4. :target-current matches the marker for the currently-snapped item — style the active dot.

The full carousel

.carousel {
  scroll-snap-type: x mandatory;
  overflow-x: auto;
  scroll-marker-group: after;
  display: flex;
}
.carousel > * {
  scroll-snap-align: center;
  flex: 0 0 100%;
}
.carousel > *::scroll-marker {
  content: "";
  inline-size: .6rem; block-size: .6rem;
  border-radius: 50%;
  background: var(--color-border-strong);
}
.carousel > *::scroll-marker:target-current {
  background: var(--color-primary);
}
.carousel::scroll-button(left),
.carousel::scroll-button(right) {
  content: "";
  /* style the arrow buttons */
}

Browser support

Carousel primitives: Chrome 135+, Edge 135+. Safari and Firefox not yet. Always wrap in @supports (scroll-marker-group: after) — the fallback is a plain overflow-x: auto; scroll-snap-type: x mandatory carousel, which is still usable (just without dots or buttons).
