Lesson 8.3

:has() — The Parent Selector

For twenty years the answer to "can you style a parent based on its child?" was "no, use JavaScript". The answer is now yes. :has() is the single biggest reduction in JavaScript-for-styling this decade.

What :has() actually is

:has() is a functional pseudo-class that matches an element if its argument matches something inside it. It is a real selector, not a hint — the browser's style engine resolves it during normal matching.

.card:has(img)          { /* cards that contain an image */ }
.card:has(> img)        { /* cards whose direct child is an image */ }
.field:has(input:invalid) { /* fields containing an invalid input */ }
form:has(:focus)        { /* a form any of whose inputs is focused */ }

The pattern this kills

Before :has(), this was the canonical JavaScript pattern:

const field = document.querySelector('.field');
const input = field.querySelector('input');
input.addEventListener('input', () => {
  field.classList.toggle('is-invalid', !input.checkValidity());
});

That whole pattern — thousands of event handlers in every codebase — is now:

.field:has(input:invalid:not(:placeholder-shown)) {
  --field-border: var(--color-danger);
  --field-label:  var(--color-danger);
}

Zero listeners. Zero state. Zero stale DOM.

Real patterns

  • article:has(> figure:first-child) — articles that lead with an image get a different layout.
  • nav:has(.dropdown[open]) — dim the nav while a dropdown is open.
  • tr:has(input[type="checkbox"]:checked) — highlight selected rows.
  • body:has(dialog[open]) — prevent background scroll while any dialog is open.
  • .card:not(:has(img)) — text-only cards get extra padding.

Specificity

:has() takes on the highest specificity of its argument. div:has(.primary) scores 0,1,1. Wrap in :where() to neutralize: :where(:has(.primary)) scores 0,0,0.

Browser support

Chrome 105+, Safari 15.4+, Firefox 121+. Production-ready. No @supports wrap needed — this is baseline in 2026.
