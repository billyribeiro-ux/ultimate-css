Lesson 8.2

Progressive enhancement

@scope: Component Isolation

Descendant selectors are the original leaky abstraction. Every .card h3 you write is a promise to the rest of the codebase that no h3 will ever appear inside a card without your permission. @scope is how you stop making that promise.

The problem @scope solves

Write .card h3 { font-size: 1.25rem }. Six months later, a card contains a nested article that itself has an h3. Your rule now reaches into the nested article because descendant selectors descend forever. The fix has historically been BEM (.card__title), a discipline that works but bloats markup.

@scope: proximity-based selection

@scope (.card) {
  h3 { font-size: 1.25rem; color: var(--color-text-heading); }
  p  { color: var(--color-text-secondary); }
}

Inside a @scope, the browser selects the nearest .card ancestor for any matched descendant. Nested cards do not bleed; the rules apply to each card's own h3.

Donut scope: upper and lower bounds

The second argument is a scope end — a "hole" that cuts the scope short:

@scope (.post-list) to (.author-meta) {
  a { color: var(--color-link); text-decoration: underline; }
}

This rule styles anchors inside a .post-list, but stops descending the moment it hits .author-meta. Donut scope is how you say "style the article body, but not the avatar widget embedded in it" without inventing new classes.

Specificity: lower than you think

@scope does not add specificity. A selector written inside @scope (.card) has the same specificity as if you had written it outside the scope — the scope only affects matching, not weight. That means @scope (.card) { h3 { ... } } scores 0,0,1, not 0,1,1. Use this. It means consumers can still override your component's internals without a specificity war.

Browser support

Chrome 118+, Edge 118+, Safari 17.4+, Firefox 128+. Production-ready in 2026 but still worth an @supports wrap for older evergreen installs.
