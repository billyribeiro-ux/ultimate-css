Lesson 8.6

Progressive enhancement

Anchor Positioning & Tooltips

Popper.js exists because CSS used to be unable to position one element relative to another without a common parent. That is no longer true. CSS anchor positioning replaces an entire category of JavaScript libraries with five declarative lines.

The problem

A tooltip must: (1) appear next to its trigger, (2) escape its ancestor's overflow: hidden, (3) flip to the opposite side when it would clip the viewport, and (4) update on scroll and resize. The old answer was Popper.js plus a mutation observer. The new answer is anchor positioning plus popover.

The four primitives

  1. anchor-name: --trigger on the element to anchor to.
  2. position-anchor: --trigger on the element being positioned.
  3. position-area: top center to pick a side relative to the anchor.
  4. position-try-fallbacks: flip-block so the browser flips when the default side would clip.

Combined with popover

The popover attribute promotes an element to the top layer — it renders above every ancestor's stacking context, is dismissed by ESC and light-dismiss automatically, and is keyboard-accessible for free. Anchor positioning + popover is the complete replacement:

<button popovertarget="tip">Help</button>
<div id="tip" popover style="anchor-name: none; position-anchor: --btn">Tooltip text</div>

Browser support

Chrome 125+, Edge 125+. Safari and Firefox still catching up. Always wrap in @supports (anchor-name: --x) and provide a fixed-position fallback, or fall through to a plain title attribute for non-supporting browsers.

Mini-exercise

Change position-area to bottom end. Then add a second fallback: position-try-fallbacks: flip-block, flip-inline, flip-block flip-inline. Resize the preview until you see the tooltip flip to stay on-screen — all without a line of JavaScript.
