Lesson 8.5

Progressive enhancement

Card Component with @scope

A card is the archetype of a container component — it wraps arbitrary content and must not leak. We build it with @scope, a scoped token API, and a container query that adapts horizontally or vertically based on the card's own width, not the viewport.

The architecture

  1. .card declares a container with its scoped token API.
  2. @scope (.card) styles internal elements (img, h3, p, footer) using element selectors — no BEM.
  3. A @container query switches between stacked and horizontal layout based on the card's inline-size.
  4. Variants override only tokens: --card-bg, --card-border, --card-accent.

Why not descendant selectors?

If you wrote .card img { ... }, a nested card's image would inherit the outer card's image styles. @scope uses proximity matching — each image belongs to its nearest enclosing card, so nesting is safe.

Container query adaptation

The container query lets the card decide its own layout without knowing anything about the page:

@container (inline-size > 28rem) {
  .card-body { display: grid; grid-template-columns: 10rem 1fr; gap: 1rem; }
}

Drop the same card into a wide hero, a narrow sidebar, or a three-column grid — it adapts. There is no "card-horizontal" variant class.

Browser support

@scope: Chrome 118+, Safari 17.4+, Firefox 128+. Container queries: baseline in all modern browsers. Wrap the scope in @supports (selector(@scope)) and fall back to element selectors inside .card.
