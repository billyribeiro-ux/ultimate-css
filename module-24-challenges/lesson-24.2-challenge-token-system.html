Build a Token System from a Design Spec

A designer hands you a visual spec. Your job: translate it into a complete design token system with OKLCH primitives, semantic aliases, and automatic dark mode via light-dark().

The scenario

Below is a visual design spec showing color swatches, spacing values, and type sizes. You must build a tokens.css from scratch that defines all the primitives, maps them to semantic names, and supports both light and dark modes automatically.

Constraints

  • All colors must use OKLCH color space
  • You must define primitive tokens (raw values) AND semantic tokens (contextual aliases)
  • Dark mode must use light-dark() with color-scheme on :root
  • Spacing must use a consistent scale (e.g., powers of 2 or a ratio)
  • Type sizes must use clamp() for fluid scaling
  • Token names must follow a clear naming convention
  • The entire system should fit in one :root block plus one @media (prefers-color-scheme: dark) or use light-dark() exclusively

Your challenge — build tokens.css

Hint

Start with primitives: --color-primary-500: oklch(55% 0.2 260). Then create semantic tokens: --primary: light-dark(var(--color-primary-500), var(--color-primary-400)). For dark mode surfaces, invert the neutral scale — light mode uses neutral-50 for surfaces, dark mode uses neutral-900.
