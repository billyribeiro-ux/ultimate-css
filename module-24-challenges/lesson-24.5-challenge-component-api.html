Challenge 5 · Intermediate

Design a Button API

Build a button component with 5 variants and 3 sizes. The catch: variant classes can ONLY override custom properties — zero new property declarations allowed. The base .btn class does all the work.

The scenario

You're building a design system's button component. The architecture must be maintainable: the base class declares every visual property once, using custom properties. Variant classes only swap token values. Size classes only swap sizing tokens. This means adding a 6th variant requires exactly 3-4 lines of custom-property overrides, not duplicating the entire button.

Why this pattern matters

In traditional CSS, each button variant redeclares all its properties. A 5-variant button might have 50+ lines of repeated padding, border-radius, font-size, font-weight, cursor, and transition declarations. With the custom property API pattern, the base class declares these once — variants are 3-4 lines each. Adding a 6th variant? Three lines. Changing the border-radius of all buttons? One line.

The custom properties you'll need

  • --btn-bg — background color
  • --btn-text — text color
  • --btn-border-color — border color (transparent for filled variants)
  • --btn-border-w — border width
  • --btn-py — vertical padding
  • --btn-px — horizontal padding
  • --btn-font — font size
  • --btn-radius — border radius
  • --btn-hover-bg — background on hover (optional: can use opacity instead)

Constraints

  • 5 variants: primary, secondary, ghost, danger, success
  • 3 sizes: sm, md (default), lg
  • The .btn base class must declare ALL visual properties (background, color, border, padding, font-size, radius, etc.)
  • Variant classes (.btn-primary, etc.) can ONLY set custom property values — no background:, color:, or any other property declaration
  • Size classes (.btn-sm, etc.) can ONLY set sizing custom properties
  • All 15 combinations (5 variants x 3 sizes) must work correctly
  • Hover and focus states must also work through the custom property API
  • All colors must use OKLCH

Design spec

Here are the exact values for each variant:

  • Primary: bg oklch(50% 0.2 260), text white
  • Secondary: bg oklch(92% 0.04 260), text oklch(35% 0.12 260)
  • Ghost: bg transparent, text oklch(50% 0.2 260), border oklch(50% 0.2 260)
  • Danger: bg oklch(55% 0.2 25), text white
  • Success: bg oklch(55% 0.17 150), text white

Hint

The base .btn class should reference custom properties for everything: background: var(--btn-bg), color: var(--btn-text), padding: var(--btn-py) var(--btn-px), font-size: var(--btn-font), border: var(--btn-border-w) solid var(--btn-border-color). Set defaults for the "md" size and "primary" variant. Then each variant class just overrides --btn-bg, --btn-text, and --btn-border-color.
