Challenge Solutions & Scoring

Difficulty ratings, time estimates, key insights for each challenge, and the scoring rubric. Review only after you've attempted the challenge yourself.

Scoring rubric

Grade each challenge on 5 dimensions. Each is worth 1-5 points for a maximum of 25 per challenge.

Dimension 5 (Excellent) 3 (Adequate) 1 (Needs work)
Architecture Proper @layer order, tokens for all values, @scope where appropriate Some layering, some tokens, mostly organized No layers, hardcoded values, flat structure
Visual fidelity Matches target exactly, polished details Close to target, minor differences Significant visual differences from target
Accessibility Focus visible, reduced-motion, semantic HTML, proper contrast Some a11y considerations, basic semantics No accessibility considerations
Performance No layout thrashing, efficient selectors, minimal repaints Generally performant, minor issues Expensive animations, complex selectors, bloated CSS
Code economy Concise, no repetition, leverages cascade Some repetition, mostly efficient Verbose, lots of duplication, fighting the cascade

Challenge reference

Challenge 1: Fix the Specificity War

  • Difficulty: Beginner
  • Time estimate: 10-15 minutes
  • Key insight: The @layer order statement at the top (@layer base, utilities, components;) controls which layer wins regardless of selector specificity. Wrap each group in its named layer. The component layer is declared last, so it wins over the higher-specificity .page .card selector in the base layer.
  • Common mistake: Forgetting that unlayered CSS always beats layered CSS. All rules must be inside a layer for the order to work.

Challenge 2: Build a Token System

  • Difficulty: Intermediate
  • Time estimate: 25-35 minutes
  • Key insight: Separate primitive tokens (raw OKLCH values) from semantic tokens (contextual aliases). Semantic tokens use light-dark() to define both themes in one declaration. The naming convention (--color-primary-500 for primitives, --primary for semantic) creates a clear hierarchy.
  • Common mistake: Putting dark mode values in a media query instead of using light-dark(). Or defining semantic tokens that reference other semantic tokens (creates circular dependencies).

Challenge 3: Responsive Layout, Zero Media Queries

  • Difficulty: Intermediate
  • Time estimate: 20-30 minutes
  • Key insight: The min(100%, Xrem) pattern inside minmax() and flex-basis prevents overflow on narrow screens. repeat(auto-fit, minmax(min(100%, 18rem), 1fr)) creates columns that exist only when there's room. clamp() for all fluid values (padding, font-size, gaps).
  • Common mistake: Using fixed pixel values for min-width in minmax(), which causes overflow on mobile. Always use min(100%, ...) as the floor.

Challenge 4: Add Dark Mode in Under 20 Lines

  • Difficulty: Intermediate
  • Time estimate: 15-20 minutes
  • Key insight: light-dark() is the game-changer — it eliminates the need for a separate media query block. Add color-scheme: light dark to :root, then replace each hardcoded color with light-dark(lightValue, darkValue). You're modifying existing lines, not adding many new ones. Identify the 8-10 properties that actually need to change.
  • Common mistake: Trying to add a full @media (prefers-color-scheme: dark) block that duplicates selectors. The constraint says no media queries — use light-dark() inline.

Challenge 5: Design a Button API

  • Difficulty: Intermediate
  • Time estimate: 25-35 minutes
  • Key insight: The base .btn class references custom properties for EVERY visual value: background: var(--btn-bg); color: var(--btn-text); padding: var(--btn-py) var(--btn-px); etc. Variants only override those properties: .btn-danger { --btn-bg: oklch(55% 0.2 25); --btn-text: white; }. This is the Open/Closed principle applied to CSS.
  • Common mistake: Declaring background: or color: directly in variant classes instead of only setting custom property values. The constraint is strict: variants set properties, not declarations.

Challenge 6: Orchestrate a 5-Step Animation

  • Difficulty: Advanced
  • Time estimate: 30-40 minutes
  • Key insight: @starting-style defines where elements come FROM (the invisible state). The normal CSS defines where they end up. transition-delay creates the stagger. Each element gets: opacity: 1; transform: none; transition: opacity 500ms ease, transform 500ms ease; transition-delay: Xms; and in @starting-style { opacity: 0; transform: translateY(1.5rem); }.
  • Common mistake: Putting @starting-style on the wrong element, or forgetting that it must be a nested rule inside the element's selector (or a standalone block that targets it).

Challenge 7: Build a Scroll-Driven Story

  • Difficulty: Advanced
  • Time estimate: 35-45 minutes
  • Key insight: Two timeline types: animation-timeline: scroll() for the progress bar (tracks overall page scroll), and animation-timeline: view() for section reveals (tracks each element's visibility). animation-range: entry 0% cover 40% controls when in the scroll the animation plays. The @supports fallback ensures content is visible in unsupported browsers.
  • Common mistake: Forgetting that without @supports, the keyframes set opacity: 0 as initial state, making content invisible in browsers that don't support scroll-driven animations.

Challenge 8: Complete Form Validation

  • Difficulty: Advanced
  • Time estimate: 30-40 minutes
  • Key insight: The :not(:placeholder-shown) trick — fields show validation styling only after the user has typed (the placeholder disappears). Combined with :valid/:invalid, you get: input:not(:placeholder-shown):invalid. The submit button uses .form:has(input:invalid) .submit { pointer-events: none; opacity: 0.5; }.
  • Common mistake: Showing error states on page load (before the user has interacted). The :not(:placeholder-shown) guard is essential for good UX.

Challenge 9: Draw a Scene with One Element

  • Difficulty: Expert
  • Time estimate: 45-60 minutes
  • Key insight: The main div's background property accepts multiple gradient layers — stack 3-4 gradients for sky sections. ::before becomes the sun (small circle) with box-shadow creating its glow and cloud shapes. ::after uses clip-path: polygon() for mountain silhouettes. The trick is treating box-shadow as a shape duplicator — each shadow is a copy of the element at an offset.
  • Common mistake: Trying to create too much detail. Focus on recognizable shapes: clear sky gradient, a round sun with glow, jagged mountain silhouette, and a distinct water section at the bottom.

Challenge 10: Clone a Real UI

  • Difficulty: Expert
  • Time estimate: 50-70 minutes
  • Key insight: The layout is a CSS Grid with two columns and two rows: grid-template-columns: 14rem 1fr; grid-template-rows: 1fr auto;. The sidebar spans both rows (grid-row: 1 / -1). The player bar spans both columns (grid-column: 1 / -1). The album grid inside uses auto-fit. Using @scope(.player-bar) keeps player styles encapsulated.
  • Common mistake: Not using PE7 architecture as required — this isn't just about matching the visual, it's about the code structure. Tokens, layers, and scope must all be present.

Challenge 11: Build an Accessible Modal

  • Difficulty: Expert
  • Time estimate: 40-55 minutes
  • Key insight: Exit animation is the hard part. You need: transition: opacity 200ms, transform 200ms, display 200ms, overlay 200ms; transition-behavior: allow-discrete;. The overlay property keeps the element in the top layer during exit. @starting-style inside :popover-open defines the entry state. The popover API gives you Escape-to-close and backdrop-click-to-close for free.
  • Common mistake: Forgetting transition-behavior: allow-discrete — without it, display and overlay can't transition, and the exit is instant (no animation). Also forgetting to transition the ::backdrop separately.

Challenge 12: The Final Boss

  • Difficulty: Boss
  • Time estimate: 90-120 minutes
  • Key insight: Work in layers, literally. Start with your @layer order and tokens. Then reset+base. Then layout (the portfolio is a simple vertical stack). Then components one section at a time. Animations come last — they're enhancements, not structure. The 500-line constraint forces you to be economical: reuse tokens, leverage inheritance, avoid redundancy.
  • Common mistake: Starting with animations or visual polish before the structure is solid. Also: writing verbose CSS that exceeds 500 lines. The constraint forces architectural thinking — every property must earn its place.

Score interpretation

  • 275-300 (all challenges): You've mastered modern CSS. Ship production code with confidence.
  • 220-274: Strong skills with some gaps. Review the challenges where you scored lowest.
  • 150-219: Good foundation. Revisit the module that corresponds to your weakest challenges.
  • Below 150: More practice needed. Work through the earlier modules again, then retry.

What to do next

If you completed all 12 challenges, you've demonstrated mastery of the techniques in this course. The next step is to apply these patterns in real projects. Every production stylesheet you write should use PE7 architecture, OKLCH colors, intrinsic sizing, and accessibility-first thinking.
