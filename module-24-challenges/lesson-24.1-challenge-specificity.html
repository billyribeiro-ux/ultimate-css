Challenge 1 · Beginner

Fix the Specificity War

You've inherited a stylesheet where 6 rules conflict with each other. Colors are wrong, spacing is off, fonts are overridden. Your mission: fix all 6 conflicts using ONLY @layer — no selector changes, no !important.

The scenario

A previous developer wrote CSS in no particular order. A card component has rules scattered across a utility file, a component file, and inline overrides. The result: the card looks nothing like the design. Your job is to wrap the existing rules in @layer declarations to establish the correct cascade order — without touching any selectors or adding !important.

Why this matters

Specificity wars are the number-one source of CSS frustration in large codebases. Before @layer, the only solutions were: increase specificity (leading to escalation), use !important (leading to !important wars), or restructure selectors (breaking other things). Cascade layers solve this architecturally — they let you control which origin wins regardless of specificity.

The 6 conflicts

In the starter code below, here's what's going wrong:

  1. Background: .page .card (specificity 0,2,0) beats .notification (0,1,0) — the card shows grey instead of teal
  2. Text color: .page .card sets dark text, overriding .notification's white
  3. Padding: .card (utility) sets small padding; .notification (component) wants larger padding, but source order gives .card precedence if specificity is tied
  4. Border-radius: Same issue — .card utility sets 0.25rem, component wants 1rem
  5. Font-size: The base layer's .page .card sets the correct font-size, but only if it isn't overridden by something else in a higher layer
  6. Box-shadow: The utility .card defines the shadow — it should survive the layering

Constraints

  • You may ONLY add @layer declarations and the layer order statement
  • You may NOT change any selector
  • You may NOT add !important
  • You may NOT delete any existing rule
  • You may NOT add new property declarations
  • All 6 conflicts must resolve to match the target

Key concept: layer order vs. specificity

When two declarations are in different layers, the layer order always wins — specificity is irrelevant. A selector with specificity 0,1,0 in a later layer beats 0,10,0 in an earlier layer. This is the fundamental insight: @layer adds a new dimension to the cascade that sits above specificity.

Target result

When correctly layered, the card should show:

  • Background: the teal color (oklch(55% 0.15 180)) from the component layer
  • Text color: white from the component layer
  • Padding: the larger padding (2rem 2.5rem) from the component layer
  • Border-radius: the rounded corners (1rem) from the component layer
  • Font-size: the 1rem size from the base layer (not overridden by components since components don't declare it)
  • Box-shadow: the shadow from the utility layer (not overridden by components since components don't declare it)

How to approach this

Look at the starter CSS below. There are three groups of rules, each labeled with a comment showing which "file" they originated from. Your task:

  1. First, add a layer order statement at the very top declaring the priority
  2. Then wrap each group in its corresponding named layer
  3. The page layout styles can go in any layer (base is logical)

Remember: in the layer order, later layers have higher priority. So if you want components to win over utilities and base, declare: @layer base, utilities, components;. Properties that a higher layer doesn't declare simply fall through — lower layers still provide them.

Testing your solution

After layering correctly:

  • The card should have a teal background (from components, which wins)
  • Text should be white (from components)
  • Padding should be generous — 2rem 2.5rem (from components)
  • Corners should be rounded — 1rem (from components)
  • Font size stays at 1rem (from base — components doesn't override it)
  • Shadow appears (from utilities — components doesn't override it)

If any of these are wrong, check which layer each rule is in and whether the layer order gives priority to the right one.

Your challenge

Hint

The layer order statement goes at the very top: @layer base, utilities, components; — this establishes priority regardless of source order. Then wrap each group in its corresponding @layer name { ... } block. The component layer wins because it's declared last in the order.

Step-by-step approach

  1. Add the layer order statement at the top of the CSS: @layer base, utilities, components;
  2. Wrap the "utilities.css" rules in @layer utilities { ... }
  3. Wrap the "base.css" rules in @layer base { ... }
  4. Wrap the "components.css" rules in @layer components { ... }
  5. Decide where page layout styles go (they could be in base or layout)
  6. Verify: components layer is last in the order, so .notification beats .page .card despite lower specificity
  7. Verify: properties not declared in components (font-size, box-shadow) fall through to the layer that declares them

What to check

After layering: the card background should be teal, text white, padding generous, corners rounded. The font-size comes from base (because components doesn't override it). The box-shadow comes from utilities (same reason). If you see grey background or dark text, your layer order is wrong or rules are in the wrong layer.
