@scope and :scope

@scope is CSS's native solution for component-scoped styling. It limits where selectors match — both from a root (scope start) and optionally to a boundary (scope end, the "donut scope"). Combined with :scope, it enables truly isolated component styles.

Basic @scope syntax

@scope (.card) {
  /* These rules only match inside .card elements */
  h2 { font-size: 1.25rem; }
  p  { color: oklch(40% 0 0); }
  a  { color: oklch(50% 0.2 275); }
}

Rules inside @scope (.card) only apply to elements that are descendants of .card. Unlike .card h2, the scope doesn't increase specificity of the inner selectors the same way.

Donut scope with to()

The "donut hole" — styles apply between the scope root and the boundary, but NOT inside the boundary:

@scope (.card) to (.card-footer) {
  /* Matches inside .card but NOT inside .card-footer */
  color: oklch(30% 0 0);
  a { color: oklch(50% 0.2 275); }
}

@scope (.layout) to (.sidebar, .modal) {
  /* Styles the layout area but stops at sidebar and modal */
  font-size: 1rem;
}

This is invaluable for design systems. You can style a card's body area without accidentally styling nested components like footers, modals, or embedded cards.

The :scope pseudo-class

Inside @scope, :scope refers to the scope root element itself:

@scope (.card) {
  :scope {
    /* Styles the .card element itself */
    border: 1px solid oklch(88% 0.04 275);
    border-radius: 0.75rem;
    padding: 1.5rem;
  }
  :scope > h2 {
    /* Direct child h2 of the card */
    margin-top: 0;
  }
}

Specificity inside @scope

The scope root (.card in the @scope declaration) does NOT add to the specificity of rules inside. A bare h2 inside @scope (.card) has specificity (0,0,1), not (0,1,1). However, :scope adds its own specificity when used in a selector.

@scope (.card) {
  h2 { }           /* specificity: (0,0,1) */
  :scope h2 { }    /* specificity: (0,1,1) — :scope = (0,1,0) */
  .title { }       /* specificity: (0,1,0) */
}

Nesting @scope blocks

@scope (.page) {
  @scope (.sidebar) {
    /* Only matches .sidebar inside .page */
    nav { padding: 1rem; }
  }
  @scope (.main-content) to (.widget) {
    /* Main content area, stopping at widgets */
    p { line-height: 1.7; }
  }
}

@scope vs other approaches

  • vs BEM: @scope provides native scoping without naming conventions. No need for .card__title — just use h2 inside the scope.
  • vs Shadow DOM: @scope is lighter weight, doesn't break inheritance, and works with existing selectors.
  • vs CSS Modules: @scope works in plain CSS without a build step.
  • vs nesting: Nesting creates descendant selectors (increases specificity). @scope limits matching without adding specificity from the root.

Inline @scope (in style elements)

<div class="widget">
  <style>
    @scope {
      /* Implicitly scoped to the parent of this style element */
      p { color: oklch(45% 0.1 275); }
    }
  </style>
  <p>This paragraph is styled.</p>
</div>
