@scope, :scope, and CSS Nesting

@scope creates a scoping boundary for your selectors — styles only apply within that subtree. Combined with CSS nesting and the & operator, it provides true component-level isolation without Shadow DOM or naming conventions.

@scope basics

The @scope rule defines a scoping root. Selectors inside only match descendants of that root.

@scope (.card) {
  /* These rules ONLY apply inside .card elements */
  h2 { font-size: 1.25rem; margin: 0; }
  p  { color: oklch(45% 0.05 275); font-size: 0.9rem; }
  a  { color: oklch(50% 0.2 275); }
}

Without @scope, those bare h2, p, a selectors would target every matching element on the page. With it, they're safely confined.

The :scope pseudo-class

Inside @scope, the :scope pseudo-class refers to the scoping root element itself.

@scope (.card) {
  :scope {
    border: 1px solid oklch(85% 0.05 275);
    border-radius: 0.75rem;
    padding: 1.5rem;
  }
  :scope:hover {
    box-shadow: 0 4px 12px oklch(0% 0 0 / 0.08);
  }
}

Donut scope: @scope to

The to keyword creates a "donut scope" — styles apply from the root down to but not including a boundary element. This prevents styles from leaking into nested sub-components.

@scope (.card) to (.card-footer) {
  /* Styles apply inside .card but NOT inside .card-footer */
  color: oklch(30% 0.05 275);
  font-size: 0.9rem;
}

@scope (.page) to (.sidebar, .modal) {
  /* Main content styles that don't bleed into sidebar/modal */
  h2 { color: oklch(35% 0.1 275); }
  p  { max-width: 65ch; }
}

Specificity inside @scope

Selectors inside @scope have proximity advantage: when two scoped rules match the same element, the one from the closer (more nested) scope wins — regardless of specificity. The scoping root selector itself does not contribute to specificity of contained rules.

@scope (.card) {
  p { color: oklch(45% 0.05 275); }    /* specificity: (0,0,1) */
}

@scope (.card .body) {
  p { color: oklch(35% 0.1 275); }     /* specificity: (0,0,1) — same! */
  /* But this wins by PROXIMITY — .card .body is closer to the p */
}

CSS Nesting with &

Native CSS nesting lets you write nested rules using & to reference the parent selector. It integrates naturally with @scope.

.card {
  border: 1px solid oklch(85% 0.05 275);
  border-radius: 0.75rem;

  & h2 { font-size: 1.25rem; margin: 0; }
  & p  { color: oklch(45% 0.05 275); }

  &:hover {
    box-shadow: 0 4px 12px oklch(0% 0 0 / 0.08);
  }

  & .badge {
    background: oklch(55% 0.2 275);
    color: white;
    font-size: 0.7rem;
    padding: 0.2rem 0.5rem;
    border-radius: 999px;
  }
}

Nesting inside @scope

@scope (.card) {
  :scope {
    padding: 1.5rem;

    & h2 {
      font-size: 1.25rem;
      & span { color: oklch(55% 0.2 275); }
    }

    &:hover { box-shadow: 0 4px 12px oklch(0% 0 0 / 0.08); }
  }
}

Nested @scope blocks

You can nest @scope inside another @scope for fine-grained control:

@scope (.page) {
  h1 { font-size: 2rem; }

  @scope (.sidebar) {
    h1 { font-size: 1.25rem; }  /* sidebar h1 is smaller */
    a  { color: oklch(50% 0.15 200); }
  }

  @scope (.main-content) to (.widget) {
    p { line-height: 1.7; max-width: 65ch; }
  }
}

PE7 integration

In the PE7 architecture, @scope sits inside the components layer. Each component can be its own scope, preventing styles from leaking between siblings:

@layer components {
  @scope (.card) to (.card-footer) {
    :scope { padding: 1.5rem; border-radius: 0.75rem; }
    h2 { margin: 0; }
    p  { color: oklch(45% 0.05 275); }
  }

  @scope (.card-footer) {
    :scope { padding: 1rem; background: oklch(96% 0.02 275); }
    a  { font-weight: 600; }
  }
}
