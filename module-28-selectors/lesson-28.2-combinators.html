Combinator Selectors: descendant, child, sibling

Combinators express relationships between elements — parent-child, ancestor-descendant, and sibling adjacency. The four combinators (space, >, +, ~) let you target elements based on their position in the DOM tree without adding extra classes.

Descendant combinator (space)

Matches any element that is a descendant (at any depth) of another:

/* Any <a> inside .nav, at any nesting level */
.nav a { color: oklch(55% 0.2 275); }

/* Any <p> inside article, however deep */
article p { line-height: 1.7; }

Performance note: The browser matches selectors right-to-left. .nav a first finds ALL <a> elements, then walks up the tree to check if any ancestor is .nav. Deep descendant selectors in large DOMs can be slower than direct child selectors.

Child combinator (>)

Matches only direct children — one level deep:

/* Only direct <li> children of .menu, not nested lists */
.menu > li { padding: 0.5rem 1rem; }

/* Only direct children, not deeper elements */
.card > .title { font-size: 1.25rem; }

Use > when you need to avoid styling nested elements. A .menu > li won't accidentally style list items inside a dropdown submenu.

Adjacent sibling combinator (+)

Matches the element immediately following another (same parent):

/* The paragraph right after an h2 */
h2 + p { font-size: 1.1rem; color: oklch(45% 0.05 275); }

/* Input immediately after a label */
label + input { margin-block-start: 0.25rem; }

Only the first matching sibling after the target is selected. If there are two paragraphs after an h2, only the first gets styled.

General sibling combinator (~)

Matches ALL siblings following an element (same parent):

/* All paragraphs after an h2 (same parent level) */
h2 ~ p { margin-inline-start: 1rem; }

/* All siblings after .active */
.active ~ .item { opacity: 0.5; }

Unlike +, the ~ combinator matches multiple elements and they don't need to be immediately adjacent.

Combining combinators

/* Direct child ul's li that follows another li */
.nav > ul > li + li { border-inline-start: 1px solid oklch(80% 0 0); }

/* First paragraph directly inside a section */
section > p:first-child { font-weight: 600; }

Performance implications

  • Worst: div a span — deep descendant with generic elements. The browser must check many ancestors.
  • Better: .card > .title — direct child with classes. Only one level to check.
  • Best: .card-title — flat class selector. No relationship checks needed.

In practice, selector performance rarely matters unless you have thousands of elements. But keeping selectors flat is still good practice for maintainability.

Try it yourself

Mini-exercise

Build a FAQ accordion where each question (h3) is followed by an answer (p). Use h3 + p to style the first answer paragraph differently (larger text, different color). Then use h3 ~ p to add a left border to ALL answer paragraphs. Notice how + targets just the first while ~ targets all.
