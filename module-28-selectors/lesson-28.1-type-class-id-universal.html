Type, Class, ID, Universal Selectors

These are the four fundamental selectors — the atoms from which all CSS targeting is built. Each has a different specificity weight, a different appropriate use case, and a clear place in the PE7 architecture.

Type selectors

Target elements by their HTML tag name. Specificity: (0, 0, 1).

h1 { font-size: 2rem; }
p  { line-height: 1.6; }
a  { color: oklch(50% 0.2 275); }

PE7 placement: The base layer. Type selectors set foundational element styles — typography, spacing, link colors. They should never appear in component layers where classes dominate.

Class selectors

Target elements by their class attribute. Specificity: (0, 1, 0).

.card    { border-radius: 0.75rem; }
.btn     { padding: 0.5rem 1rem; }
.active  { background: oklch(55% 0.2 275); }

PE7 placement: The workhorse of components and utilities layers. Classes are the primary targeting mechanism in modern CSS. They're reusable, composable, and have predictable specificity.

Multi-class patterns

/* Compound: element must have BOTH classes */
.btn.primary { background: oklch(55% 0.2 275); }

/* Two separate classes for composition */
.btn { padding: 0.5rem 1rem; }
.primary { background: oklch(55% 0.2 275); }

ID selectors

Target a single element by its id attribute. Specificity: (1, 0, 0).

#hero    { min-height: 100vh; }
#sidebar { grid-area: sidebar; }

PE7 placement: Avoid in stylesheets. IDs have extremely high specificity (1,0,0 = 256 classes in the old model), making them nearly impossible to override without !important. Use IDs for JavaScript hooks and fragment links only. In PE7, cascade layers eliminate any need for ID specificity.

Universal selector

Matches any element. Specificity: (0, 0, 0) — adds zero specificity.

/* The classic box-sizing reset */
*, *::before, *::after {
  box-sizing: border-box;
}

/* Lobotomized owl — spacing between adjacent siblings */
* + * {
  margin-block-start: 1rem;
}

PE7 placement: The reset layer. The universal selector is perfect for global resets because it adds no specificity weight.

Specificity comparison

SelectorSpecificityExample
Universal *(0, 0, 0)* { margin: 0; }
Type(0, 0, 1)p { color: black; }
Class(0, 1, 0).card { padding: 1rem; }
ID(1, 0, 0)#nav { display: flex; }

Compound selectors

You can combine any of the four basic selectors without a combinator to create compound selectors that must all match the same element:

/* Type + class: an anchor with class .btn */
a.btn { text-decoration: none; }

/* Type + ID (valid but discouraged) */
section#hero { min-height: 100vh; }

/* Multiple classes: must have both */
.btn.primary.large { font-size: 1.2rem; }

/* Universal + class: same as just .card */
*.card { padding: 1rem; }

Specificity is additive. a.btn is (0,1,1) — the type's (0,0,1) plus the class's (0,1,0).

When type selectors cause problems

Type selectors in component layers create fragile styles that break when HTML changes:

/* Fragile: breaks if heading level changes */
.card h2 { font-size: 1.25rem; }

/* Robust: works regardless of element */
.card-title { font-size: 1.25rem; }

This is why PE7 reserves type selectors for the base layer. Components should target classes, making them element-agnostic.

The case against ID selectors

Consider this real scenario: you style #nav in your stylesheet. Later, you need to override it for a specific page. You try .special-page .nav — it loses. You try .special-page #nav — it wins, but now you've used two IDs-worth of specificity. The specificity arms race has begun.

With @layer, this entire problem vanishes:

@layer base, components, overrides;

@layer components {
  .nav { display: flex; gap: 1rem; }
}
@layer overrides {
  .nav { gap: 0.5rem; }  /* always wins — layer order, not specificity */
}

Best practices

  • Use type selectors only in base/reset layers.
  • Use classes for all component and utility styling.
  • Avoid IDs in CSS — use cascade layers for specificity control instead.
  • Use the universal selector sparingly and only in resets.
  • Prefer flat selectors — a single class is almost always enough.
  • When specificity conflicts arise, reach for @layer before reaching for more specific selectors.
