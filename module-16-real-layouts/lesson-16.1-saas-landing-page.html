The SaaS Landing Page (Stripe/Vercel Style)

The modern SaaS landing page is the most common layout on the web today. A gradient hero, feature grid, social proof, pricing table with monthly/yearly toggle, FAQ accordion, and a final CTA. This lesson rebuilds the entire page in pure CSS, including a pricing toggle powered by :has() that swaps prices with zero JavaScript.

Anatomy of the layout

Every Stripe-style landing page follows the same rhythm: a hero that sells the vision, features that sell the product, social proof that sells trust, pricing that sells the plan, and a final CTA that closes the deal. The CSS primitives involved are container queries for the feature grid, :has() for the pricing toggle, scroll-driven animations for reveal effects, and OKLCH gradients for the hero backdrop.

The pricing toggle trick

The monthly/yearly toggle is a pair of radio inputs. When the "yearly" radio is checked, :has(input[value="yearly"]:checked) on the pricing wrapper hides the monthly prices and shows the yearly ones. No JavaScript, no class toggling. The :has() selector reaches upward from the toggle to the pricing cards, swapping display: none and display: inline on the price spans.

Scroll-driven fade-up reveals

Each section uses animation-timeline: view() to fade and translate upward as it enters the viewport. The animation range is entry 0% entry 30% for a quick, subtle reveal that does not block reading.

The hero gradient

The hero uses a multi-stop radial gradient with OKLCH colors that shifts hue via @property animation. Two overlapping radial gradients create the Stripe-style mesh effect. A floating UI mockup (built from CSS shapes) sits on top.

Key takeaway

The :has() selector turns a humble radio button into a full page state manager. The pricing section wrapper uses :has(input[value="yearly"]:checked) to swap every price on the page simultaneously. No JavaScript, no class toggles, no state management library. The radio buttons are the state. CSS reads it.
