Lesson 16.7 · Real-World Layout

The Music Player (Spotify/Apple Music Style)

A full music player interface with a playlists sidebar, album grid, a bottom "now playing" bar with progress gradient, playback controls, a spinning vinyl animation, and color-adaptive backgrounds using data-hue attributes with OKLCH. The entire layout responds to theme and viewport changes.

Anatomy of the layout

The music player uses a three-row grid: sidebar + main content on top, and a full-width player bar pinned to the bottom. The sidebar lists playlists, the main area shows album artwork in a responsive grid, and the bottom bar holds the now-playing track info, controls, and volume.

Color-adaptive backgrounds

Each album card carries a data-hue attribute. Using OKLCH and the style attribute with --hue, we create per-card gradient backgrounds that reflect the "album color." The now-playing bar picks up the active track's hue through a shared custom property. In browsers supporting relative color syntax, we derive lighter/darker variants automatically.

The vinyl spin

The album art thumbnail in the now-playing bar gets a border-radius: 50% and a continuous rotate animation when the "playing" state is active. A :has() selector on a hidden checkbox toggles the play/pause state, controlling both the spin animation and the play button icon swap.

Progress bar gradient

The track progress uses an input[type="range"] styled with a gradient track. The filled portion uses the accent hue while the unfilled portion remains neutral, creating the signature streaming-app progress look.

Key takeaway

A single --hue custom property, threaded through OKLCH color functions, can theme an entire music player. The vinyl spin, progress gradient, active sidebar highlight, and play button all derive their color from one variable. Change the hue, and the whole interface adapts. This is design-token-driven theming with zero JavaScript.
