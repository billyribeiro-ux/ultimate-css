Lesson 4.5

Typography Tokens

Font families, a modular type scale, a narrow set of weights, sensible line-heights, and — new in modern CSS — first-class control over how lines wrap. Typography is the densest visual decision in any product; tokens make it legible.

Font families

Three named families are enough for almost every product: body, display, and monospace. Everything else is a specialty case.

:root {
  --font-body:    ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  --font-display: var(--font-body);
  --font-mono:    ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
}

Default --font-display to the body family. If the design later introduces a separate display face, the switch happens in one token without a single component edit.

The type scale — ratio 1.25

A modular scale multiplies each step by a fixed ratio. PE7's default is 1.25 (the "major third"), which produces a progression that feels calm without getting repetitive:

:root {
  --text-xs:   0.75rem;   /* 12 */
  --text-sm:   0.875rem;  /* 14 */
  --text-md:   1rem;      /* 16 — body baseline */
  --text-lg:   1.125rem;  /* 18 */
  --text-xl:   1.25rem;   /* 20 */
  --text-2xl:  1.5rem;    /* 24 */
  --text-3xl:  1.875rem;  /* 30 */
  --text-4xl:  2.25rem;   /* 36 */
  --text-5xl:  3rem;      /* 48 */
}

You rarely need more than nine steps. If a design has eleven heading sizes, the design has two systems and one of them needs consolidating.

Weights, narrow

:root {
  --weight-regular: 400;
  --weight-medium:  500;
  --weight-bold:    700;
}

Three weights cover body, emphasis, and heading. Any more and the product loses its voice.

Line-heights by use

Line-height is not a single number; it depends on what is being set. Headlines want tight leading, body copy wants loose. Name them:

:root {
  --leading-tight:   1.15;  /* for display/headlines */
  --leading-snug:    1.3;   /* for subheads */
  --leading-normal:  1.55;  /* for body */
  --leading-loose:   1.75;  /* for reading-focused content */
}

text-wrap: balance and pretty

Two recent CSS features end the era of ragged headlines and orphan last words. They belong in base rules that reference these tokens, but the decision lives here:

  • text-wrap: balance — browser balances line lengths across the whole element. Use on headings, card titles, hero copy. Budget-limited, so not for long paragraphs.
  • text-wrap: pretty — browser avoids orphans on the last line. Use on body copy and anywhere long prose lives.
h1, h2, h3 { text-wrap: balance; line-height: var(--leading-tight); }
p          { text-wrap: pretty;  line-height: var(--leading-normal); }

Semantic aliases

:root {
  --text-body-sm:   var(--text-sm);
  --text-body:      var(--text-md);
  --text-heading:   var(--text-2xl);
  --text-display:   var(--text-4xl);
}

Base rules reference the semantics: h1 { font-size: var(--text-display); }. Repointing the scale ratio later is a single edit.

Mini-exercise

Remove text-wrap: balance from the h1 and narrow the container to 30ch. You will see the headline wrap with an uneven second line. Put balance back. Then remove text-wrap: pretty from the paragraph. On most viewports you will see a single word on the final line. Why do these two values earn their place in every PE7 base layer?
