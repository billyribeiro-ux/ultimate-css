Lesson 4.4

Spacing Tokens

A fixed T-shirt scale, always in rem, with semantic aliases for common uses. Spacing is where the discipline of tokens is most visible — and where raw numbers in a component hurt most.

Why a scale, not free numbers

The moment any component sets padding: 0.625rem, the design system has a hole in it. That value is not in the scale, which means no other component can match it, which means visual rhythm breaks in ways that are hard to see but impossible to unsee once you look. A scale prevents the hole by making only a small set of values legitimate.

The scale also makes design reviews fast. "Use --space-4 here" is a conversation. "Use 0.9375rem" is not.

The primitive scale

PE7 uses a roughly 4px-grid scale. Every value is a rem, so the user's font-size preference scales the entire layout:

:root {
  --space-0:  0;
  --space-1:  0.25rem;  /* 4px  */
  --space-2:  0.5rem;   /* 8px  */
  --space-3:  0.75rem;  /* 12px */
  --space-4:  1rem;     /* 16px */
  --space-5:  1.25rem;  /* 20px */
  --space-6:  1.5rem;   /* 24px */
  --space-8:  2rem;     /* 32px */
  --space-10: 2.5rem;   /* 40px */
  --space-12: 3rem;     /* 48px */
  --space-16: 4rem;     /* 64px */
  --space-20: 5rem;     /* 80px */
  --space-24: 6rem;     /* 96px */
}

The numeric suffixes correspond to the value in 0.25rem units, so --space-6 is 6 × 0.25rem = 1.5rem. That naming lets you do mental math without a lookup table.

Why rem, not px

Users who bump their browser font size up to 200% for readability should see your entire layout scale with them. rem units make this automatic; px units freeze the layout at the designer's font size. A single padding: 20px in a component is an accessibility bug waiting for a bad review.

Semantic aliases

Just like colour, spacing gets semantic aliases for common uses:

:root {
  --space-gutter:        var(--space-4);
  --space-section:       var(--space-16);
  --space-inline-inset:  var(--space-4);
  --space-card-pad:      var(--space-4);
  --space-field-gap:     var(--space-2);
}

Rebranding spacing is now a search-and-replace on a handful of semantic tokens. Reshaping the entire visual density of the product happens in one file.

What never lives in the spacing scale

  • Arbitrary values. If a component needs a one-off, it needs a new scale stop first.
  • Pixel values. The scale is rem-only.
  • Negative values. Negative margins are a code smell; express the same idea with grid gaps or flex orderings.

Mini-exercise

Change --space-card-pad from var(--space-6) to var(--space-8). The card loosens. Now change --space-4 itself — a primitive. What shifts? What does not? Articulate the division of labour between primitives and semantic aliases in one sentence.
