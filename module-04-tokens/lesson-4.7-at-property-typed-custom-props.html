Lesson 4.7

@property & Typed Custom Properties

Plain custom properties are strings. Browsers cannot animate them because they do not know what a string "halfway between A and B" is. @property lets you give a custom property a type — and the moment you do, it becomes animatable like any built-in.

The limitation of plain custom properties

Write --angle: 0deg, transition it to 360deg, and nothing happens. The browser sees the custom property as an opaque string; it cannot interpolate from "0deg" to "360deg". The transition goes from one string to the other instantly at the end.

This is the single biggest gap in plain custom properties. It blocks animated gradients, animated colour hues, animated rotation angles driven by variables — anything where the variable is the thing you want to tween.

The @property at-rule

@property registers a custom property with the CSS engine and declares its type. Once typed, the browser can interpolate it during transitions and animations just like it would opacity or translate.

@property --hue {
  syntax: "<number>";
  inherits: false;
  initial-value: 290;
}

Three required descriptors:

  • syntax — a string describing the value type. Common values: "<number>", "<length>", "<percentage>", "<color>", "<angle>", "<url>", or the universal "*".
  • inherits — whether the property inherits down the DOM. false is almost always the right default for animation-driving variables.
  • initial-value — a fallback the browser uses when the property is unset. Required unless syntax is "*".

The canonical example — animate an OKLCH hue

With plain variables you cannot animate the H channel of an OKLCH colour. With @property you can:

@property --hue {
  syntax: "<number>";
  inherits: false;
  initial-value: 290;
}

.hue-shift {
  background: oklch(60% 0.18 var(--hue));
  transition: --hue 2s ease-in-out;
}

.hue-shift:hover {
  --hue: 150;
}

Hover the element and the background smoothly sweeps from purple (H = 290) to green (H = 150), passing through blue on the way — because the browser now interpolates the hue number as a number.

Where @property lives in the architecture

@property declarations sit inside the tokens layer. They are data definitions, not selectors — they match the layer's single responsibility exactly. A typical PE7 tokens file registers every animation-driving variable at the top, then uses them throughout the rest of the codebase.

Other uses that matter

  • Animated conic gradients. Animate a --angle in a conic-gradient for spinner or progress visuals.
  • Scroll-driven positioning. Scroll-linked animations can drive a typed length token that other rules reference.
  • Typed guard against bad values. If a consumer passes --space-4: red, a typed property rejects the invalid value and falls back to the initial, preventing cascade-time disasters.
