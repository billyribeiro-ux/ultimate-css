Lesson 4.3

Building a Color System in OKLCH

A palette is not a list of colours — it is a structure. A 9-stop scale per hue, semantic aliases pointing into those stops, and a dark mode that flips the scale, not the names.

The 9-stop scale, per hue

For each brand hue, PE7 defines a 9-stop scale from -50 (lightest) to -900 (darkest). The lightness values are fixed across all hues so that a step across scales feels consistent. A typical scale:

:root {
  --purple-50:  oklch(97% 0.02 290);
  --purple-100: oklch(93% 0.04 290);
  --purple-200: oklch(86% 0.08 290);
  --purple-300: oklch(78% 0.13 290);
  --purple-400: oklch(68% 0.18 290);
  --purple-500: oklch(55% 0.22 290);  /* base */
  --purple-600: oklch(47% 0.22 290);
  --purple-700: oklch(38% 0.19 290);
  --purple-800: oklch(28% 0.14 290);
  --purple-900: oklch(18% 0.08 290);
}

-500 is the "base" stop of the hue. Chroma usually peaks in the middle of the scale and tapers toward white and black, because near-white and near-black can only hold so much saturation before clipping.

Repeat per hue

You do the same thing for gray (chroma near 0, a cool or warm hue like 264), plus at least one accent per semantic status: success (green, H ≈ 150), warning (amber, H ≈ 85), danger (red, H ≈ 25).

:root {
  --gray-50:  oklch(98% 0.003 264);
  /* ...through... */
  --gray-900: oklch(14% 0.015 264);

  --green-500: oklch(60% 0.17 150);
  --amber-500: oklch(75% 0.15  85);
  --red-500:   oklch(60% 0.22  25);
}

Semantic aliases

Primitives are never used directly by components. Semantic aliases name intentions and point into the scale:

:root {
  --color-brand:         var(--purple-500);
  --color-brand-hover:   var(--purple-600);
  --color-brand-muted:   var(--purple-100);

  --color-surface:       var(--gray-50);
  --color-surface-alt:   var(--gray-100);
  --color-border:        var(--gray-200);
  --color-text:          var(--gray-900);
  --color-text-muted:    var(--gray-600);

  --color-success:       var(--green-500);
  --color-warning:       var(--amber-500);
  --color-danger:        var(--red-500);

  --color-focus:         var(--purple-400);
}

Dark mode with light-dark()

Modern CSS has a first-class dark mode switch: the light-dark() function. It takes two values — one for light, one for dark — and resolves based on the color-scheme property. Combine it with semantic aliases and dark mode becomes a single pass through your semantic tokens, not a duplicate palette:

:root {
  color-scheme: light dark;

  --color-surface: light-dark(var(--gray-50),  var(--gray-900));
  --color-text:    light-dark(var(--gray-900), var(--gray-50));
  --color-border:  light-dark(var(--gray-200), var(--gray-700));
  --color-brand:   light-dark(var(--purple-500), var(--purple-400));
}

Notice that the primitives are unchanged. Only the semantic aliases switch. The brand token resolves to purple-500 in light mode and purple-400 in dark because a slightly lighter brand reads better against a dark surface. That tuning is the whole point of having semantic aliases.

Mini-exercise

Replace --purple-500 with oklch(60% 0.17 150). The brand rebrands to green in one edit, and the card, button, and focus ring all follow. Now try to do the same rebrand by pointing --color-brand directly at a primitive from a new scale — --teal-500. Which approach is more honest about what "rebranding" means?
