Lesson 4.6

Motion Tokens

A scale of durations, a small vocabulary of easing curves, and a rule for which combination to use when. Motion is a language; tokens make it speakable.

Why tokenise motion

Left untouched, every component picks its own duration and easing. One button transitions in 150ms, another in 300ms, another uses ease-in-out for what should be an entrance. The product feels inconsistent in a way users perceive but cannot articulate. A motion scale forces the decisions to be made once, in one place, and then reused.

The duration scale

:root {
  --motion-instant: 80ms;
  --motion-fast:    150ms;
  --motion-md:      250ms;
  --motion-slow:    400ms;
  --motion-slower:  600ms;
}

Five stops is enough. Most products use two or three of them. --motion-fast for micro-interactions (button hover, focus ring). --motion-md for most UI state changes. --motion-slow for page or panel movements. The instant and slower values are reserved for edge cases.

The easing vocabulary

Easing is not a numeric scale — it is a short vocabulary with rules about when to use each:

:root {
  --ease-out:     cubic-bezier(0.2, 0.7, 0.3, 1);   /* decelerate */
  --ease-in:      cubic-bezier(0.7, 0, 0.8, 0.3);   /* accelerate */
  --ease-in-out:  cubic-bezier(0.65, 0, 0.35, 1);   /* symmetric  */
  --ease-spring:  cubic-bezier(0.3, 1.4, 0.5, 1);   /* overshoot  */
}

The use rules

  • Enter: --ease-out. Things coming into view should decelerate. Dialogs opening, tooltips appearing, menus expanding.
  • Exit: --ease-in. Things leaving should accelerate out. Dismissed toasts, closing overlays.
  • State changes (reversible): --ease-in-out. Something toggling between two equal states — checked/unchecked, expanded/collapsed.
  • Playful/delight moments: --ease-spring. Use sparingly; over-use feels cartoonish.

Semantic aliases

:root {
  --transition-button: background var(--motion-fast) var(--ease-out),
                       transform  var(--motion-fast) var(--ease-out);

  --transition-dialog: opacity    var(--motion-md)   var(--ease-out),
                       transform  var(--motion-md)   var(--ease-out);
}

A component then writes transition: var(--transition-button); and cannot accidentally diverge from the product's motion language.

Reduced motion — the hard rule

As covered in Lesson 3.8, @media (prefers-reduced-motion: reduce) inside the animations layer neutralises every transition and animation via the one legitimate !important in PE7. Motion tokens make that override a one-liner — all of them collapse to an effective zero duration, because the media query targets transition-duration and animation-duration directly.

Mini-exercise

Change the button's transition to use --ease-spring. Hover it. The overshoot feels playful. Now change it to --ease-in — the wrong easing for an entering state. Describe, in one sentence, why the motion feels "off" even though nothing else changed. That feeling is why easing deserves tokens.
