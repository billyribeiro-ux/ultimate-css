Lesson 4.1

What Design Tokens Are

A design token is a named design decision. That is the whole definition. Understanding the consequences of that single sentence separates teams that scale from teams that rebrand by rewriting every component.

The definition

A design token is a name bound to a value, stored in one place, referenced from everywhere. --color-brand is a token. #7c3aed is not. The first is a decision your product has made and given a name to; the second is just data.

If you see a raw hex value anywhere in a component stylesheet, there is a missing token. The hex is a decision that never got named, so every consumer had to rediscover it, and tomorrow when the decision changes, every consumer has to be found and updated.

Why naming is the whole point

A name has three superpowers that a value does not:

  1. Substitutability. Change the value behind the name once; every consumer updates for free.
  2. Intention. --color-danger tells you why the colour is used. #ef4444 tells you nothing.
  3. Contracts across tools. Designers, developers, and documentation can all refer to the same name, and the meaning is stable even as the value drifts.

These properties compound. A codebase with 200 tokens and no raw values is indefinitely renamable, rethemable, and refactorable. A codebase with 50 tokens and 5,000 scattered raw values is locked in place.

The two-tier model: primitive and semantic

PE7 tokens live in two tiers.

Primitive tokens are the raw palette. They describe what things are:

--purple-500: oklch(55% 0.22 290);
--gray-900:   oklch(14% 0.015 264);
--space-4:    1rem;
--text-xl:    1.25rem;

Primitives are stable. They rarely change. You add to them; you seldom rewrite them.

Semantic tokens are named intentions that reference primitives. They describe what things are for:

--color-brand:   var(--purple-500);
--color-text:    var(--gray-900);
--space-gutter:  var(--space-4);
--text-heading:  var(--text-xl);

Semantics are where rebranding happens. Point --color-brand at --teal-500 and the entire product rebrands without touching a component. Point --space-gutter at --space-6 and every gutter loosens without touching a layout rule.

The rule consumers follow

Components always reference semantic tokens, never primitives. If a component has background: var(--purple-500), the rebranding contract is broken — the button will stay purple even when the brand moves to green. The right form is background: var(--color-brand), and the semantic token is what gets repointed during a rebrand.

The only place primitives appear in consuming code is the tokens layer itself, aliasing them into semantic tokens. Nowhere else.

A token is not just for colour

Everything a designer makes a decision about is a candidate for a token. Spacing, typography, motion, radius, shadow, z-index, focus-ring width. If two places in your codebase need the same value and you would want them to change together during a redesign, that value deserves a name.
