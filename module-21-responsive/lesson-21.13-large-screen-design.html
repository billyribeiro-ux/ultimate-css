Lesson 21.13 · Responsive

Designing for Large Screens: 1440p, 4K & Ultrawide

Most responsive design tutorials stop at "desktop." This lesson covers what happens above 1440px: content capping, multi-column strategies, scaling limits, high-resolution images, and ultrawide considerations.

Max content width

Content wider than approximately 80 characters per line becomes difficult to read. On a 2560px monitor, unrestricted text spans 200+ characters per line. The solution: cap content width.

/* The standard content cap */
.page {
  max-inline-size: 90rem; /* 1440px */
  margin-inline: auto;
  padding-inline: clamp(1rem, 0.5rem + 2vw, 3rem);
}

/* For reading-focused layouts, go narrower */
.article {
  max-inline-size: 65ch; /* ~65 characters */
  margin-inline: auto;
}

/* Why 90rem and not 100%?
   - 90rem = 1440px, comfortable for most content
   - Content is centered with auto margins
   - Padding adds breathing room on smaller viewports
   - On a 2560px screen, content stays centered with
     generous whitespace on both sides */

Multi-column layouts at ultrawide

When the viewport is 2560px or wider, you have space for 2-3 content columns or a generous sidebar. Use grid with a max column width to prevent overstretching:

/* Content grid that fills ultrawide gracefully */
.wide-layout {
  display: grid;
  grid-template-columns: minmax(0, 65ch) minmax(0, 65ch);
  gap: clamp(2rem, 1rem + 3vw, 6rem);
  justify-content: center;
  max-inline-size: 140rem;
  margin-inline: auto;
  padding-inline: clamp(1rem, 0.5rem + 2vw, 3rem);
}

/* At narrow viewports, collapse to single column */
/* Using auto-fit so no media query needed */
.adaptive-wide {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(min(65ch, 100%), 1fr));
  gap: clamp(2rem, 1rem + 3vw, 6rem);
  max-inline-size: 140rem;
  margin-inline: auto;
}

Scaling strategy: when to stop scaling

Should fluid tokens keep scaling beyond 1440px? Usually no. Text at 2rem is perfectly readable on a 27-inch monitor -- it does not need to be 3rem. The clamp() max parameter is your scaling cap:

/* Token scaling stops at comfortable maximums */
:root {
  /* Body: 1rem to 1.125rem -- caps early */
  --text-base: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);

  /* Heading: 1.5rem to 2.5rem -- caps at 2.5rem */
  --text-xl: clamp(1.5rem, 1.2rem + 1.5vw, 2.5rem);

  /* Hero display: 2rem to 4rem -- caps at 4rem */
  --text-3xl: clamp(2rem, 1rem + 3.5vw, 4rem);

  /* Spacing caps similarly */
  --space-xl: clamp(1.5rem, 1.2rem + 1.5vw, 3rem);
}

/* On a 5120px ultrawide, these tokens are capped:
   --text-base = 1.125rem (not 5rem!)
   --text-3xl = 4rem (dramatic but not absurd)
   --space-xl = 3rem (generous but controlled) */

Image resolution

Large screens often have high DPR (device pixel ratio). A 2x display needs 2x resolution images to appear crisp. CSS provides tools for resolution-aware image delivery:

/* image-set() for resolution switching */
.hero {
  background-image: image-set(
    url("hero-1x.webp") 1x,
    url("hero-2x.webp") 2x,
    url("hero-3x.webp") 3x
  );
}

/* Resolution media query for conditional loading */
@media (min-resolution: 2dppx) {
  .logo {
    background-image: url("logo-2x.svg");
  }
}

/* Modern approach: use SVG where possible.
   SVGs are resolution-independent -- they look crisp
   on any DPR without any special handling.
   Reserve raster for photos only. */

Ultrawide hero constraints

A hero section that fills 100% width on a 3440px ultrawide can be absurdly tall if given a fixed min-height. Use aspect-ratio constraints and capped heights:

/* Hero that doesn't become absurdly tall on ultrawide */
.hero {
  min-block-size: min(60svh, 600px);
  max-block-size: 800px;
  aspect-ratio: auto; /* don't force aspect ratio */
  display: grid;
  place-items: center;
  padding: clamp(2rem, 1rem + 4vw, 6rem);
}

/* For full-bleed hero images, cap the aspect ratio */
.hero-image {
  inline-size: 100%;
  aspect-ratio: 21 / 9; /* ultrawide-friendly */
  max-block-size: 600px;
  object-fit: cover;
}

The scrollbar problem

100vw includes the scrollbar width on most platforms, causing horizontal overflow. On ultrawide monitors, this is especially jarring because the scrollbar is a tiny fraction of the viewport:

/* Problem: 100vw includes scrollbar */
.full-width {
  width: 100vw; /* overflows by scrollbar width! */
}

/* Solution 1: use 100% instead */
.full-width {
  width: 100%; /* content area only, no scrollbar */
}

/* Solution 2: prevent layout shift with scrollbar-gutter */
html {
  scrollbar-gutter: stable;
  /* Reserves space for scrollbar even when content
     doesn't overflow. Prevents layout shift when
     navigating between short and long pages. */
}

/* Solution 3: overlay scrollbar (no space reserved) */
html {
  overflow-y: overlay; /* scrollbar floats over content */
  /* Note: limited browser support */
}

Key Principles

  • Cap content at 90rem
  • Cap line length at 65ch
  • Cap hero height
  • Use SVG for resolution independence
  • Use scrollbar-gutter: stable

About
