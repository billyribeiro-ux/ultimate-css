Foldable & Adaptive Layouts

CSS for foldable devices, dual-screen layouts, iPad multitasking, and the progressive enhancement approach that makes fold-aware CSS always additive -- never required.

Fold detection

The horizontal-viewport-segments and vertical-viewport-segments media features detect whether the device viewport is split by a physical fold or hinge:

/* Detect a device unfolded with two side-by-side screens */
@media (horizontal-viewport-segments: 2) {
  /* The viewport has a fold/hinge creating two horizontal segments */
  .layout {
    display: grid;
    grid-template-columns:
      env(viewport-segment-width 0 0)  /* left panel */
      env(viewport-segment-width 1 0); /* right panel */
  }
}

/* Detect a device with top/bottom fold (laptop/tent mode) */
@media (vertical-viewport-segments: 2) {
  .layout {
    display: grid;
    grid-template-rows:
      env(viewport-segment-height 0 0)  /* top panel */
      env(viewport-segment-height 0 1); /* bottom panel */
  }
}

The Samsung Fold pattern

The Galaxy Z Fold 6 has two distinct modes: 373px CSS width when folded (a normal phone) and 884px when unfolded (a small tablet). If you designed with container queries, this transition is handled automatically:

/* Container queries handle fold/unfold automatically */
.card-container {
  container-type: inline-size;
}

/* Small: single column, stacked */
.card {
  display: grid;
  gap: 0.75rem;
}

/* When container has space: side-by-side layout */
@container (min-width: 30rem) {
  .card {
    grid-template-columns: auto 1fr;
    gap: 1rem;
  }
}

/* This works for:
   - Z Fold folded (373px) -> stacked
   - Z Fold unfolded (884px) -> side-by-side
   - iPad split view (320px-1024px)
   - Any container at any width
   No fold-specific CSS needed! */

The iPad multitasking pattern

iPad apps in Stage Manager or Split View can be 1/3, 1/2, 2/3, or full width. Your app might be 320px wide on a device with a 1024px screen. Container queries handle this without knowing the device:

/* iPad multitasking widths (iPad Pro 13") */
/* 1/3 split: ~341px (phone-sized) */
/* 1/2 split: ~512px */
/* 2/3 split: ~683px */
/* Full:      1024px */

/* Container queries adapt to whatever width the app gets */
.widget-wrapper {
  container-type: inline-size;
}

.widget {
  /* Default: compact layout */
  padding: 0.75rem;
}

@container (min-width: 25rem) {
  .widget {
    /* More space: expand */
    padding: 1.25rem;
    display: grid;
    grid-template-columns: 1fr 1fr;
  }
}

@container (min-width: 45rem) {
  .widget {
    /* Lots of space: full layout */
    padding: 2rem;
    grid-template-columns: 1fr 1fr 1fr;
  }
}

Progressive enhancement for fold-aware CSS

Fold detection features have limited browser support. The golden rule: fold-specific CSS is always additive. The base layout must work without any fold awareness. Then add fold-specific enhancements inside @media and @supports:

/* Base layout: works everywhere */
.email-app {
  display: grid;
  grid-template-columns: 1fr;
}

.email-list { /* full width by default */ }
.email-detail { /* full width by default, or hidden */ }

/* Enhancement: fold-aware split on dual-screen devices */
@supports (env(viewport-segment-width 0 0)) {
  @media (horizontal-viewport-segments: 2) {
    .email-app {
      grid-template-columns:
        env(viewport-segment-width 0 0)
        env(viewport-segment-width 1 0);
    }
    /* List on left screen, detail on right screen */
    .email-list {
      grid-column: 1;
      overflow-y: auto;
    }
    .email-detail {
      grid-column: 2;
      display: block; /* reveal on unfolded device */
    }
  }
}

/* If fold features aren't supported:
   - @supports fails, fold CSS is skipped
   - User gets the normal single-column layout
   - Nothing breaks */

Testing foldable layouts

Chrome DevTools has a device emulation mode for foldable devices. Test at: Galaxy Z Fold folded (373px), unfolded (884px), dual-screen mode (2 segments), iPad 1/3 split (341px), iPad full (1024px), normal phone (393px), and desktop (1440px). If your layout works at all of those using container queries alone, then fold-aware CSS is purely additive enhancement.
