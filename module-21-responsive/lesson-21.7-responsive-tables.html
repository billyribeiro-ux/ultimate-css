Responsive Data Tables

Four patterns for tables on small screens: horizontal scroll, stacked cards, column toggle, and priority columns with sticky first column. Each with trade-offs explained and a working implementation.

Pattern 1: Horizontal scroll

The simplest approach. Wrap the table in an overflow container and let users scroll horizontally:

.table-wrap {
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
}
/* Pros: preserves table semantics, simple
   Cons: content hidden off-screen, discoverability */

Pattern 2: Stacked cards

Each row becomes a card with label/value pairs. Uses data-label attributes and CSS Grid:

@container (max-width: 600px) {
  table, thead, tbody, tr, th, td {
    display: block;
  }
  thead { display: none; }
  tr {
    margin-block-end: 1rem;
    padding: 1rem;
    border: 1px solid var(--border);
    border-radius: 0.5rem;
  }
  td::before {
    content: attr(data-label);
    font-weight: 600;
    display: block;
    margin-block-end: 0.25rem;
  }
}
/* Pros: all data visible, mobile-friendly
   Cons: loses tabular comparison, verbose */

Pattern 3: Column toggle

Hide less-important columns at narrow widths. Priority classes control which columns remain visible:

@container (max-width: 700px) {
  .col-low { display: none; }
}
@container (max-width: 500px) {
  .col-medium { display: none; }
}
/* Pros: keeps table format, progressive
   Cons: data is hidden, needs priority decisions */

Pattern 4: Priority columns (sticky first)

Keep the first (identifying) column sticky while the rest scroll horizontally:

.table-wrap { overflow-x: auto; }
th:first-child, td:first-child {
  position: sticky;
  inset-inline-start: 0;
  background: var(--bg);
  z-index: 1;
}
/* Pros: identifier always visible, full data accessible
   Cons: requires fixed-width first column */
