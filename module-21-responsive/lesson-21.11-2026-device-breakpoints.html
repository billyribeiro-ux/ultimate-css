2026 Device Landscape: Every Breakpoint That Matters

The complete reference of CSS viewport widths, pixel ratios, and safe-area insets across every major device category in 2026. Then: why you should ignore most of them.

Phone (compact): 360-440px CSS width

The compact phone tier has settled into a narrow range. All modern phones ship with CSS widths between 360px and 440px, regardless of their physical resolution.

/* 2026 phone CSS widths */
/* iPhone 16 / 16 Pro:    393 x 852  (2x / 3x DPR) */
/* iPhone 16 Pro Max:     440 x 956  (3x DPR) */
/* Samsung Galaxy S25:    412 x 915  (3x DPR) */
/* Google Pixel 9:        412 x 924  (2.625x DPR) */

/* Dynamic Island safe area */
/* iPhone 16 Pro: safe-area-inset-top: 59px */
/* Usage: */
.app-header {
  padding-block-start: env(safe-area-inset-top, 0px);
}

Tablet: 768-1024px

Tablets occupy a wide band. iPad models cluster around 820px, while the largest iPad Pro reaches 1024px in portrait. Samsung tablets sit at 800px.

/* 2026 tablet CSS widths */
/* iPad (10th gen):       820 x 1180  (2x DPR) */
/* iPad Air M3:           820 x 1180  (2x DPR) */
/* iPad Pro 11":          834 x 1194  (2x DPR) */
/* iPad Pro 13":         1024 x 1366  (2x DPR) */
/* Samsung Tab S10:       800 x 1280  (2x DPR) */

/* iPad multitasking splits: 1/3, 1/2, 2/3, full */
/* A "tablet" can be 320px wide in split view */

Laptop: 1024-1920px

Laptop viewports vary dramatically. A MacBook Air at default scaling is 1470px, but a budget Windows laptop may show 1366px. All are "laptop" but the CSS width range spans nearly 600px.

/* 2026 laptop CSS widths */
/* MacBook Air 13":      1470 x 956   (2x DPR) */
/* MacBook Pro 14":      1512 x 982   (2x DPR) */
/* MacBook Pro 16":      1728 x 1117  (2x DPR) */
/* Typical Windows:      1366 x 768   (1x DPR) */
/* Common Windows:       1536 x 864   (1.25x DPR) */
/* Full HD:              1920 x 1080  (1x DPR) */

Desktop / External: 1920px+

External monitors start where laptops leave off. The range stretches from 1920px all the way to 5120px on ultrawide displays.

/* 2026 desktop / external CSS widths */
/* 1440p:    2560 x 1440 */
/* 4K:       3840 x 2160 */
/* Ultrawide: 3440 x 1440 */
/* Super UW: 5120 x 2160 */

/* At 2x scaling, a 4K monitor shows 1920 CSS pixels */
/* At "default" (no scaling), it shows 3840 CSS pixels */
/* Always design for CSS pixels, not physical pixels */

Foldable: two widths per device

Foldable phones have two distinct CSS widths. The Samsung Galaxy Z Fold 6 is 373px when folded (a normal phone) and 884px when unfolded (a small tablet). This is a device that changes breakpoint tier by physically opening.

/* Samsung Galaxy Z Fold 6 */
/* Folded (cover):  373 x 832  (phone) */
/* Unfolded (main): 884 x 832  (tablet) */

/* Fold detection media features */
@media (horizontal-viewport-segments: 2) {
  /* Device has two horizontal viewport segments (unfolded, dual-screen) */
  .layout {
    display: grid;
    grid-template-columns:
      env(viewport-segment-width 0 0)
      env(viewport-segment-width 1 0);
  }
}

@media (vertical-viewport-segments: 2) {
  /* Device has two vertical viewport segments (e.g. laptop/tent mode) */
}

The PE7 recommendation: stop targeting devices

The device list above is a reference, not a prescription. If your layout uses media queries at 375px, 768px, 1024px, and 1440px, you are designing for exactly four sizes. Every width between those breakpoints is an afterthought.

Continuous adaptation beats discrete breakpoints

The modern CSS toolkit gives you tools for continuous adaptation. Use them instead of device-specific breakpoints:

/* Instead of media queries at device widths... */
/* Use auto-fit for grids: */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: clamp(0.75rem, 0.5rem + 1vw, 1.5rem);
}

/* Use clamp() for typography: */
h1 { font-size: clamp(1.5rem, 1rem + 2.5vw, 3.5rem); }

/* Use container queries for component adaptation: */
.card-container { container-type: inline-size; }
@container (min-width: 25rem) {
  .card { flex-direction: row; }
}

/* These work at EVERY width, not just 4 breakpoints */

When breakpoints are still useful

Breakpoints remain appropriate for major layout shifts that cannot be expressed intrinsically: switching from a bottom tab bar to a side nav, hiding a desktop-only sidebar, or changing interaction patterns. These are UX decisions, not CSS sizing decisions.

/* Acceptable: UX pattern change */
@media (max-width: 48rem) {
  .desktop-sidebar { display: none; }
  .mobile-tab-bar  { display: flex; }
}

/* Avoid: CSS sizing at device widths */
@media (min-width: 375px) { .card { width: 50%; } }
@media (min-width: 768px) { .card { width: 33%; } }
/* Use auto-fit instead */
