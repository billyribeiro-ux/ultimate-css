Lesson 21.1 · Fluid Systems

Fluid Typography with clamp()

The clamp(min, preferred, max) pattern for type that scales smoothly between viewport sizes. No media queries, no breakpoints — just text that flows from mobile to desktop in one continuous motion.

The problem with fixed font sizes

Traditional responsive typography uses media queries to jump between sizes: 1rem on mobile, 1.25rem on tablet, 1.5rem on desktop. These discrete jumps create awkward in-between states and require constant maintenance as new breakpoints emerge.

The clamp() formula

The clamp() function takes three arguments: a minimum, a preferred (fluid) value, and a maximum. The browser uses the preferred value unless it falls below the minimum or exceeds the maximum.

/* The formula */
font-size: clamp(1rem, 0.5rem + 1.5vw, 2rem);

/* Breakdown:
   min: 1rem (16px) — never smaller than this
   preferred: 0.5rem + 1.5vw — scales with viewport
   max: 2rem (32px) — never larger than this
*/

Why vw alone is dangerous

Using font-size: 3vw alone creates two problems: (1) on a 320px viewport that's only 9.6px — unreadable, and (2) it completely ignores the user's font-size preference set in browser settings. A user who sets their default to 20px for accessibility gets overridden.

The rem + vw hybrid

By combining rem (respects user preference) with vw (responds to viewport), we get the best of both worlds. The rem portion acts as an accessible baseline that the vw portion adds to:

/* Accessible fluid type */
font-size: clamp(1rem, 0.75rem + 1vw, 1.5rem);

/* If user sets base to 20px:
   min becomes 20px (not 16px)
   preferred becomes 15px + 1vw
   max becomes 30px
   User preference is respected throughout */

Building a complete fluid type scale

A production type scale defines every size token with clamp(). The key insight: larger sizes need more dramatic scaling, smaller sizes need less.

:root {
  --text-xs:  clamp(0.75rem, 0.7rem + 0.25vw, 0.875rem);
  --text-sm:  clamp(0.875rem, 0.8rem + 0.4vw, 1rem);
  --text-base: clamp(1rem, 0.9rem + 0.5vw, 1.125rem);
  --text-lg:  clamp(1.125rem, 0.95rem + 0.9vw, 1.5rem);
  --text-xl:  clamp(1.25rem, 0.9rem + 1.5vw, 2rem);
  --text-2xl: clamp(1.5rem, 0.8rem + 2.5vw, 2.75rem);
  --text-3xl: clamp(2rem, 1rem + 3.5vw, 4rem);
}

The math behind the preferred value

To calculate the preferred value for a given min/max range across viewport sizes:

/* Target: 1rem at 320px, 2rem at 1200px

   slope = (max - min) / (vw-max - vw-min)
   slope = (32 - 16) / (1200 - 320) = 16/880 = 0.01818
   In vw: 1.818vw

   intercept = min - slope * vw-min
   intercept = 16 - 0.01818 * 320 = 10.18px = 0.636rem

   Result: clamp(1rem, 0.636rem + 1.818vw, 2rem)
*/

Line-height considerations

As font-size scales, line-height should adapt too. Large display text needs tighter leading than body text. Use unitless values that scale with the font-size, or use clamp() for the line-height itself:

/* Headings: tight leading that loosens on small screens */
h1 {
  font-size: var(--text-3xl);
  line-height: clamp(1.05, 0.9 + 0.5vw, 1.2);
}

/* Body: comfortable reading line-height */
p {
  font-size: var(--text-base);
  line-height: 1.6; /* unitless — scales with font-size */
}

/* Rule of thumb:
   - Display text: 1.0–1.2
   - Headings: 1.2–1.3
   - Body text: 1.5–1.7
   - Small/UI text: 1.3–1.5 */

Fluid type in practice: the cascade

Define the scale once at the :root level, then reference tokens throughout. Components never hardcode sizes — they use the scale:

/* tokens layer */
:root {
  --text-xs: clamp(0.75rem, 0.7rem + 0.25vw, 0.875rem);
  --text-sm: clamp(0.875rem, 0.8rem + 0.4vw, 1rem);
  --text-base: clamp(1rem, 0.9rem + 0.5vw, 1.125rem);
  --text-lg: clamp(1.125rem, 0.95rem + 0.9vw, 1.5rem);
  --text-xl: clamp(1.25rem, 0.9rem + 1.5vw, 2rem);
}

/* components layer — references only */
.card-title { font-size: var(--text-lg); }
.card-body  { font-size: var(--text-base); }
.card-meta  { font-size: var(--text-xs); }
/* No magic numbers, no breakpoints, fully maintainable */
