Lesson 21.12 · Responsive · Tokenization

Responsive Token Systems: Fluid Design Decisions

How to tokenize responsive behavior itself -- not just static values. Fluid spacing, fluid type, container-responsive tokens, density modes, and device-adaptive safe areas, all in one coherent system.

Fluid spacing tokens

Static spacing tokens like --space-md: 1rem force you to override at breakpoints. Fluid spacing tokens adapt continuously:

:root {
  --space-xs:  clamp(0.25rem, 0.2rem + 0.25vw, 0.5rem);
  --space-sm:  clamp(0.5rem, 0.4rem + 0.5vw, 0.75rem);
  --space-md:  clamp(0.75rem, 0.6rem + 0.75vw, 1.25rem);
  --space-lg:  clamp(1rem, 0.8rem + 1vw, 2rem);
  --space-xl:  clamp(1.5rem, 1.2rem + 1.5vw, 3rem);
  --space-2xl: clamp(2rem, 1.5rem + 2.5vw, 5rem);
}

/* Usage: spacing is now responsive by default */
.section { padding-block: var(--space-xl); }
.card    { padding: var(--space-md); gap: var(--space-sm); }

Fluid type tokens

Type tokens follow the same pattern. Larger sizes scale more aggressively, smaller sizes barely change:

:root {
  --size-base: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);
  --size-lg:   clamp(1.25rem, 1.1rem + 0.75vw, 1.75rem);
  --size-xl:   clamp(1.5rem, 1.2rem + 1.5vw, 2.5rem);
  --size-2xl:  clamp(2rem, 1.5rem + 2.5vw, 3.5rem);
  --size-4xl:  clamp(2.5rem, 1.5rem + 5vw, 5rem);
}

/* Body text barely changes (1rem to 1.125rem) */
/* Hero headings scale dramatically (2.5rem to 5rem) */
p  { font-size: var(--size-base); }
h1 { font-size: var(--size-4xl); }

Container-responsive tokens

Fluid tokens respond to the viewport. But what about components that live inside containers of varying widths? Container-responsive tokens change at the container level:

.card-wrapper {
  container-type: inline-size;
  --card-padding: var(--space-md);
  --card-gap: var(--space-sm);
  --card-font-size: var(--size-base);
}

@container (min-width: 30rem) {
  .card-wrapper {
    --card-padding: var(--space-lg);
    --card-gap: var(--space-md);
    --card-font-size: var(--size-lg);
  }
}

@container (min-width: 50rem) {
  .card-wrapper {
    --card-padding: var(--space-xl);
    --card-gap: var(--space-lg);
    --card-font-size: var(--size-xl);
  }
}

/* The card uses these tokens -- it doesn't know
   whether it's in a sidebar or the main content area */
.card {
  padding: var(--card-padding);
  gap: var(--card-gap);
  font-size: var(--card-font-size);
}

Density tokens

Density controls how compact or spacious the UI feels. Instead of creating separate compact/default/spacious token sets, use a single multiplier:

:root {
  --density: 1; /* 1 = default, 0.75 = compact, 1.25 = spacious */
}

.card {
  padding: calc(var(--space-md) * var(--density));
  gap: calc(var(--space-sm) * var(--density));
}

.table td {
  padding: calc(var(--space-xs) * var(--density))
           calc(var(--space-sm) * var(--density));
}

/* Compact mode: tighter data tables, denser dashboards */
.dashboard { --density: 0.75; }

/* Spacious mode: marketing pages, reading experiences */
.marketing { --density: 1.25; }

Device-adaptive tokens with safe areas

Modern phones with notches, Dynamic Islands, and rounded corners expose safe area insets. Tokenize them so components can consume them without knowing the device:

:root {
  --safe-top:    env(safe-area-inset-top, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left:   env(safe-area-inset-left, 0px);
  --safe-right:  env(safe-area-inset-right, 0px);
}

.app-header {
  padding-block-start: calc(var(--space-sm) + var(--safe-top));
  padding-inline: calc(var(--space-md) + max(var(--safe-left), var(--safe-right)));
}

.bottom-nav {
  padding-block-end: calc(var(--space-sm) + var(--safe-bottom));
}

/* On devices without notches, env() returns 0px (the fallback).
   On iPhone 16 Pro, --safe-top is 59px.
   The layout adapts automatically. */

Combining all token layers

A production token system stacks these layers: fluid viewport tokens at the root, container-responsive overrides at the component level, density as a multiplier, and safe areas as additive offsets. Each layer is independent -- fluid tokens scale with the viewport, container tokens adapt to local space, density adjusts compactness, and safe areas handle device chrome.
