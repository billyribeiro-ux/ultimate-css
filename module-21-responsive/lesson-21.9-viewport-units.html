Viewport Units: The Complete Reference

vw, vh, svh, lvh, dvh, vi, vb, and why 100vh is wrong on mobile. The definitive guide to viewport units including the new dynamic viewport units that account for mobile browser chrome.

Classic units: vw and vh

1vw = 1% of the viewport width. 1vh = 1% of the viewport height. These are the original viewport units and they have a critical flaw on mobile: 100vh includes the area behind the browser's URL bar, creating overflow.

/* This creates overflow on mobile! */
.hero { height: 100vh; }

/* The URL bar takes ~60-80px on mobile.
   100vh = viewport height INCLUDING the URL bar area.
   The element extends behind/below the URL bar. */

New viewport units: svh, lvh, dvh

Three new variants solve the mobile browser chrome problem:

/* svh — Small Viewport Height
   The viewport with browser chrome FULLY visible.
   This is the smallest the viewport can be. SAFE choice. */
.hero { height: 100svh; }

/* lvh — Large Viewport Height
   The viewport with browser chrome FULLY hidden.
   This is the largest the viewport can be. */
.bg { min-height: 100lvh; }

/* dvh — Dynamic Viewport Height
   Tracks the CURRENT viewport height as chrome appears/disappears.
   Updates live — can cause reflows! Use cautiously. */
.section { height: 100dvh; }

When to use which

/* Full-screen hero: use svh (safe, no overflow) */
.hero { min-block-size: 100svh; }

/* Sticky footer layout: use dvh for smooth updates */
body { min-block-size: 100dvh; }

/* Background positioning: use lvh (largest area) */
.bg-fill { block-size: 100lvh; }

/* General rule: default to svh unless you need dynamic */

Writing-mode-aware: vi and vb

For layouts that must work in both horizontal and vertical writing modes:

/* vi = viewport inline axis (width in horizontal, height in vertical)
   vb = viewport block axis (height in horizontal, width in vertical) */

.container {
  max-inline-size: 90vi;  /* 90% of inline viewport axis */
  min-block-size: 50vb;   /* 50% of block viewport axis */
}
/* These adapt to writing-mode: vertical-rl automatically */

svmin and svmax

Small viewport versions of vmin/vmax — the smaller or larger of svw and svh:

/* svmin: the smaller of svw and svh
   Perfect for elements that must fit within the viewport */
.modal {
  inline-size: min(90svmin, 600px);
  block-size: min(80svmin, 500px);
}

Demo — Viewport units comparison

svh
Small viewport height. Chrome fully visible. Never overflows.
Use for: full-screen heroes, safe default
lvh
Large viewport height. Chrome fully hidden. Maximum available.
Use for: background fills, maximum coverage
dvh
Dynamic viewport height. Updates live as chrome toggles.
Use for: sticky footers, interactive layouts
vi / vb
Viewport inline/block. Writing-mode aware viewport units.
Use for: i18n-ready layouts, logical sizing

Try it yourself

Mini-exercise

Create a three-section page where each section takes exactly 100svh in height. The first section should use a centered hero layout, the second a two-column layout, and the third a centered call-to-action. Ensure none of them overflow on mobile by using svh instead of vh. Add a min-block-size fallback for browsers that don't support svh.
