Lesson 25.1 · Custom Properties

How Custom Properties Inherit and Cascade

Inheritance flows down the DOM tree. A property set on a parent is available to all descendants. Overriding at any level creates a new scope. Understanding this mechanism is the foundation for every advanced custom property pattern.

The inheritance model

Custom properties inherit by default. When you set --color: oklch(60% 0.2 275) on a parent element, every descendant can read that value via var(--color). This is unlike most CSS properties which do not inherit (like padding or border).

Global vs. component-scoped

Setting a custom property on :root makes it a global token available everywhere. Setting it on a component class creates a local scope:

:root {
  --color-primary: oklch(55% 0.22 275);
}

.card {
  --card-padding: 1.5rem;
  padding: var(--card-padding);
}

The --color-primary is available to every element in the document. The --card-padding is only available inside .card and its descendants.

Overriding creates a new scope

When a descendant redefines a custom property, it creates a new inheritance scope from that point downward. The parent's value is unaffected:

.parent { --color: oklch(60% 0.2 275); }
.child  { --color: oklch(60% 0.2 150); }
/* Grandchild inherits from .child, not .parent */

The cascade

Custom properties participate fully in the cascade. They respect specificity, source order, layers, and importance:

@layer base {
  .btn { --btn-bg: oklch(50% 0.2 275); }
}
@layer components {
  .btn { --btn-bg: oklch(55% 0.22 275); }
  /* Wins — higher layer */
}

Specificity applies

A more specific selector wins, just like any other property:

.card { --accent: oklch(55% 0.2 275); }
.card.featured { --accent: oklch(65% 0.25 50); }
/* .card.featured has higher specificity */

Inheritance vs. the universal selector

Setting a property on * is not the same as relying on inheritance. The universal selector sets the property directly on every element, while :root sets it once and lets inheritance distribute the value. The former prevents overriding at intermediate levels without higher specificity.

Stopping inheritance with @property

By default, custom properties always inherit. To create a property that does not inherit, register it:

@property --card-elevation {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}
/* Children of a card with --card-elevation: 3
   will NOT inherit that value — they get 0 */

This is critical for component-scoped values that should not leak into children (e.g., elevation levels, internal state flags).

Practical implications

The inheritance model means custom properties are "opt-out" rather than "opt-in." Every descendant receives the value unless it explicitly overrides. This makes them ideal for theming (colors cascade to all children) but potentially surprising for tightly scoped values. The rule of thumb: use inheritance for tokens (colors, spacing scales, type sizes) and register with inherits: false for component internals.

Key rules to remember

  • Custom properties inherit by default — unlike padding, border, display.
  • Overriding a property at any level creates a new scope from that point downward.
  • The cascade applies fully: specificity, source order, layers, !important.
  • Use @property { inherits: false } to prevent inheritance for component internals.
  • :root is the canonical place for global tokens; component selectors for local ones.

Mini-exercise

Add a third branch with --accent: oklch(55% 0.2 30) and observe how its leaves pick up the red accent automatically. Then try setting --accent on a single leaf to override just that one element while its siblings keep the branch color.
