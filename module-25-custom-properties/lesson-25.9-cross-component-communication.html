Lesson 25.9 · Custom Properties

Cross-Component Communication

A parent sets a custom property, children read it — no classes, no JS events, no data attributes. This inheritance-based communication lets components coordinate visuals without knowing about each other.

The slot pattern

A wrapper provides a color or size property. Any child that uses that property inherits it automatically:

.hero-section {
  --slot-accent: oklch(55% 0.22 275);
  --slot-radius: 0.75rem;
}

/* These components know nothing about .hero-section */
.btn   { background: var(--slot-accent, oklch(50% 0.2 0)); }
.badge { border-color: var(--slot-accent, oklch(50% 0.2 0)); }
.link  { color: var(--slot-accent, oklch(50% 0.2 0)); }

Drop these components inside any wrapper that sets --slot-accent and they adapt.

The layout intent pattern

A layout wrapper communicates its intent via a custom property. Children adjust their styles based on context:

.sidebar-layout { --layout-context: sidebar; }
.main-content   { --layout-context: main; }

/* Card adapts to its context */
.card {
  padding: 1.5rem;
}
@container style(--layout-context: sidebar) {
  .card { padding: 0.75rem; font-size: 0.85rem; }
}

Nested theming

Override surface colors at any nesting level. A dark card inside a light page overrides --surface for its descendants:

body {
  --surface: oklch(98% 0.01 275);
  --on-surface: oklch(20% 0 0);
}

.dark-card {
  --surface: oklch(20% 0.02 275);
  --on-surface: oklch(92% 0.01 275);
  background: var(--surface);
  color: var(--on-surface);
}

/* Any child inside .dark-card inherits the dark tokens */
.dark-card .badge {
  background: var(--on-surface);
  color: var(--surface);
}

One property, four components

The power of this pattern: change one property on the wrapper, and every child component that consumes it reacts. No event system, no prop drilling, no selectors reaching into children.
