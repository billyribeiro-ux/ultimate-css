Lesson 25.6 · Custom Properties

Responsive Values via Custom Properties

Set different custom property values at different breakpoints without duplicating component code. Separate "when it changes" (the container query) from "what changes" (the component styles) for cleaner, more maintainable responsive design.

The separation pattern

Instead of rewriting component styles inside media or container queries, change only the custom property values:

.dashboard {
  --cols: 1;
  --gap: 0.75rem;
  container-type: inline-size;
}

@container (min-width: 30rem) {
  .dashboard { --cols: 2; --gap: 1rem; }
}
@container (min-width: 50rem) {
  .dashboard { --cols: 3; --gap: 1.5rem; }
}

.dashboard-grid {
  display: grid;
  grid-template-columns: repeat(var(--cols), 1fr);
  gap: var(--gap);
}

Why this is better

The grid component has one definition. It reads its configuration from custom properties. The container queries only set values — they know nothing about how those values are consumed. This clean separation means:

  • Component styles are defined once (no duplication across breakpoints).
  • Breakpoint logic is centralized and easy to scan.
  • Adding a new breakpoint means adding one rule, not rewriting layout code.

Works with viewport queries too

:root {
  --content-width: 100%;
  --sidebar-width: 0fr;
}
@media (min-width: 60rem) {
  :root {
    --content-width: 1fr;
    --sidebar-width: 16rem;
  }
}

Responsive typography

Custom properties combined with clamp() give you fluid sizing with named breakpoint overrides:

:root {
  --heading-size: clamp(1.5rem, 4vw, 3rem);
  --body-size: clamp(0.9rem, 1.5vw, 1.1rem);
}
@container (min-width: 50rem) {
  .article { --heading-size: 2.5rem; }
}

The "configuration" vs. "implementation" split

This pattern creates a clear architectural boundary:

  • Configuration layer — container/media queries that set property values. Answers "when?" and "what value?"
  • Implementation layer — component styles that consume properties. Answers "how is this value used?"

This separation means you can change breakpoints without touching components, or restyle components without touching breakpoints. Each layer can be maintained independently.

Combining with design tokens

In a token-based system, responsive custom properties become the bridge between static tokens and dynamic context:

/* Static tokens (never change) */
:root { --space-sm: 0.5rem; --space-md: 1rem; --space-lg: 1.5rem; }

/* Context-aware mapping */
.panel { --panel-gap: var(--space-sm); }
@container (min-width: 30rem) {
  .panel { --panel-gap: var(--space-md); }
}
@container (min-width: 50rem) {
  .panel { --panel-gap: var(--space-lg); }
}
