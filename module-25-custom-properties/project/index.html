How it works

This entire page derives its visual appearance from three custom properties:

  • --pg-hue (0-360) — drives the entire OKLCH color system. Primary, secondary, surfaces, and borders all reference this single hue value.
  • --pg-density (0.4-1.0) — multiplied against spacing, padding, border-radius, and font sizes. Compresses or expands the entire UI proportionally.
  • --pg-dark (0 or 1) — used in lightness calculations via calc(). Flips all lightness values to create a dark mode without a single additional class.

Patterns demonstrated

  • Lesson 25.1 — Inheritance cascading from root to all children.
  • Lesson 25.3 — Numeric toggle (--is-dark: 0/1) for light/dark switching.
  • Lesson 25.5 — Single hue generating a full palette via OKLCH.
  • Lesson 25.7 — @property registration for smooth transitions.
  • Lesson 25.8 — calc() and density multiplier for computed layouts.
  • Lesson 25.9 — Cross-component communication through inherited properties.

Key implementation detail

The only JavaScript is on the three input elements: each sets one custom property on the root .demo-25-project element. The CSS handles everything else reactively through var() and calc().

Challenge

Add a fourth control: a --roundness slider that independently controls border-radius across all components (from sharp 0 to pill-shaped). Then add a fifth component — a notification toast — that consumes all four properties. The goal: every element on the page responds to every control, creating a fully parametric UI system.
