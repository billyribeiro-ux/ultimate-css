Lesson 25.4 · Custom Properties

Component State Machines with Custom Properties

A button has states: default, hover, active, loading, success, error. Each state sets custom properties that drive every visual aspect simultaneously. Changing state means changing one property — everything else reacts.

The state machine pattern

Instead of scattering visual changes across pseudo-classes and modifier classes, centralize them into custom properties:

.btn {
  --btn-bg: oklch(55% 0.22 275);
  --btn-color: oklch(100% 0 0);
  --btn-scale: 1;
  --btn-cursor: pointer;
  --btn-opacity: 1;

  background: var(--btn-bg);
  color: var(--btn-color);
  transform: scale(var(--btn-scale));
  cursor: var(--btn-cursor);
  opacity: var(--btn-opacity);
}

.btn:hover   { --btn-bg: oklch(60% 0.24 275); }
.btn:active  { --btn-scale: 0.97; }
.btn.loading { --btn-cursor: wait; --btn-opacity: 0.7; }
.btn.success { --btn-bg: oklch(55% 0.18 150); }
.btn.error   { --btn-bg: oklch(55% 0.2 25); }

Why this is powerful

The component's visual output is a function of its state properties. You can read which state a button is in by inspecting its custom properties in DevTools. Adding a new state means adding one rule that sets the relevant properties — you never touch the base styles.

The space toggle approach

For states that need multiple simultaneous changes, the space toggle gives you "all or nothing" activation:

.btn {
  --is-loading: initial;
  --is-success: initial;
  --is-error: initial;
}
.btn.loading { --is-loading: ; }
.btn.success { --is-success: ; }
.btn.error   { --is-error: ; }

Each toggle activates an entire visual profile: background, color, icon visibility, cursor, and pointer-events all flip at once.

Transition-friendly

Because the visual properties read from custom properties, transitions on background, color, transform, and opacity animate between states smoothly. Register properties with @property for interpolation control.
