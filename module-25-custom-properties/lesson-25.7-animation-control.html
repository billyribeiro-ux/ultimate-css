Lesson 25.7 · Custom Properties

Controlling Animations with Custom Properties

A single --progress property can drive a progress bar, color gradient, transform, and opacity simultaneously. This "conductor pattern" gives you one animated value with many visual consumers — the foundation of scroll-driven and timeline-based effects.

The conductor pattern

Instead of animating each property independently, animate one custom property and let multiple elements consume it:

@property --progress {
  syntax: "<number>";
  inherits: true;
  initial-value: 0;
}

.scene {
  --progress: 0;
  transition: --progress 0.5s;
}
.scene:hover { --progress: 1; }

.bar   { width: calc(var(--progress) * 100%); }
.fade  { opacity: var(--progress); }
.slide { transform: translateX(calc(var(--progress) * 200px)); }
.color { background: oklch(calc(50% + var(--progress) * 30%) 0.2 275); }

Why @property registration matters

Without @property, the browser treats custom properties as strings and cannot interpolate them. Registering with a syntax of "<number>" or "<percentage>" enables smooth transitions and keyframe animations on the property itself.

Scroll-driven animations

With scroll-driven animations, you can bind --progress to scroll position:

@keyframes track-scroll {
  from { --progress: 0; }
  to   { --progress: 1; }
}

.scene {
  animation: track-scroll linear;
  animation-timeline: scroll();
}

Now every consumer element reacts to scroll position through a single property.

Multiple timelines, one property

Different scroll containers or view timelines can each set their own progress property. Child elements subscribe to whichever is relevant — the inheritance model handles distribution.
