Lesson 25.8 · Custom Properties

Computed Layouts with calc() and Custom Properties

Custom properties combined with calc() create layouts that respond to numeric inputs: density sliders, column counts, and spacing scales. One number changes, and the entire UI compresses or expands.

Dynamic grid columns

The simplest computed layout: a column count custom property driving a grid:

.grid {
  --cols: 3;
  display: grid;
  grid-template-columns: repeat(var(--cols), 1fr);
}

The density pattern

A density value between 0.5 (compact) and 1 (spacious) scales all spacing proportionally:

:root {
  --density: 1;
  --space-unit: 1rem;
}

.card {
  padding: calc(var(--density) * var(--space-unit) * 1.5);
  gap: calc(var(--density) * var(--space-unit));
  border-radius: calc(var(--density) * 0.75rem);
  font-size: calc(0.8rem + var(--density) * 0.2rem);
}

At --density: 1, padding is 1.5rem. At --density: 0.5, it compresses to 0.75rem. Every element in the system that reads --density responds proportionally.

Why this works

CSS calc() resolves at computed-value time. Custom properties substitute before resolution. This means the math always uses the current value of the property, updated instantly when JS or a container query changes it.

Aspect-ratio grids

.tile {
  --ratio: 16 / 9;
  aspect-ratio: var(--ratio);
}

/* Override for specific content */
.tile.square { --ratio: 1; }
.tile.portrait { --ratio: 3 / 4; }

Computed spacing scales

Build a complete spacing system from two variables:

:root {
  --base: 0.25rem;
  --scale: 2;
}
.space-1 { padding: var(--base); }
.space-2 { padding: calc(var(--base) * var(--scale)); }
.space-3 { padding: calc(var(--base) * var(--scale) * var(--scale)); }
/* Geometric progression: 0.25, 0.5, 1, 2, 4... */

The min/max safety pattern

When using density multipliers, prevent values from going too small or too large:

.card {
  padding: max(0.5rem, calc(var(--density) * 1.5rem));
  font-size: clamp(0.75rem, calc(var(--density) * 1rem), 1.25rem);
  border-radius: min(calc(var(--density) * 1rem), 1.5rem);
}

The clamp(), min(), and max() functions act as guardrails, ensuring computed values stay within usable ranges regardless of the input.

Performance considerations

Custom properties with calc() are resolved at computed-value time. For most layouts, this is instant. However, if a single property change triggers recalculation of hundreds of elements (e.g., --density on :root consumed by 200 elements), be aware of potential frame drops during rapid input changes. Consider using will-change or debouncing for extreme cases.
