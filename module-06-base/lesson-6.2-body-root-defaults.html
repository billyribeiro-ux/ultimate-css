Lesson 6.2

:root and body Defaults

Four properties on :root, six on body, and the entire document inherits a sane typographic foundation. These ten lines of CSS are the most reused in the base layer — every project needs them, and every project writes them the same way.

color-scheme on :root

The color-scheme property tells the browser which of its native color schemes the document supports. The browser uses it for scrollbars, form controls, and the default UA palette — without it, a dark-mode page still has light scrollbars and light dropdowns.

:root {
  color-scheme: light dark;
}

Declaring light dark is an opt-in to both modes. The OS preference decides which one the UA controls adopt. Combined with light-dark() in Lesson 6.7, this single line drives the whole theming story.

The rest of :root

Keep :root minimal — it is where tokens live, not where rules live. The only rules that belong on :root itself are those that influence the whole document's rendering mode:

:root {
  color-scheme: light dark;
  font-family: var(--font-sans);
  font-size: 100%;
  line-height: var(--leading-normal);
  -webkit-text-size-adjust: 100%;
}

font-size: 100% respects the user's browser default text size — critical for users who have changed it for legibility. -webkit-text-size-adjust: 100% prevents iOS Safari from inflating text in landscape orientation.

body: the real baseline

body {
  font-family: var(--font-sans);
  font-size: var(--size-base);
  line-height: var(--leading-normal);
  color: var(--color-text-primary);
  background-color: var(--color-surface);
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}

Every property is a token. The only non-token lines are the two font-smoothing hints — they have no token because they are not values, they are rendering switches. Opinions differ on whether antialiased smoothing is correct for every design; pick the one that matches your brand and leave it alone.

Why background-color on body, not html

Backgrounds on html propagate to the canvas (the viewport) under the CSS backgrounds specification, which is occasionally what you want and occasionally a surprise. Setting background on body gives the normal element-level behaviour and still fills the viewport as long as the body is at least viewport-tall — which the reset guarantees via min-block-size: 100svh.

What we do not set here

  • No margin on body — the reset already cleared it.
  • No padding — that is layout's job.
  • No max-inline-size — the body is the canvas; constraint happens at .container in layout.

Mini-exercise

Change color-scheme: light dark to just dark and re-run. The form controls and scrollbar adopt dark chrome regardless of your OS preference. That is the forced-mode technique from Lesson 6.7 — useful for a permanent-dark marketing page or a code editor interface.
