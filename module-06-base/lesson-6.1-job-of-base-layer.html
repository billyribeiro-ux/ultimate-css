Lesson 6.1

The Job of the Base Layer

Between your design tokens and your first component lies a quiet layer that does all the work nobody notices. Base exists to turn raw HTML into a readable document using tokens alone. Get this layer right and components become trivial; get it wrong and every component re-implements typography.

The bridge

Tokens are numbers without meaning — --size-base: 1rem doesn't know what a paragraph is. Components are meaning without defaults — a .card doesn't know what a heading looks like. Base is the bridge. It takes the tokens and paints them onto every element in the HTML vocabulary: h1 through h6, p, a, code, table, blockquote, and so on.

Three rules, always

  1. No classes. Every selector is an element, a pseudo-element, or an attribute selector on an element. h1, p, a:hover, code, ::selection. If you need a class, write a component.
  2. No hard-coded values. Every length, color, and font comes from a token. No font-size: 18px; always font-size: var(--size-lg). No #333; always color: var(--color-text-primary).
  3. Logical properties only. margin-block instead of margin-top/bottom, max-inline-size instead of max-width. This is covered in depth in Lesson 6.5.

Why these rules exist

The constraint is what makes base reusable. Two projects with different components but the same token scale can share the same base file verbatim. Two projects with different languages — one LTR, one RTL — can share base because logical properties adapt to writing mode. A project that needs a dark mode can flip it by redefining tokens alone, because base never touches a raw color.

What belongs in base

  • Root and body defaults (font-family, color, background, color-scheme).
  • Heading sizes and weights, bound to tokens.
  • Paragraph measure, link styles, inline text (strong, em, code, small).
  • List indentation, blockquote styling, horizontal rules.
  • Table defaults.
  • Focus styles via :focus-visible.
  • Selection color.

What does not belong in base

  • Anything that targets a class. That is a component.
  • Anything that sets a fixed pixel value. That is a missing token.
  • Layout primitives like .stack or .grid. Those live in @layer layout.
  • Visual polish like shadows on cards or hover states on buttons. Those are components.

The anti-pattern

The most common mistake is writing base rules that target classes: .prose h1 { ... }, .article p { ... }. That is a component dressed as base. It works — until a second project, a second theme, or a second layout wants the same typography without the wrapping class. By keeping base element-only, every project gets the typography for free.

Mini-exercise

Open the base CSS of any project you worked on recently. Count the number of rules that target a class. That count is the number of rules that should not have been in base. Write them down — Module 8 will show you where they actually belong.
