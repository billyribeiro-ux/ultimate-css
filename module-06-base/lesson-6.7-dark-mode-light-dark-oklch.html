Lesson 6.7

Dark Mode with light-dark() and OKLCH

Dark mode does not belong in every component. It belongs in one place: the token layer. One function — light-dark() — expresses both values in a single declaration, and OKLCH makes sure the dark palette feels like the light palette rather than looking like a broken copy of it.

light-dark() at the token level

The light-dark() function takes two color values and picks one based on the element's current color-scheme. Combined with color-scheme: light dark on :root, it gives you automatic dark mode with zero media queries.

:root {
  color-scheme: light dark;

  --color-surface: light-dark(oklch(99% 0.003 264), oklch(15% 0.02 264));
  --color-text-primary: light-dark(oklch(18% 0.02 264), oklch(95% 0.01 264));
  --color-primary: light-dark(oklch(55% 0.22 275), oklch(70% 0.18 275));
}

Every other layer — base, components, utilities — uses the tokens without caring which mode is active. That is the whole technique. The base layer never writes a @media (prefers-color-scheme: dark) block. Tokens carry the complexity so the rest of the codebase stays simple.

Why OKLCH matters for dark mode

sRGB is perceptually non-uniform — a 10% lightness drop in blue looks very different from a 10% lightness drop in yellow. When you invert a palette from light to dark in sRGB, saturated colors become either washed out or neon-bright. OKLCH is perceptually uniform: oklch(55% 0.22 275) and oklch(70% 0.18 275) share a hue angle and the eye reads them as the "same color, different weight."

A practical heuristic for dark-mode color derivation:

  • Surfaces: flip lightness. A 99% light surface becomes an 15% dark surface.
  • Text: flip lightness, drop chroma slightly. A 18%/0.02 text becomes a 95%/0.01 text.
  • Accents: raise lightness by 10-15% and drop chroma by 10-20%. A saturated 55%/0.22 primary becomes 70%/0.18 in dark mode — the hue is recognisable, the contrast is maintained, and the eye does not burn.

Forcing a mode

Sometimes you want a permanent dark section — a marketing hero, a code editor panel, a fullscreen presentation. Force color-scheme on the ancestor and every descendant token flips:

.dark-section { color-scheme: dark; }
.light-section { color-scheme: light; }

Because light-dark() resolves against the nearest color-scheme, this works without any media query override — the tokens see the scheme and return the dark variant inside .dark-section, the light variant everywhere else.

Fallbacks

light-dark() is supported in all current browsers. For older browsers, the pre-PE7 pattern is a @media (prefers-color-scheme: dark) block that redefines the same tokens on :root. Wrap it in @supports not (color: light-dark(white, black)) if you want progressive enhancement.

Try it yourself

Mini-exercise

Remove the .force-light and .force-dark classes from the HTML. Both sections now follow your OS preference. Toggle your system dark mode on and off and watch them change in lockstep. Then change --accent to use a sRGB hex pair like light-dark(#6b46ff, #9b7bff) and compare how the hue drifts between modes. OKLCH keeps the hue stable; hex approximations do not.
