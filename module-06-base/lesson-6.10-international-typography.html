Lesson 6.10

International Typography: CJK, Ruby & Text Polish

Most CSS defaults were designed around Latin text: words separated by spaces, emphasis by italics, lines broken at word boundaries. Chinese, Japanese, and Korean follow none of those rules — and a base layer that ignores them ships visibly broken typography to a third of the web's readers. This lesson covers the properties that fix CJK text, plus the finishing details — drop caps, hanging punctuation, language-aware quotes — that polish every locale.

Why Latin-centric CSS breaks for global text

The root cause is structural. CJK text has no inter-word spaces, so "break at spaces" produces no useful break opportunities — browsers instead allow a break after almost any character, which is correct but crude: Japanese lines wrap mid-word and mid-phrase. CJK punctuation is full-width, carrying built-in padding that doubles up visually when two marks meet. Emphasis is marked with dots above characters, not slanted glyphs — italicizing Japanese is as wrong as dotting English. None of this can be fixed by a generic reset; it needs language-aware properties, and a base layer that applies them via :lang().

text-spacing-trim — kerning full-width punctuation

Full-width brackets and periods (「」、。) occupy a full em square each. When two land adjacently — a closing bracket followed by a comma — the result is a visible hole in the line. text-spacing-trim tells the engine to trim that built-in spacing contextually, the way professional Japanese typesetting (JIS X 4051) requires:

:lang(ja), :lang(zh) {
  text-spacing-trim: normal;     /* trim adjacent full-width punctuation */
}
/* Other values: space-all (legacy full spacing),
   space-first, trim-start */

Progressive — Chrome 123+, with other engines planned. It is purely cosmetic refinement, so it can ship unguarded; use @supports (text-spacing-trim: space-all) only if you need to branch other styles on it.

word-break: auto-phrase — natural Japanese line breaks

Default CJK breaking is "anywhere", which routinely splits a word like 最先端 (cutting-edge) across two lines. word-break: auto-phrase runs a phrase-segmentation model (Chrome uses BudouX) and moves break opportunities to bunsetsu — natural phrase boundaries — the difference between a machine-wrapped paragraph and one a typesetter would approve.

:lang(ja) :is(h1, h2, h3, .standfirst) {
  word-break: auto-phrase;
}

Progressive — Chrome 119+. Unsupporting engines treat the value as invalid and keep default breaking, so this is a zero-risk enhancement. Note it costs segmentation work; the guidance is headings and short lead text, not ten-thousand-character articles.

Precision recap: line-break, word-break, overflow-wrap

Three properties, three different jobs — worth stating precisely because they are chronically confused:

  • line-break tunes the strictness of CJK breaking rules (kinsoku): strict forbids breaks before small kana and prolonged-sound marks; loose permits them for narrow columns.
  • word-break changes where breaks are allowed at all: break-all (anywhere, even Latin), keep-all (treat CJK like spaced words — useful for Korean, which has spaces), auto-phrase (above).
  • overflow-wrap: break-word is the last-resort emergency break from Lesson 6.8 — it only fires when a word cannot otherwise fit.
:lang(ko) { word-break: keep-all; }   /* Korean has spaces — use them */
:lang(ja) { line-break: strict; }     /* honor kinsoku rules */

Ruby annotations

Ruby is the small annotation text above (or beside) characters — furigana readings in Japanese, pinyin in Chinese learning material. The structure is HTML; CSS controls placement and distribution. All of this is production across the three engines.

<ruby>漢字<rp>(</rp><rt>かんじ</rt><rp>)</rp></ruby>

ruby { ruby-position: over; }   /* or: under */
rt   { ruby-align: space-around; } /* start | center | space-between */

The <rp> elements hold fallback parentheses that only render in museum-grade browsers without ruby support — keep them; they cost nothing. ruby-position: under serves conventions like Taiwanese zhuyin placement in horizontal text and double-sided annotations.

Text emphasis marks

Where Latin uses italics, Japanese and Chinese emphasis places a mark — a dot or sesame — over each character (圏点/着重号). text-emphasis draws these without extra markup, and it is production:

:lang(ja) em {
  font-style: normal;             /* italics are not Japanese emphasis */
  text-emphasis: filled dot;      /* also: open circle, sesame, "❀" */
  text-emphasis-position: over right;  /* under left for some zh styles */
}

:lang() and language-correct quotes

The pattern uniting this lesson: write language rules once, keyed on :lang(), in the base layer. The selector matches the inherited lang attribute, so a single <html lang="ja"> or a per-element override both work. The quotes property is the smallest, highest-value example — <q> elements render the typographically correct marks per language instead of ASCII quotes everywhere:

:lang(en) { quotes: "\201C" "\201D" "\2018" "\2019"; }  /* “ ” ‘ ’ */
:lang(fr) { quotes: "«\202F" "\202F»"; }  /* « guillemets » + thin space */
:lang(de) { quotes: "\201E" "\201C"; }    /* „low-high“ */
:lang(ja) { quotes: "「" "」" "『" "』"; }  /* corner brackets */

/* Modern engines do this automatically with: */
q { quotes: auto; }

initial-letter — true drop caps

The classic drop cap was a ::first-letter float with hand-tuned negative margins that broke whenever the font, size, or line-height changed (Lesson 16.3's article layout uses exactly that hack). initial-letter states intent directly — sink this letter n lines and size it to span them — and the browser aligns cap height and baseline precisely:

.article-opener::first-letter {
  /* Fallback for engines without initial-letter (Firefox, planned): */
  float: inline-start;
  font-size: 3.2em;
  line-height: 0.8;
  padding-inline-end: 0.1em;
}
@supports (initial-letter: 3) or (-webkit-initial-letter: 3) {
  .article-opener::first-letter {
    float: none; font-size: unset; line-height: unset; padding: 0;
    -webkit-initial-letter: 3;   /* Safari */
    initial-letter: 3;           /* sink 3 lines, span 3 lines */
    padding-inline-end: 0.15em;
  }
}

Progressive — Chrome 110+ and long-standing in Safari (prefixed, then unprefixed); Firefox planned. The float hack is the fallback, which is why the @supports block must undo it before applying the real thing.

hanging-punctuation

Optically aligned margins: an opening quote at the start of a line hangs outside the text edge so the letterforms align, the way fine book typography sets it. One declaration, progressive — Safari only, harmlessly ignored elsewhere:

blockquote, .prose { hanging-punctuation: first allow-end last; }

hyphenate-character and hyphenate-limit-chars

Lesson 6.8 turned on hyphens: auto; these two tune it. hyphenate-character swaps the break glyph (some languages and house styles use ⸗ or ‐), and hyphenate-limit-chars stops the engine hyphenating short words or leaving two-letter fragments — the difference between helpful and twitchy hyphenation. Both are additive refinements: unsupporting engines simply keep default hyphenation.

:lang(de) .prose {
  hyphens: auto;
  hyphenate-limit-chars: 7 4 3;  /* min word 7; ≥4 before, ≥3 after */
}

Try it yourself

Mini-exercise

Build the international block of your base layer. (1) Add :lang(ja), :lang(zh), and :lang(ko) rules: text-spacing-trim: normal and line-break: strict for Japanese and Chinese, word-break: keep-all for Korean, and word-break: auto-phrase on Japanese headings only. (2) Define quotes for every language your product ships, and verify each <q> renders its native marks. (3) Replace one drop-cap float hack with the initial-letter + @supports pattern from this lesson and confirm the fallback still renders in Firefox. (4) Add hanging-punctuation: first allow-end last to your pull quotes and check the optical alignment in Safari — then confirm nothing changes elsewhere, which is exactly what progressive enhancement should look like.
