Lesson 6.6

Accessible Focus Styles

Every keyboard user relies on focus rings to know where they are. Every designer complains that the default rings are ugly. The base layer reconciles both — a clean, high-contrast, intentional ring that appears only for keyboard users, satisfies WCAG, and matches your design tokens.

The :focus-visible split

The pseudo-class :focus matches any focused element, whether focus came from a keyboard, a click, or a script. :focus-visible matches only when the browser decides the user needs a visible indicator — essentially, keyboard and programmatic focus, never clicks on a button. The base layer uses both.

:focus-visible {
  outline: 2px solid var(--color-focus);
  outline-offset: 3px;
  border-radius: var(--radius-sm);
}
:focus:not(:focus-visible) {
  outline: none;
}

The first rule draws the ring when the user needs it. The second rule explicitly removes the ring when :focus-visible is not active — this is necessary because setting outline: none on everything and then re-adding it for :focus-visible breaks browsers that have not implemented the pseudo-class. The ":not(:focus-visible)" pattern is the safe form.

WCAG focus contrast (SC 1.4.11)

WCAG SC 1.4.11 (Non-text Contrast) requires focus indicators to meet a 3:1 contrast ratio against the adjacent background; WCAG 2.2's SC 2.4.13 (Focus Appearance, AAA) adds minimum-area requirements. A 1px outline in a light-grey color does not pass. The PE7 pattern uses a --color-focus token defined to be high-contrast in both light and dark modes — typically a saturated OKLCH around 55% lightness for light mode and 75% for dark.

outline, not box-shadow

A common trick is to use box-shadow: 0 0 0 3px as a focus ring because it can have rounded corners and color-mixing. Do not use it in base. box-shadow is part of the element's paint box and is clipped by overflow: hidden; a focus ring on a button inside a rounded-corner card can disappear entirely. outline is drawn outside the box and is never clipped — and as of 2023, outline supports the border-radius of its element, so the ring follows rounded corners natively.

outline-offset

A 3px offset pushes the ring away from the element so it reads as a halo rather than a border. On tight layouts reduce it to 2px; on roomy layouts increase it to 4px. This is a taste call, but never set it to 0 — a zero-offset outline is indistinguishable from a plain border when the element already has one.

Skip links

Not a base-layer rule, but worth knowing: every keyboard-navigable page benefits from a "skip to main content" link as the first focusable element. It lives in the components layer, not here.

Mini-exercise

Tab through the live preview. Every interactive element shows the ring. Click one of the buttons with your mouse. No ring. That is :focus-visible doing exactly the right thing — keyboard users see focus, mouse users do not get visual noise. Now set --color-focus to oklch(85% 0.05 275) and tab again. The ring is barely visible against the white background. That is a WCAG 1.4.11 (Non-text Contrast) failure. Restore the saturated value.
