Lesson 6.9

Variable Fonts, Font Features & Color Fonts

A traditional font family ships one file per weight — four weights, four network requests, and nothing in between. Variable fonts collapse the whole design space into a single file with continuous axes, and OpenType features unlock the typographic detail that is already sitting inside it. This lesson covers the high-level CSS that drives both, and the color-font layer (COLRv1, font-palette) that sits on top.

Why static weights waste bandwidth and design range

The root problem is quantization. A static family exposes a handful of points — 400, 500, 700 — sampled from a continuous design. Every weight you ship costs another file (often 20–60 KB of woff2 each), and every weight you don't ship is a design decision you can never make. A variable font stores the extremes plus interpolation deltas, so one file (typically 1.2–1.8× the size of a single static weight) yields every weight from 100 to 900, every width, every optical size. Fewer requests, smaller total payload, and font-weight: 580 becomes a legitimate, renderable value.

/* One @font-face rule covers the whole weight range */
@font-face {
  font-family: "Inter Var";
  src: url("/fonts/inter-var.woff2") format("woff2") tech(variations);
  font-weight: 100 900;   /* a RANGE, not a point */
  font-style: normal;
  font-display: swap;     /* loading strategy: Lesson 20.6 */
}

The five registered axes — drive them with high-level properties

OpenType registers five standard axes, and each one maps to an existing CSS property. This mapping is the most important fact in the lesson: when a registered axis exists, the high-level property is the correct interface.

/* wght — weight: any number in the font's range */
font-weight: 580;

/* wdth — width: percentage via font-stretch */
font-stretch: 87.5%;          /* (being renamed font-width; */
                              /*  font-stretch is the compat name) */

/* slnt — slant: oblique with an angle.
   Gotcha: oblique 12deg maps to slnt = -12 (sign is negated). */
font-style: oblique 12deg;

/* ital — italic: a 0/1 switch, not an angle */
font-style: italic;

/* opsz — optical size: tracked automatically from font-size */
font-optical-sizing: auto;    /* the initial value — leave it on */

font-optical-sizing: auto deserves a sentence of mechanics: fonts with an opsz axis redraw themselves for the size they are rendered at — higher contrast and tighter spacing at display sizes, sturdier strokes and open apertures at caption sizes. The browser feeds the computed font-size into the axis for you. Only set it to none when you deliberately want display-cut letterforms at small sizes.

font-variation-settings — the low-level escape hatch

font-variation-settings addresses axes by four-character tag, which is the only way to reach custom axes (GRAD, YTAS, CASL…). But it is deliberately low-level, and it has two sharp edges. First, it overrides the high-level properties: a "wght" 700 here silently beats any font-weight in the cascade, including ones set later. Second, it does not compose — each declaration replaces the entire axis list, so a child that sets only "GRAD" wipes out an inherited "wght". The PE7 rule: high-level properties for registered axes, font-variation-settings only for custom axes, and route values through custom properties so there is exactly one place each axis is written.

:root { --grade: 0; --casual: 0; }

.recursive-sample {
  font-weight: 450;                       /* registered axis: high-level */
  font-variation-settings: "CASL" var(--casual),
                           "GRAD" var(--grade);  /* custom axes only */
}
/* Change an axis by changing the custom property —
   never by writing a second font-variation-settings rule. */

Animating axes

Axis values are numbers, so they interpolate. The simple case needs nothing special: with a variable font loaded, transition: font-weight 200ms animates smoothly through every intermediate weight — a beautiful hover affordance for nav links. font-variation-settings also transitions, but only when the start and end values list the same axes in the same order; otherwise it falls back to a discrete flip. To animate a single custom axis independently, register a custom property with @property so the engine knows it is a <number> and can interpolate it, then feed it into the settings list.

@property --grade {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}
.link {
  --grade: 0;
  font-variation-settings: "GRAD" var(--grade);
  transition: --grade 200ms ease-out;   /* the NUMBER animates */
}
.link:hover { --grade: 150; }

/* Registered axes are simpler still: */
.nav-link { transition: font-weight 200ms; }
.nav-link:hover { font-weight: 700; }

One caution: weight changes alter glyph advance widths, so animating font-weight on inline text causes layout shift mid-animation. Reserve it for single-line UI text, or pick a font with a GRAD axis, which changes stroke weight without changing widths — that is literally what the axis is for.

OpenType features: font-variant-* before font-feature-settings

The same high-level/low-level split applies to OpenType features. font-feature-settings is the tag-based escape hatch with the same replace-don't-compose behavior; the font-variant-* family is the cascading, composable, self-documenting interface. The ones that earn their place in a base layer:

/* Data tables, timers, anything that must align vertically:
   every digit gets the same advance width. */
.stats td, .timer { font-variant-numeric: tabular-nums; }

/* Book-style prose: lowercase-height figures that sit in text */
.prose { font-variant-numeric: oldstyle-nums; }

/* Ligatures: common ones are on by default; discretionary opt-in */
.display { font-variant-ligatures: discretionary-ligatures; }
code     { font-variant-ligatures: none; }  /* != stays two glyphs */

/* Small caps — uses REAL small-cap glyphs when the font has them */
abbr { font-variant-caps: small-caps; }

The small-caps caveat is a classic root-cause item: if the font has no smcp feature, the browser synthesizes small caps by scaling down capitals — visibly too light, with mismatched stroke weight. font-synthesis: none (or the granular font-synthesis-small-caps: none) disables the fake and falls back to normal lowercase, which is usually the better failure mode. The same property suppresses faux-bold and faux-italic when a variable font's real axes should be doing the work.

font-size-adjust — fallback fonts that match

While your variable font loads, the fallback renders — and if its x-height ratio differs, the swap reflows the page (the layout-shift mechanics are Lesson 20.6's territory). font-size-adjust scales the fallback so its x-height matches a target ratio, and the modern from-font value reads that ratio straight from the first available font:

body {
  font-family: "Inter Var", system-ui, sans-serif;
  font-size-adjust: from-font;  /* fallbacks inherit Inter's x-height */
}

Pair this with the size-adjust, ascent-override, and descent-override descriptors in a fallback @font-face for near-zero-CLS font loading — the full recipe lives in Lesson 20.6, and the type tokens these settings hang off were defined in Lesson 4.5.

Color fonts: COLRv1 and font-palette

COLRv1 fonts carry vector color layers — gradients, compositing — inside the glyph data, which makes them tiny compared to bitmap-emoji formats and fully recolorable from CSS. The font ships one or more palettes; font-palette picks one, and @font-palette-values defines your own by starting from a base palette and overriding indexed entries:

@font-palette-values --brand {
  font-family: "Nabla";        /* must name the family it applies to */
  base-palette: 1;             /* start from the font's palette #1 */
  override-colors:
    0 oklch(70% 0.19 280),     /* recolor palette entry 0 */
    1 oklch(85% 0.10 200);
}

h1.fancy {
  font-family: "Nabla", sans-serif;
  font-palette: --brand;       /* also: normal | light | dark */
}

The light and dark keywords select palettes the font itself marks as scheme-appropriate — combine with Lesson 6.7's color-scheme work for color glyphs that follow the user's theme.

Support status and feature detection

Everything in this lesson is production: variable-font axes, font-optical-sizing, the font-variant-* family, and font-size-adjust are supported across all three engines; font-palette shipped in Chrome 101+, Firefox 107+, and Safari 15.4+. The one thing worth gating is the font file format you serve, and @supports grew dedicated functions for exactly this:

@supports font-tech(color-COLRv1) {
  h1.fancy { font-family: "Nabla", sans-serif; }
}
@supports not font-tech(color-COLRv1) {
  h1.fancy { color: oklch(70% 0.19 280); }  /* flat-color fallback */
}

/* Also available: format detection */
@supports font-format(woff2) { /* ... */ }

The same belt-and-braces logic exists at @font-face level: src entries with tech(color-COLRv1) are skipped by browsers that cannot render them, falling through to the next source. Use the src list for file selection and @supports font-tech() for styling differences.

Try it yourself

Mini-exercise

Upgrade a static-font project to variable. (1) Replace the multiple @font-face weight files with one variable file and a font-weight: 100 900 range descriptor, then delete every now-redundant rule. (2) Find one data table or timer and apply font-variant-numeric: tabular-nums — confirm the columns stop wobbling as values change. (3) Add font-synthesis: none to your base layer and check whether anything was secretly relying on faux-bold or synthesized small caps. (4) Add a hover transition on font-weight to your nav links and verify it interpolates smoothly — then check the layout-shift caveat by watching the adjacent links move, and decide whether a GRAD-axis font would serve better.
