Module 6 · Project

A Documentation Site's Base Layer

One base.css, zero classes. Prove it by rendering the same prose page in both light and dark mode and showing that the only thing your CSS references is tokens and element selectors.

The brief

  1. Assemble every rule from lessons 6.2 through 6.8 into a single base.css.
  2. Apply it to the documentation HTML below. No class selectors may appear in the file.
  3. Verify that the same HTML renders correctly in light mode, dark mode, LTR, and RTL — without any new CSS.

The complete base layer

@layer base {
  :root {
    color-scheme: light dark;

    --font-sans: system-ui, sans-serif;
    --font-mono: ui-monospace, monospace;
    --measure: 65ch;
    --radius-sm: .25rem;
    --radius-md: .5rem;

    --color-surface:       light-dark(oklch(99% 0.003 264), oklch(14% 0.02 264));
    --color-text-primary:  light-dark(oklch(18% 0.02 264), oklch(95% 0.01 264));
    --color-text-secondary:light-dark(oklch(38% 0.02 264), oklch(80% 0.01 264));
    --color-text-heading:  light-dark(oklch(12% 0.02 264), oklch(98% 0.01 264));
    --color-link:          light-dark(oklch(55% 0.22 275), oklch(72% 0.18 275));
    --color-link-hover:    light-dark(oklch(45% 0.22 275), oklch(80% 0.18 275));
    --color-focus:         light-dark(oklch(60% 0.22 275), oklch(75% 0.18 275));
    --color-code-bg:       light-dark(oklch(96% 0.01 264), oklch(22% 0.02 264));
    --color-border:        light-dark(oklch(88% 0.01 264), oklch(30% 0.02 264));
  }

  body {
    font-family: var(--font-sans);
    color: var(--color-text-primary);
    background: var(--color-surface);
    -webkit-font-smoothing: antialiased;
  }

  :where(h1, h2, h3, h4, h5, h6) {
    font-weight: 700;
    line-height: 1.15;
    color: var(--color-text-heading);
    text-wrap: balance;
  }
  h1 { font-size: 2.25rem; letter-spacing: -.02em; }
  h2 { font-size: 1.75rem; letter-spacing: -.015em; }
  h3 { font-size: 1.375rem; }

  p {
    max-inline-size: var(--measure);
    text-wrap: pretty;
    color: var(--color-text-secondary);
  }

  a {
    color: var(--color-link);
    text-decoration: underline;
    text-decoration-thickness: 1px;
    text-underline-offset: 3px;
  }
  a:hover { color: var(--color-link-hover); text-decoration-thickness: 2px; }

  code {
    font-family: var(--font-mono);
    font-size: .9em;
    background: var(--color-code-bg);
    border: 1px solid var(--color-border);
    border-radius: var(--radius-sm);
    padding-inline: .3em;
  }

  blockquote {
    border-inline-start: 3px solid var(--color-link);
    padding-inline-start: 1rem;
    font-style: italic;
    max-inline-size: var(--measure);
  }

  :focus-visible {
    outline: 2px solid var(--color-focus);
    outline-offset: 3px;
    border-radius: var(--radius-sm);
  }
  :focus:not(:focus-visible) { outline: none; }

  :where(p, li) { hyphens: auto; overflow-wrap: break-word; orphans: 3; widows: 3; }

  @supports (margin-trim: block) {
    :where(article, section, blockquote) { margin-trim: block; }
  }
}

Deliverable

  1. Your base.css — grep it for \. (a literal dot). Any match is a class selector that should not be there.
  2. Two screenshots of the same documentation HTML rendered in light and dark mode. Prove the only difference between them is the resolved tokens.
  3. One screenshot of the LTR version and one of the RTL version. Prove that no new CSS was required.
  4. A list of every @supports-gated feature in your base and a short note on what browsers fall back to.
