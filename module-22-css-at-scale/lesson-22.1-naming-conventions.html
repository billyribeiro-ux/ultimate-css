Lesson 22.1 · Enterprise Architecture

Naming Conventions: BEM, CUBE, PE7 Compared

Every naming convention is a contract between developers. BEM encodes structure in the name itself. CUBE embraces the cascade. PE7 replaces naming conventions entirely with architectural layers. Understanding all three helps you choose the right tool for your team.

BEM: Block, Element, Modifier

BEM encodes the component hierarchy directly in class names. A .card__title--featured tells you the block (card), the element (title), and the modifier (featured) at a glance. The contract: every class is self-documenting.

Strengths

Explicit relationships. Zero cascade dependency. Grep-friendly. Easy onboarding for new developers. Works without any build tool or modern CSS feature.

Weaknesses

Verbose HTML. No cascade awareness means duplication. Modifier explosion for complex states. The naming becomes the architecture rather than the architecture informing the naming.

CUBE CSS: Composition, Utility, Block, Exception

Andy Bell's CUBE CSS embraces the cascade instead of fighting it. Composition classes handle layout (.flow, .cluster). Utility classes handle single-purpose overrides. Block classes handle component-specific styling. Exceptions handle state with data attributes.

Strengths

Cascade-friendly. Less HTML markup. Leverages browser defaults. Encourages design tokens via utilities.

Weaknesses

Utility class proliferation. Less explicit than BEM for large teams. Requires cascade understanding that junior developers may lack.

PE7: Layers + @scope + Custom Properties

PE7 eliminates naming conventions as a concern. With @layer controlling specificity order, @scope controlling reach, and custom properties providing the API, the architecture itself prevents conflicts. You name things descriptively without encoding hierarchy.

Strengths

Zero naming convention overhead. Architecture replaces discipline. Cascade is controlled by the browser, not by developer agreement. Scales infinitely without naming collisions.

Weaknesses

Requires modern browser support. Steeper learning curve for the architecture itself. Less established community consensus.

When each is appropriate

BEM: Legacy codebases, teams with mixed CSS skill levels, projects requiring IE11 support. CUBE: Small-to-medium teams that understand the cascade, projects with a strong design token system. PE7: New projects targeting modern browsers, teams ready to invest in architectural understanding over naming discipline.
