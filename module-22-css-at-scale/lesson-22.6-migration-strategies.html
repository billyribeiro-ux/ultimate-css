Lesson 22.6 · Enterprise Architecture

Migrating Legacy CSS to @layer

You cannot rewrite 10,000 lines of CSS in a sprint. The incremental migration strategy wraps existing CSS in a compatibility layer, adds new CSS in proper layers, and refactors one component at a time. Six months, zero regressions.

The incremental approach

Step 1: Declare your layer order at the top of your entry point. Step 2: Wrap all existing CSS in a single @layer legacy. This changes nothing visually — unlayered CSS beats layered CSS, but since everything is now layered, the existing specificity relationships are preserved within that layer. Step 3: Write all new CSS in the appropriate PE7 layer. Step 4: Migrate one component at a time from legacy to the correct layer.

The @import layer() technique

Third-party CSS can be wrapped in a layer at import time: @import url("vendor.css") layer(vendor). This gives you architectural control over CSS you do not own. The vendor layer sits below your layers, so your overrides always win without !important.

Handling !important during migration

Legacy codebases often have !important scattered throughout. During migration, these become problematic because !important reverses layer order (lower layers win). The strategy: remove !important as you migrate each component. It is temporary — the goal is zero !important usage in the final architecture.

The test strategy: visual regression

Before migrating any component, capture screenshots of every state (default, hover, focus, active, disabled, error). After migration, compare screenshots pixel-by-pixel. Any visual difference is a regression that must be resolved before merging. Tools like Playwright's screenshot comparison make this automated.

A realistic 6-month migration plan

Month 1: Declare layers, wrap all existing CSS in @layer legacy, set up visual regression testing. Month 2-3: Extract tokens from hard-coded values, build the token layer. Month 4-5: Migrate components one at a time (highest-traffic pages first). Month 6: Remove the legacy layer, delete !important usage, audit for completeness.

Demo — Before/after wrapping legacy CSS in layers

Before (legacy)

/* styles.css - 10,000 lines */
.header { ... }
.header .nav { ... }
.header .nav a { ... }
.btn { ... }
.btn!important { color: red; }
.card { ... }
/* specificity wars everywhere */

After (step 1)

/* main.css - entry point */
@layer reset, tokens, base,
       layouts, components, utilities;

/* Wrap everything in legacy */
@import url("legacy.css")
  layer(legacy);

/* New code in proper layers */
@layer components {
  .new-card { ... }
}
Result: Zero visual changes. Legacy CSS is now contained. New CSS goes in proper layers. Migration can proceed component by component with no deadline pressure.

Try it yourself

Mini-exercise

Migrate the legacy .header styles into the proper layers: its colors become tokens, its layout rules move to a layouts layer. Delete the original from @layer legacy. The visual result should be identical — that is the test. Migration preserves appearance while improving architecture.
