Styling Web Components: ::part(), ::slotted() & :state()

Design systems increasingly ship as custom elements, and shadow DOM is the one boundary in the platform that @layer, @scope, and your token sheet do not cross by default. At scale, that boundary is either a deliberate API surface or a permanent source of "why won't this style apply" tickets. This lesson makes it the former.

The encapsulation model, precisely

Get the mechanics exact, because every pattern below follows from them. Styles defined inside a shadow root cannot leak out. Selectors written on the page cannot reach in — .page .card h2 stops dead at the shadow boundary regardless of specificity or layer. But two things pierce the boundary by design: inherited properties (color, font-family, line-height flow into the shadow tree like any inheritance) and custom properties (they inherit too — types and all). That second fact is the foundation of everything: your token system (Lesson 4.8) crosses the boundary for free, which makes custom properties the natural public styling API of a component — Lesson 22.4's component-API philosophy, extended across the shadow boundary.

/* Page (light DOM): set the contract */
pe-card { --card-surface: var(--color-surface-2); }

/* Inside the shadow root: consume with a documented default */
.surface { background: var(--card-surface, oklch(98% 0.01 270)); }

Inside the shadow: :host, :host(), ::slotted()

Shadow styles address their own element with :host, and conditionally with the functional form. Avoid :host-context() — Firefox resisted it for years on performance and encapsulation grounds; design components to receive context via custom properties instead of sniffing ancestors:

:host { display: inline-flex; }            /* custom elements default to inline! */
:host([variant="danger"]) { --_accent: var(--color-danger); }
:host(:focus-visible) { outline: 2px solid var(--_accent); }
/* :host-context(.dark) — avoid: never shipped in Firefox */

::slotted() styles light-DOM nodes projected through a <slot> — with a hard limit: it matches only the top-level assigned nodes, never their descendants. This is deliberate. Slot assignment is a flat list; allowing ::slotted(figure img) would reopen unbounded cross-boundary descendant matching — the exact invalidation cost and coupling that encapsulation exists to close off:

::slotted(img) { border-radius: var(--radius-2); }  /* works: assigned node  */
::slotted(figure img) { /* never matches */ }        /* descendants: off-limits */

Outside the shadow: ::part() is the contract

When a component author stamps part="name" on a shadow element, page CSS may style that element — and only that element — via ::part(name). You can attach pseudo-classes and pseudo-elements after it, but you cannot select through it (::part(label) span is invalid): parts expose nodes, not subtrees.

/* component template */
<button part="trigger">
  <span part="label"><slot></slot></span>
</button>

/* page CSS */
pe-button::part(trigger) { border-radius: var(--radius-2); }
pe-button::part(trigger):hover { filter: brightness(1.05); }

/* nested components re-export inner parts upward */
<pe-dialog>
  <pe-button exportparts="label: confirm-label">…</pe-button>
</pe-dialog>
pe-dialog::part(confirm-label) { font-weight: 700; }

Treat the part vocabulary as a public API, because it is one: document every part name, version the list, and never rename one in a minor release — consumers' CSS depends on it exactly as their JS depends on your method names. This is Lesson 22.2's token-governance discipline and Lesson 22.4's API-design discipline applied to selectors.

Custom states: ElementInternals and :state()

Production-ready (Chrome 125+, Firefox 126+, Safari 17.4+). Components used to reflect internal state as attributes purely so consumers could style it — a hack that pollutes the attribute namespace and invites consumers to write what should be read-only. Custom states fix this: the component adds a state via ElementInternals, and CSS matches it with :state():

class PeChip extends HTMLElement {
  #internals = this.attachInternals();
  set loading(on) {
    on ? this.#internals.states.add('loading')
       : this.#internals.states.delete('loading');
  }
}
/* page CSS — state is read-only, set only by the component */
pe-chip:state(loading) { opacity: 0.6; }
pe-chip:state(loading)::part(label) { visibility: hidden; }

One cascade caveat: a browser that lacks :state() drops any selector list containing it. While you support older browsers, keep a separate [data-loading] rule (set both from the component) rather than comma-joining the two.

Sharing stylesheets: adoptedStyleSheets and @layer inside shadows

A design system with 40 components must not parse its token sheet 40 times — or once per component instance. Constructable stylesheets parse once and are adopted by reference into any number of shadow roots: one copy in memory, guaranteed consistency, and updating the sheet updates every adopter:

const tokens = new CSSStyleSheet();
tokens.replaceSync(':host { --space-1: 0.25rem; --radius-2: 0.5rem; }');

class PeCard extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: 'open' });
    root.adoptedStyleSheets = [tokens, cardSheet]; // shared by reference
  }
}

Modern layout CSS works normally inside shadow trees: container queries, :has(), nesting — all of it. And @layer works per root: each shadow root has its own independent layer order, so your component can declare @layer reset, base, component; internally without ever colliding with the page's layer stack. Encapsulated cascade architecture, in miniature.

The decision framework: shadow DOM vs light DOM + @scope

Shadow DOM is not the default; it is a tool with a real cost. Lesson 8.2's @scope gives you style isolation without the boundary. The PE7 decision table:

SignalShadow DOMLight DOM + @scope
DistributionCross-team, cross-framework, third-party embedsOne codebase you control end to end
Styling contractExplicit and enforced: tokens + parts + statesConventional: full cascade available (and abusable)
ThemingCustom properties only — by designAnything, including consumer overrides
SSRDeclarative shadow DOM required; heavierPlain HTML; trivial
AccessibilityARIA ID references (aria-labelledby) cannot cross the boundary — plan composition carefullyNo boundary issues

The accessibility row is the one teams discover too late: an aria-labelledby inside a shadow root cannot point at an ID outside it (or vice versa). If a component's labeling must come from page content, slot the label in, or keep the component in the light DOM. When in doubt at scale: third-party surface area earns shadow DOM; internal components are usually better served by @scope and tokens.
