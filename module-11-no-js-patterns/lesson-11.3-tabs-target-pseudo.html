Lesson 11.3

Tabs: :target and URL Hash

:target is the oldest trick in no-JS CSS, and still the right answer when tabs are deep-linkable. It is an anchor tag plus a pseudo-class. The trade-off is real — this lesson explains it honestly.

The pattern

<nav>
  <a href="#overview">Overview</a>
  <a href="#usage">Usage</a>
  <a href="#api">API</a>
</nav>
<section id="overview" class="panel">…</section>
<section id="usage"    class="panel">…</section>
<section id="api"      class="panel">…</section>
.panel         { display: none; }
.panel:target  { display: block; }
.panel:first-of-type { display: block; } /* default tab */
.panel:first-of-type:not(:target) ~ .panel { display: none; }

:target matches the element whose ID equals the current URL fragment. Clicking an anchor updates the fragment, and the correct panel reveals. No JavaScript.

The honest trade-offs

  • URL history. Every tab click adds a history entry. Back-button behavior becomes "go to the previous tab", which is sometimes what you want and sometimes a bug. There is no way to switch this off in pure CSS.
  • One tab group per page. The URL has one hash. If you need two independent tab groups on the same page, :target cannot carry two states.
  • Scroll jumping. By default the browser scrolls to the targeted element. Fix with scroll-margin-block-start or prevent jumping by anchoring to a zero-height sibling.
  • Focus management. After a tab click, focus moves to the panel. That is correct for screen reader users but different from what JavaScript tab libraries do.

When NOT to use it

If the tabs control a deeply-nested piece of app state (a form step, a data view), use JavaScript. :target is for navigational tabs — sections of a document you might want to deep-link into. The question "would a user expect this tab to appear in the URL?" is the deciding factor.

Browser support

:target: baseline since CSS2.1. Universal. No @supports needed.
