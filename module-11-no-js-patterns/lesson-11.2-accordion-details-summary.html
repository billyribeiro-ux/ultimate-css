Lesson 11.2

Accordion: details/summary + @starting-style

The accordion is the perfect no-JS pattern because it has a built-in element for it. <details> handles the open/close state, keyboard handling, ARIA, and focus. Your job is the paint — and animating the transition smoothly, which is where @starting-style comes in.

The minimum version

<details>
  <summary>Question</summary>
  <p>Answer.</p>
</details>

This works already. Clicking or pressing Enter on the summary toggles open. Screen readers announce the state. No CSS required. No JavaScript required. The lesson is what you add on top.

Styling the summary

summary {
  list-style: none;       /* remove the default disclosure triangle */
  cursor: pointer;
  display: flex; justify-content: space-between;
}
summary::-webkit-details-marker { display: none; } /* Safari holdout */
summary::after {
  content: "";
  inline-size: .5rem; block-size: .5rem;
  border-inline-end: 2px solid currentColor;
  border-block-end: 2px solid currentColor;
  transform: rotate(-45deg);
  transition: transform 200ms;
}
details[open] summary::after { transform: rotate(45deg); }

Animating the panel

The panel's content uses interpolate-size: allow-keywords (Chrome 129+) so height: auto becomes animatable, plus @starting-style to define the enter-from state:

details[open] .panel {
  block-size: auto;
  opacity: 1;
  transition: block-size 300ms, opacity 300ms;
  interpolate-size: allow-keywords;
}
@starting-style {
  details[open] .panel { block-size: 0; opacity: 0; }
}

Browser support

<details>: baseline everywhere since 2020. @starting-style: Chrome 117+, Safari 17.5+, Firefox 129+. interpolate-size: allow-keywords: Chrome 129+ only in early 2026 — Firefox and Safari will follow. Always provide the non-animated fallback; the accordion still works without smooth height animation.

Mini-exercise
