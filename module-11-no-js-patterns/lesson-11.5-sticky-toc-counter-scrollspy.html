Lesson 11.5

Progressive enhancement

Sticky TOC + Counters + Scrollspy

The sidebar table of contents with auto-numbering and active-section highlighting is the single most common "I need a library for this" request. It is three CSS primitives stacked: position: sticky, CSS counters, and :target-current.

Layer one: sticky positioning (universal)

.toc {
  position: sticky;
  inset-block-start: var(--space-lg);
  align-self: start;
}

Baseline everywhere. The sidebar stays in view as the reader scrolls, anchored to the top of the viewport with a little breathing room. align-self: start is critical in a grid layout — without it, the sticky element stretches to fill the row and never actually sticks.

Layer two: counters (universal)

.toc ol { counter-reset: toc; list-style: none; }
.toc li { counter-increment: toc; }
.toc a::before { content: counter(toc) ". "; color: var(--color-primary); }

Auto-numbering everywhere, including nested lists via counters(toc, "."). Works in every browser since 2005.

Layer three: :target-current (progressive)

.toc { scroll-target-group: auto; }
.toc a:target-current { color: var(--color-primary); font-weight: 700; }

The browser tracks which section you are reading and applies :target-current to the matching anchor automatically. No scroll listener. No IntersectionObserver. No "which section is at 40% viewport height" math.

Why three layers?

Universal baseline + progressive enhancement is the PE7 mindset applied to this pattern. Sticky and counters work everywhere — a reader on an old browser gets a numbered sidebar that stays visible. Only the "active" highlight is gated on modern browsers. Nothing is broken; one affordance is added.

Browser support

position: sticky: baseline. CSS counters: baseline. scroll-target-group + :target-current: Chrome 140+, Edge 140+. Wrap the progressive layer in @supports selector(:target-current).
