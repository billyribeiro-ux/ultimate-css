Lesson 2.2

Declaring Layer Order

The single line that defines your entire architecture. Once you write it, where the rules physically live in the file stops mattering — the declaration freezes the priority order.

The declaration form

A bare @layer statement with a list of names — and nothing else — declares the layers and their priority order, from lowest to highest:

@layer reset, tokens, base, layout, components, animations;

Read that line out loud: "reset is the lowest priority layer, animations is the highest, and everything in between is stacked in the order written." That order is now locked for the rest of the document. It does not matter where you populate each layer or how late in the file you do it.

Last-wins

The rule is dead simple: the layer named last in the declaration has the highest priority. First in the list is weakest. If you want animations to override components, put it after components. That is the entire API.

Physical position is irrelevant — once declared

Before the declaration line exists, CSS falls back to "layers are ordered by first appearance." That means a layer referenced lower in the file beats one referenced higher. That is fragile — add one import and your cascade flips.

The fix is to always put the bare declaration at the top of your entry stylesheet. Once declared, you can populate layers in any order, in any file, loaded at any time, and the priority stays fixed. This is what makes @layer scale.

Best practice

Declare all your layers on line 1 of your root stylesheet, even the ones you are not using yet. It costs nothing. It prevents every "why did adding a file break my cascade" bug.
