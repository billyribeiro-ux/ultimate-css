Lesson 2.1

What @layer Actually Is

Before syntax, the model. @layer is a new step in the cascade that sits above specificity. Once you grasp that single sentence, every confusing part of CSS architecture becomes obvious.

Why it exists

In Module 1 you saw rules fight each other. Third-party libraries clashed with author styles. Specificity arms races erupted. !important chains formed. None of that came from bad engineers — it came from the cascade offering exactly one lever (specificity) to express an intent that actually has two dimensions: how specific is the selector and what kind of rule is this.

@layer gives you the second dimension. It lets you declare, explicitly, that one bucket of rules should always beat another bucket — regardless of how the selectors inside each bucket are written.

The one-sentence definition

A layer is a named priority bucket in the cascade. Every rule inside a higher-priority layer beats every rule inside a lower-priority layer, no matter the specificity of either one.

Where it sits in the cascade

Recall the four-step cascade from Lesson 1.1. Layer priority is step 2 — it runs after origin-and-importance, but before specificity. That ordering is the whole point. Specificity only ever decides things inside a single layer. Across layers, specificity is irrelevant.

  1. Origin & importance
  2. Layer priority ← this is what @layer controls
  3. Specificity
  4. Source order

The mental model: shelves, not piles

Without layers, your stylesheet is a single pile of rules. The only way to sort them is specificity. With layers, you get labelled shelves stacked on top of each other. A feather on a high shelf is higher than a brick on a low shelf. A class in a high layer wins against an ID in a low layer.

This is the single most important sentence in the course. Re-read it. Everything from Module 3 onward is built on it.

Live demo — a layer beats an ID

A class in a high layer beats an ID in a low layer

The ID rule scores 1,0,0. The class rule scores 0,1,0. Without layers, the ID wins. With layers — and with high declared after low — the class wins. You should see indigo.

Mini-exercise

In the editor above, remove the @layer low, high; declaration line entirely, then run. The two layers still exist — but their order is now determined by the order they were first seen. Does the class still win? Why or why not? Write down your prediction before running.
