Lesson 2.3

Populating Layers

Declaration is half the story. Now you put rules inside. There are three ways to populate a layer, and one of them is the technique that makes cross-file architecture actually work.

Form 1 — block syntax

The most common form. Name the layer, open a block, write rules inside:

@layer reset {
  *, *::before, *::after { box-sizing: border-box; }
  body { margin: 0; }
}

Every rule between the braces belongs to that layer. If the layer has not been declared yet, this statement both creates and populates it.

Form 2 — reopening a layer

You can write @layer reset { ... } as many times as you want, in as many files as you want. All of those blocks merge into the same layer. This is how you split a layer across files without losing its priority:

/* reset.css */
@layer reset { html { line-height: 1.5; } }

/* typography.css */
@layer reset { h1, h2, h3 { margin-block: 0; } }

Both blocks contribute to reset. The layer is still one bucket — reopening never creates a new one.

Form 3 — nested inside @media

@layer blocks nest cleanly inside conditional rules. The priority stays the same; only the applicability is conditional.

@media (min-width: 48rem) {
  @layer layout {
    .grid { grid-template-columns: repeat(12, 1fr); }
  }
}

Unlayered vs layered

Any rule you write outside of an @layer block is "unlayered." Unlayered rules have a special status — they beat every layered rule, no matter how highly prioritised. That is not a bug; it is the escape hatch, covered in Lesson 2.5.

For now, the rule: if it is inside a layer block, it is layered. If it is not, it is unlayered and will win. Be deliberate about which you choose.
