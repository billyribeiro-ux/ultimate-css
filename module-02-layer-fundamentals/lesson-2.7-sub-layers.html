Lesson 2.7

Sub-layers

Six top-level layers is rarely enough for a large component layer. Sub-layers let you stack priorities within a single layer, using dot notation, without polluting your top-level declaration.

The problem

Your components layer grows. You end up with base button styles, button variants (primary, secondary, danger), and button states (hover, disabled, loading). All three groups live in components, but they have a natural priority: states should override variants, variants should override base. How do you express that without adding states, variants, and component-base to your top-level layer list?

The answer: dot notation

You can declare layers with a parent name:

@layer components.base, components.variants, components.states;

This creates three sub-layers inside components. They behave like any other layer: last declared wins. But from outside, they are still part of components — nothing above or below components sees the sub-structure.

Populating sub-layers

@layer components.base {
  .btn { padding: .5rem 1rem; border-radius: .375rem; border: 0; }
}

@layer components.variants {
  .btn.primary { background: oklch(58% 0.22 275); color: #fff; }
  .btn.danger  { background: oklch(60% 0.22 25);  color: #fff; }
}

@layer components.states {
  .btn:hover    { filter: brightness(1.1); }
  .btn:disabled { opacity: .5; pointer-events: none; }
}

Nested block form

You can also nest @layer blocks to get the same effect:

@layer components {
  @layer base     { /* ... */ }
  @layer variants { /* ... */ }
  @layer states   { /* ... */ }
}

Both forms produce identical sub-layers. Pick whichever reads better in context.

The encapsulation rule

Sub-layers are isolated from the outside. A rule in components.states beats a rule in components.variants, but from layout's perspective both are just "inside components." No other layer can reach in and reorder components's internals. That encapsulation is what makes sub-layers safe for component library authors.
