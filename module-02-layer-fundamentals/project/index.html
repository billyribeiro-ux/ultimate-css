Module 2 · Project

Refactor the Disaster

Same broken stylesheet from Module 1. Same selectors — every single one kept intact. The only thing that changes is that every rule now lives inside a named @layer. The cascade reorganises itself and the disaster disappears.

The brief

You are not allowed to change any selector. You are not allowed to add or remove !important. You cannot reorder rules inside the file. The only tool is @layer. By the end, the page renders correctly: brand indigo primary, brand red danger, brand green hero title, slate header button, consistent sidebar background.

The declared layer order

@layer vendor, components, overrides;

Three layers are enough for this project. vendor holds the third-party library. components holds the author styles. overrides holds the context-specific rules (the hero title coloring). Later layers beat earlier layers, so author components beat vendor automatically, and overrides beat both.

What moved where

  • vendor — the .ui-card base, .ui-btn base, and the offending #site-header .ui-btn !important. All of it is now sealed inside the vendor layer.
  • components — the author .btn, .btn.primary, .btn.danger, .card, .card-title, and the later author rules that were clobbering them. Because the later rules live in the same layer, source order still decides between them — so we keep only the intended values.
  • overrides — the #hero .card-title rule that wants to colour the hero title green. This layer sits above components, so even its lower-specificity form wins against the red .card-title !important below.

Why this works — every outcome mapped

  1. Primary button is indigo. Both .btn rules live in components; source order inside the layer still applies, but all are intentionally set to indigo. The earlier "accidental amber override" is simply removed from the authored code, not fought with specificity.
  2. Hero title is green. #hero .card-title lives in the overrides layer — higher than components. The red !important sits in components and loses. A lower-specificity rule in a higher layer beats an !important in a lower layer. This is the sentence.
  3. Header UI button is slate. The vendor's #site-header .ui-btn !important stays inside the vendor layer. Author .btn rules in components beat it without having to match its specificity or escalate to another !important.
  4. Sidebar card background is consistent. Duplicates are gone; the single .card rule lives in components and wins against any vendor background.
  5. No specificity arms race. Doubled-class tricks are unnecessary — the layer system made them obsolete.
  6. No !important chain in author code. The only !important left is the one we imported from vendor, and it is contained.
