Lesson 2.6

@layer with @import

The feature that finally makes third-party CSS safe. You can drop an entire vendor stylesheet into a named layer in a single line, without editing the file or hoping its authors were polite with specificity.

The syntax

Append layer(name) to any @import statement. Every rule in the imported file joins that layer:

@import url("normalize.css") layer(reset);
@import url("bootstrap.css") layer(vendor);
@import url("./components.css") layer(components);

The file you are importing does not need to know about layers. It can be a ten-year-old vendor stylesheet full of IDs and !important. Wrap it in a layer at import time and it becomes a well-behaved citizen of your cascade.

Why this is the killer feature

Before layers, the only way to neutralise a misbehaving third-party stylesheet was to match or exceed its specificity, usually with your own !important. That started specificity wars that destroyed codebases. Now, you assign the library to a low layer and forget about it. Your author components in a higher layer always win.

The strict rule about placement

@import statements — layered or not — must appear at the top of the stylesheet, before any other rule except @charset and @layer declarations. Put an @import after a regular rule and browsers silently drop it. This bites people. Watch for it.

The recommended pattern

Declare your full layer order first. Then list your imports, each assigned to its layer. Then populate the remaining layers inline. Your root stylesheet looks like this:

/* 1. Declare order */
@layer reset, tokens, base, layout, components, animations;

/* 2. Assign imports to layers */
@import url("modern-normalize.css") layer(reset);
@import url("./tokens.css")         layer(tokens);
@import url("./base.css")           layer(base);

/* 3. Inline rules continue below */
@layer components { /* ... */ }

That is the entire contract. The order at the top is law. Everything after is plumbing.

Anonymous import layers

You can also write @import url(...) layer; with no name. That creates a single-use anonymous layer for that file. Useful for genuinely throwaway imports, but avoid it in architecture — named layers are always easier to reason about.

Live demo — conceptual layout

/* Root stylesheet — real-world skeleton */
@layer reset, tokens, base, layout, components, animations;

@import url("normalize.css")        layer(reset);
@import url("./tokens.css")          layer(tokens);
@import url("./base.css")            layer(base);
@import url("./components.css")      layer(components);

/* Everything declared at the top wins over imports above. */

Try it yourself

Mini-exercise

The vendor rule in the editor above uses body #root .btn !important — specificity 1,2,1 plus importance. Your components rule is .btn — 0,1,0, no importance. Under the classic cascade, yours could never win. Under layers, it wins trivially. Delete the @layer components block wrapper and watch what happens without layers. Re-wrap it. Explain the before/after in one sentence.
