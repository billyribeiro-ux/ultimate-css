Lesson 9.10

animation-composition, Individual Transforms & Discrete Transitions

Three modern mechanics that each delete an entire class of animation bugs: individual translate/rotate/scale properties end the "one transform property, many hands" fight; animation-composition lets simultaneous animations layer instead of clobber; and transition-behavior: allow-discrete finally makes exit animations work on display. All three are production-ready.

The single-property problem

transform is one property holding a list of functions. The cascade and the animation model both resolve a property to exactly one value — so whenever two sources write transform, one of them silently wins and the other is obliterated. The two classic crime scenes:

/* Crime scene 1: hover obliterates centering */
.tooltip { transform: translate(-50%, -50%); }   /* centered  */
.tooltip:hover { transform: scale(1.05); }       /* …and now it
   jumps to the corner: the translate is GONE, not combined */

/* Crime scene 2: a running animation swallows hover */
.card { animation: bob 2s ease-in-out infinite; }
@keyframes bob { 50% { transform: translateY(-8px); } }
.card:hover { transform: scale(1.05); }
/* Nothing happens on hover: running animations sit above
   normal author declarations, so the keyframe value wins. */

Root cause in both: there is no "merge" step for a single property. The fix is not cleverer selectors — it is to stop forcing four geometric channels through one property.

Individual transform properties: translate, rotate, scale

Production since 2022 (Chrome 104+, Firefox 72+, Safari 14.1+): translate, rotate, and scale are standalone properties. Each one cascades, transitions, and animates independently — a keyframe on translate and a hover on scale never touch each other.

.card {
  translate: 0 0;
  scale: 1;
  animation: bob 2s ease-in-out infinite;  /* owns translate */
  transition: scale 200ms ease-out;        /* owns scale     */
}
@keyframes bob { 50% { translate: 0 -8px; } }
.card:hover { scale: 1.05; }   /* composes with the bob — no fight */

/* transform-origin still applies to rotate and scale,
   exactly as it does inside transform */

Order of operations: fixed, and that's the trade

Inside transform, you choose the function order, and order matters: rotate(45deg) translateX(100px) moves along the rotated axis; translateX(100px) rotate(45deg) moves, then spins in place. The individual properties apply in a fixed order — translate, then rotate, then scale (and any transform list applies after them). That fixed order is what makes independent animation possible, and it covers the overwhelming majority of UI motion. The moment you need rotate-then-translate (orbiting around an external point), fall back to transform — or better, use a motion path (Lesson 9.9).

animation-composition: replace, add, accumulate

Individual properties solve different channels. animation-composition solves the same channel: two simultaneous animations targeting the same property. The default, replace, means the last animation in the list wins outright. add and accumulate make the effect value compose with the underlying value instead:

.buoy {
  /* an infinite bob plus a slower drift, both on translate */
  animation:
    drift 4s   ease-in-out infinite alternate,
    bob   1.2s ease-in-out infinite alternate;
  animation-composition: accumulate;  /* layer, don't clobber */
}
@keyframes drift { to { translate: 80px 0; } }
@keyframes bob   { to { translate: 0 -14px; } }
/* replace    → only bob runs (last in list wins)
   accumulate → the bob rides on top of the drift */

add vs. accumulate, precisely

The difference only appears on multiplicative channels. Given an underlying scale: 2 and an animation effect of scale: 1.5:

animation-composition: replace;    /* result: 1.5 — underlying discarded */
animation-composition: add;        /* result: 3   — effect appended to the
                                      transform list: 2 × 1.5            */
animation-composition: accumulate; /* result: 2.5 — components combine,
                                      one shared identity removed:
                                      2 + (1.5 − 1)                      */

/* For translate the two coincide: underlying 10px + effect 20px
   → 30px under add AND accumulate. Translations are additive;
   scales are multiplicative under add, additive-minus-identity
   under accumulate. */

Rule of thumb: add behaves like "do this after the underlying motion" (matrix concatenation); accumulate behaves like "blend the dials together" — and is usually what layered organic motion wants.

transition-behavior: allow-discrete

Discrete properties — display, overlay, content-visibility — have no midpoint to interpolate, so transitions historically ignored them. The fatal consequence: setting display: none removes the element instantly, killing any exit animation mid-flight. transition-behavior: allow-discrete opts a discrete property into the transition with precise flip timing: transitioning away from display: none, the value flips at 0% (visible for the whole entrance); transitioning to none, it flips at 100% (visible for the whole exit). Other discrete pairs flip at 50%. overlay gets the same treatment so popovers stay in the top layer while leaving.

The full enter/exit pattern

Combine allow-discrete with @starting-style (Lesson 9.2) and one block of CSS handles both directions for a popover — no JavaScript classes, no setTimeout before removal:

[popover] {
  /* EXIT target state + the transition itself */
  opacity: 0;
  translate: 0 8px;
  transition:
    opacity 200ms ease-out,
    translate 200ms ease-out,
    display 200ms allow-discrete,
    overlay 200ms allow-discrete;
}
[popover]:popover-open {
  opacity: 1;
  translate: 0 0;
}
/* ENTER starting point: where the open state animates FROM */
@starting-style {
  [popover]:popover-open {
    opacity: 0;
    translate: 0 8px;
  }
}

Read it as a state machine: @starting-style supplies the before-first-frame value for the entrance; the base [popover] block is both the exit destination and the place the element eases back to; allow-discrete on display/overlay keeps the element rendered (and in the top layer) until the exit finishes.

Support and reduced motion

All production: individual transforms since Chrome 104+/Firefox 72+/Safari 14.1+; animation-composition since Chrome 112+/Firefox 115+/Safari 16+; transition-behavior with @starting-style since Chrome 117+/Firefox 129+/Safari 17.4+. As always (Lesson 9.1), every layered or looping motion ships with a reduced-motion override — composition makes motion richer, which makes the override more important, not less:

@media (prefers-reduced-motion: reduce) {
  .buoy, .card { animation: none; translate: none; scale: none; }
  [popover] { transition-duration: 1ms; }  /* keep state changes, drop motion */
}

Mini-exercise

Take the composing card further. (1) Add a second animation to .compose — a slow horizontal drift on translate — and watch the default replace composition kill the bob; fix it with animation-composition: accumulate. (2) Add a rotate hover on top and confirm three channels (keyframed translate, hover scale, hover rotate) all compose with zero conflicts. (3) Rebuild the popover enter/exit pattern from this lesson: a "card" that fades and slides in via @starting-style and out via display 200ms allow-discrete, then verify the exit is visible — delete allow-discrete and watch the element vanish instantly instead. (4) Keep the reduced-motion block honest: it must neutralize every channel you added.
