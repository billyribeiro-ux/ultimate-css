Lesson 9.1

Why Animations Own Their Layer

Motion is the one concern every component has and the one every accessibility setting can strip away. Giving it the highest cascade layer is not a style preference — it is the only architecture that survives contact with prefers-reduced-motion.

The three reasons

  1. Single source of motion. Every transition and keyframe on the site is defined in one place. When a designer asks "can we slow everything down by 20%?", you change one duration token.
  2. Highest cascade priority. The animations layer comes last in @layer reset, tokens, base, layout, components, animations. That means animation properties win any cascade conflict. A component can declare a transition for its buttons; the animations layer can still override it globally without a specificity war.
  3. One-line accessibility override. Because all motion lives here, a single @media (prefers-reduced-motion: reduce) rule inside the layer can strip every animation and transition at once.

The reduced-motion override

@layer animations {
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration:   0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration:  0.01ms !important;
      scroll-behavior:      auto   !important;
    }
  }
}

The !important here is intentional and correct. It is the one place in the entire PE7 architecture where !important is not a smell — because this rule must beat any future animation that gets added, and it must do so without the rule writer needing to remember.

What goes in the layer

  • @keyframes definitions.
  • transition declarations on component states (:hover, [aria-expanded]).
  • animation assignments.
  • Scroll-driven timelines and scroll-state container queries.
  • View transition pseudo-element rules.

What does not go here

Duration, easing, and distance values belong in the tokens layer as --dur-fast, --ease-out, etc. The animations layer consumes those tokens; it does not invent new ones. This keeps the "design vocabulary" and the "motion mechanics" properly separated.

Live demo — reduced-motion override in action

Turn on "Reduce motion" in your OS and reload. The pulse stops. One rule turned off every animation on the page.

Try it yourself

Mini-exercise

Enable "Reduce motion" in your OS accessibility settings (System Settings on macOS; Ease of Access on Windows). Reload the editor above. Confirm the spinning box and the button hover both stop. Then turn it back off and watch them resume. This is the entire "respect user preferences" contract — one rule, one place.
