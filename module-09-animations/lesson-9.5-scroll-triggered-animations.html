Lesson 9.5

Progressive enhancement

Scroll-Triggered Animations

Scroll-driven animations are scrubbed by scroll position. Scroll-triggered animations play their own duration the moment scroll enters a range. This distinction used to require a JavaScript library; it is now a pair of CSS declarations.

The difference, precisely

  • Driven (Lesson 9.3): animation progress equals scroll progress. Scroll backwards, animation runs backwards.
  • Triggered: scroll position is used only to start the animation. Once fired, the animation runs on its own clock.

Both are useful; they answer different design questions. A reading progress bar must be driven. A one-shot fade-in "as the user scrolls into this section" is triggered — you don't want it scrubbing backwards when the user scrolls up.

The syntax

@scroll-timeline --reveal {
  source: selector("#scroller");
  scroll-offsets: 0%, 100%;
}

.hero-title {
  animation: fade-up 800ms ease-out both;
  animation-trigger: --reveal play-forwards;
}

Declare a named timeline, then bind an animation to it via animation-trigger. The modes are play-forwards (fire once), play (fire every entry), and alternate (play forward on entry, reverse on exit).

Browser support

Chrome 145+ only as of early 2026. Very new. Always wrap in @supports (animation-trigger: foo). Recommended fallback: use a scroll-driven view() animation with a small range, which achieves nearly the same effect in many more browsers. This lesson teaches the direction of the spec — do not ship triggered animations as the only path yet.

Mini-exercise

Change play-forwards to alternate. Scroll up and down through the trigger range. The animation now plays forward on entry and reverses on exit. Decide which pattern your real design calls for — and note how the change is a single keyword.
