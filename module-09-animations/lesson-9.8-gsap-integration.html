Lesson 9.8

GSAP Integration: Division of Labor

GSAP is an excellent library. It is also the wrong answer for at least half the problems it is still used to solve. This lesson draws the line — precisely — between what CSS should now own and what GSAP still does better than anything else.

What CSS now owns

Every item on this list used to be a reason to reach for GSAP. None of them are anymore.

  • State transitions. :hover, [aria-expanded], :checked — all native CSS transitions.
  • Enter animations. @starting-style.
  • Scroll reveals. animation-timeline: view().
  • Scroll progress bars. animation-timeline: scroll().
  • Sticky-stuck detection. @container scroll-state(stuck: top).
  • Layout morphs. View Transitions API.
  • Staggered list animations. sibling-index().

What GSAP still does better

  1. Complex timelines with tight synchronization. A hero sequence with ten overlapping beats, each with its own easing, interrupt-recoverable. CSS can do it, but GSAP's timeline API is still the best tool for the job.
  2. Pinned scrolling with forward/backward cleanup — ScrollTrigger's pin: true with onLeaveBack is still uniquely expressive.
  3. Physics and dynamic values. Draggable, InertiaPlugin — GSAP has no CSS equivalent for momentum-based motion.
  4. SVG path morphing. MorphSVG is genuinely unique.

The division-of-labor rule

If the animation is triggered by state, use CSS. If it is choreographed over time, use GSAP.

That is the entire heuristic. State-driven motion belongs in CSS because state already lives there. Time-driven motion belongs in JS because JS is the language of time.

gsap.matchMedia() for reduced motion

If you do use GSAP, wrap every timeline in gsap.matchMedia() with the reduced-motion query so the library respects the same accessibility contract as the CSS layer:

const mm = gsap.matchMedia();
mm.add("(prefers-reduced-motion: no-preference)", () => {
  gsap.timeline().from(".hero", { y: 40, opacity: 0 }).to(".hero", { scale: 1.05 });
});

Without this wrap, GSAP will animate regardless of user settings — and you will fail an accessibility audit.

Mini-exercise

Audit one page in your current project that uses GSAP. For each GSAP call, ask: "is this state-triggered or time-choreographed?" Move every state-triggered animation into CSS. Measure the resulting bundle-size reduction. You will usually find 60 to 90 percent of GSAP usage was a state transition in disguise.
