Lesson 9.4

Progressive enhancement

Scroll-State Container Queries

Detecting when a sticky element is "stuck" used to require a scroll listener plus bounding rect math. Detecting when a scroll-snap item is snapped required IntersectionObserver with root margins. Scroll-state container queries let the CSS engine answer both questions directly.

A new container type

.sticky-header {
  container-type: scroll-state;
  position: sticky;
  inset-block-start: 0;
}

@container scroll-state(stuck: top) {
  .sticky-header { box-shadow: 0 4px 14px oklch(0% 0 0 / .08); }
}

container-type: scroll-state turns the element into a container that exposes scroll-state conditions to descendants. stuck: top is true when the element is currently sticky-stuck to the top edge of its scroll container.

Snap detection

.carousel-item { container-type: scroll-state; }
@container scroll-state(snapped: x) {
  .carousel-item .caption { opacity: 1; transform: translateY(0); }
}

snapped: x is true when the item is the currently-snapped child on the x axis. Pair with a transition and the caption of the active slide fades in automatically as you scroll.

Why this matters

Two of the most common "I need JavaScript for this" UI patterns are now declarative: "raise the sticky header when it detaches from its section" and "highlight the active snap point". Both become two lines of CSS, both run off-main-thread, both respect reduced-motion by default.

Browser support

Chrome 133+, Edge 133+. Safari and Firefox not yet. Always wrap in @supports (container-type: scroll-state). The fallback is the non-stateful version of the component — it still works, just without the stateful styling.
