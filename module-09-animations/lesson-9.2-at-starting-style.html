Lesson 9.2

@starting-style: Enter Animations Without JavaScript

CSS transitions only run between two values — and an element that did not exist a moment ago has no "before" value. @starting-style fixes that. It is how you finally animate elements as they appear, without waiting for a framework's mount hook.

The old problem

Before @starting-style, animating something into the page required one of three ugly workarounds: a @keyframes animation that runs once; a JavaScript "add a class on next tick" dance; or a transition that fires only after a manual requestAnimationFrame. All three are symptoms of a missing primitive.

The primitive

.dialog {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 300ms, transform 300ms;
}
@starting-style {
  .dialog {
    opacity: 0;
    transform: translateY(1rem);
  }
}

The rules inside @starting-style are the element's "before" state. The browser applies them once when the element first becomes eligible for style — then immediately transitions to the regular values. The result is a proper enter animation with zero JavaScript.

With popover and dialog

@starting-style composes perfectly with the popover attribute and <dialog>. The only additional requirement for elements that toggle display: none is transition-behavior: allow-discrete, which lets the browser animate the discrete display property:

[popover] {
  opacity: 1;
  transition: opacity 300ms, display 300ms allow-discrete;
}
[popover]:not(:popover-open) { opacity: 0; }
@starting-style {
  [popover]:popover-open { opacity: 0; }
}

Browser support

Chrome 117+, Safari 17.5+, Firefox 129+. Production-ready in 2026. No @supports needed for the core feature, though it is polite to provide a fallback where the element simply appears without an enter animation in older browsers.
