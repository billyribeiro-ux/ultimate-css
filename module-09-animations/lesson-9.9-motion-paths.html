Lesson 9.9

Motion Paths: offset-path, ray() & Orbital Animation

Keyframes that animate translate can only draw straight lines between stops — a real curve takes a pile of keyframes that approximate it badly. The Motion Path module gives an element an actual track to ride: offset-path defines the geometry, offset-distance animates the position along it, and offset-rotate keeps the element facing where it is going.

Why translate can't turn

Interpolation between two keyframes is linear in value space. Animate translate from 0 0 to 100px 0 to 100px 100px and you get an L-shape with a hard corner — not an arc. To fake a quarter-circle you need dozens of keyframes sampling the curve, and the easing between each pair still flattens it.

/* The L-shape problem: three keyframes, two straight lines */
@keyframes corner {
  0%   { translate: 0 0; }
  50%  { translate: 100px 0; }    /* straight east  */
  100% { translate: 100px 100px; } /* hard 90° turn, straight south */
}

SVG solved this in 2001 with SMIL's <animateMotion>, and for two decades web apps reached for JavaScript — GSAP's MotionPathPlugin chief among them (Lesson 9.8) — just to fly a toast along a curve. The platform answer is the Motion Path module: the browser resolves the geometry once and interpolates along the path, not between points.

The offset model: a track and a position

Four longhands (plus the offset shorthand) define the model. The entire animation pattern is: set the track once, then animate offset-distance from 0% to 100%.

.satellite {
  offset-path: circle(120px);   /* the track geometry            */
  offset-distance: 0%;          /* position along the track      */
  offset-rotate: auto;          /* face the direction of travel  */
  offset-anchor: auto;          /* which point of the box rides
                                   the path (default: center)    */
  animation: travel 8s linear infinite;
}
@keyframes travel { to { offset-distance: 100%; } }

/* offset-rotate options, precisely:
   auto        → rotate to match the path's tangent
   auto 90deg  → tangent plus a constant offset
   0deg        → fixed angle: element stays upright
   reverse     → tangent + 180° (travel "backwards")           */

Note what offset-rotate: auto buys you for free: banking into turns. A JS implementation has to differentiate the path to compute the tangent per frame; CSS does it natively. For UI elements that must stay readable (a toast, a card), pin it with offset-rotate: 0deg.

Path sources: path(), basic shapes, shape() and ray()

offset-path accepts several geometry sources, and choosing the right one is mostly a question of how the coordinates resolve:

/* 1. path() — an SVG path string. CAVEAT: coordinates are raw
   px frozen in the containing block's coordinate space. The
   curve does NOT scale with the container. Design it for a
   known stage size, or generate it per breakpoint. */
offset-path: path("M 0,0 C 50,-80 150,-80 200,0");

/* 2. Basic shapes — percentage-friendly, fully responsive */
offset-path: circle(40%);             /* ring inside the box   */
offset-path: inset(10% round 1rem);   /* rounded-rect circuit  */

/* 3. shape() — curves with responsive units; the modern fix
   for path()'s fixed coordinate space (ahead in Lesson 13.23) */
offset-path: shape(from 0% 100%, curve to 100% 100% with 50% 0%);

/* 4. ray() — polar coordinates from a center point */
offset-path: ray(45deg closest-side);

ray(): polar positioning

ray() turns the offset model into a polar coordinate system. The ray starts at the point given by offset-position (default: the center of the containing block) and shoots outward at the given angle; offset-distance becomes the radius. Place N items at N angles and you have a radial layout with zero trigonometry — Lesson 10.7 computes the same geometry explicitly with cos()/sin() when you need the x/y values for other purposes.

.spoke {
  offset-position: 50% 50%;                        /* the hub   */
  offset-path: ray(calc(var(--i) * 60deg) closest-side);
  offset-distance: 80%;                            /* the radius */
  offset-rotate: 0deg;                             /* stay upright */
}

The orbital pattern

Put N items on the same circular track and either distribute them statically with per-item offset-distance, or give them all the same revolve animation staggered by negative delays. The negative delay starts each item mid-cycle — they hold formation forever because they share one clock.

.orbit { position: relative; inline-size: 240px; aspect-ratio: 1; }
.orbit .item {
  position: absolute;
  offset-path: circle(40%);
  /* static placement: distribute by index */
  offset-distance: calc(100% / var(--count) * var(--i));
}

/* live orbit: one animation, staggered into formation */
.orbit .item {
  animation: revolve 12s linear infinite;
  animation-delay: calc(var(--i) * (12s / var(--count)) * -1);
}
@keyframes revolve { to { offset-distance: 100%; } }

/* --i can come from sibling-index() where supported (Lesson 9.6),
   with a per-item custom property as the universal fallback */
@supports (animation-delay: calc(sibling-index() * 1ms)) {
  .orbit .item { --i: calc(sibling-index() - 1); }
}

A curved fly-in entrance

The same model handles one-shot choreography. A toast that arcs in from off-screen is a path() plus a single offset-distance animation — pair it with opacity and you have motion no translate keyframe can produce:

.toast {
  offset-path: path("M 240,-40 C 160,-40 60,20 0,0");
  offset-rotate: 0deg;          /* keep the text upright */
  animation: fly-in 600ms cubic-bezier(.2, .7, .2, 1) both;
}
@keyframes fly-in {
  from { offset-distance: 0%;   opacity: 0; }
  to   { offset-distance: 100%; opacity: 1; }
}

Performance: offset rides the compositor

The offset-* properties are composited exactly like transform and opacity (Lesson 20.2). The path geometry is resolved once; each frame is just a new transform matrix computed on the compositor thread — no layout, no paint, immune to main-thread jank. The rule that follows: animate offset-distance, never offset-path itself. Changing the geometry mid-flight forces re-resolution and is not what the model is optimized for.

Reduced motion is non-negotiable

Orbits and curved fly-ins are precisely the large-translation, sustained motion that triggers vestibular disorders — the contract from Lesson 9.1 applies with full force. Two clean strategies: pause infinite loops (the negative-delay trick means paused items hold their distributed formation), and jump one-shot entrances to their final state.

@media (prefers-reduced-motion: reduce) {
  .orbit .item { animation-play-state: paused; } /* formation kept */
  .toast { animation: none; offset-distance: 100%; opacity: 1; }
}

Browser support

Production. offset-path: path() has shipped in all three engines for years. The full source set — basic shapes, ray(), shape(), and the coord-box keywords — is complete in Chrome 116+, Firefox 122+, and Safari 17+. No @supports gate is required for current targets; if you must serve older Safari, gate ray()/shape() usages and fall back to path() or static placement.

Try it yourself

Mini-exercise

Extend the orbital system into a small solar system, then add a curved entrance. (1) Add two more dots and update --count to 8 — confirm the formation redistributes itself because the delays are arithmetic, not hand-computed. (2) Give the dots offset-rotate: auto and a non-circular shape to see tangent-following in action. (3) Replace the animation with static placement: delete the keyframes and set offset-distance: calc(100% / var(--count) * var(--i)) — same geometry, zero motion. (4) Build the toast fly-in from this lesson with path(), offset-rotate: 0deg, and a prefers-reduced-motion override that jumps it to offset-distance: 100%.
