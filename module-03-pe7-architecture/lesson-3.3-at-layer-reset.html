Lesson 3.3

@layer reset

The lowest layer, the weakest rules, the thinnest file. Its only job: delete browser defaults so the rest of your stack can start from a known baseline — and do it with zero specificity so nothing above has to fight to override it.

The single responsibility

The reset layer exists to eliminate user-agent opinions. Default margins, default list bullets, default button chrome, default focus rings. It does not paint anything, does not size anything in the semantic sense, does not make decisions about how your product should look. It just clears the slate.

If your reset layer contains a single font-family declaration, you have violated the boundary. That is typography, which belongs in base.

Why :where() matters

The :where() pseudo-class has specificity 0,0,0 regardless of what it wraps. :where(h1, h2, h3) still scores zero. That is the entire reason the PE7 reset uses it everywhere.

A reset rule wrapped in :where() has zero specificity. The layer already gives it the lowest priority. The zero specificity means that even if somehow you needed to override a reset rule from inside the same layer (you should not), you would win trivially. And when you write h1 { ... } in your base layer, you do not need to think about whether the reset is fighting you — it cannot.

The canonical reset

@layer reset {
  /* Universal box model */
  :where(*, *::before, *::after) {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
  }

  /* Document defaults */
  :where(html) {
    -webkit-text-size-adjust: 100%;
    text-size-adjust: 100%;
  }

  /* Heading reset — no default size, no default weight */
  :where(h1, h2, h3, h4, h5, h6) {
    font-size: inherit;
    font-weight: inherit;
  }

  /* Lists with role="list" drop their semantics in some screen readers
     if we strip bullets, so we only strip when role is absent. */
  :where(ul, ol) {
    list-style: none;
  }

  /* Media should behave like blocks and never overflow */
  :where(img, picture, video, canvas, svg) {
    display: block;
    max-inline-size: 100%;
    block-size: auto;
  }

  /* Form controls inherit typography */
  :where(input, button, textarea, select) {
    font: inherit;
    color: inherit;
  }

  /* Buttons lose their chrome but stay interactive */
  :where(button) {
    background: transparent;
    border: 0;
    padding: 0;
    cursor: pointer;
  }
}

What the reset must not do

  • Set colors. That is base.
  • Set fonts. That is base, using tokens.
  • Set spacing beyond zeroing. Spacing decisions belong in base and layout.
  • Touch classes. The reset only sees element selectors wrapped in :where().
  • Use !important. Ever. A reset that needs importance is a reset that has been weaponised into a framework.

Try it yourself

Mini-exercise

Remove the :where() wrappers so every reset rule uses bare element selectors. The output looks identical. Now add, inside @layer base, a single rule h1 { color: oklch(58% 0.22 275); }. Does the h1 turn indigo? Yes. Now try it again — but first put h1, h2 { color: red; } (no :where()) back into the reset layer. Does base still win? Why does it matter when specificities inside different layers are still irrelevant?
