Lesson 3.2

Six Layers, Single Responsibilities

One job per layer. If a layer owns two jobs, it owns none. The discipline is the architecture.

The declaration

@layer reset, tokens, base, layout, components, animations;

Six names, in priority order, from weakest to strongest. Memorise the order. It is not arbitrary — each layer can legitimately override everything below it and never needs to reach above.

The six responsibilities

  1. reset — eliminate browser defaults. Zero specificity. Wraps every selector in :where(). Never paints, never sizes. Just removes UA opinions so the layers above get a clean slate. Detail: Lesson 3.3.
  2. tokens — single source of truth for design decisions. Only custom properties on :root or theme roots. No selectors that target elements. No type selectors. No class selectors that style something. This layer is data, not styling. Detail: Lesson 3.4.
  3. base — styles for raw HTML elements using tokens. body, h1–h6, p, a, button, form elements. Element selectors only. No classes. This is "what does an unstyled HTML document look like when the design system is applied." Detail: Lesson 3.5.
  4. layout — structural primitives. Stack, cluster, grid, frame, center. No colors, no fonts, no decoration — just the arrangement of things in space. Classes only, and always structural classes. Detail: Lesson 3.6.
  5. components — the named UI pieces: buttons, cards, dialogs, badges, forms. Uses tokens, inherits from base, sits inside layout primitives. Each component has one responsibility and its own scoped custom properties. Detail: Lesson 3.7.
  6. animations — keyframes, transitions, and motion behaviour. The highest priority because accessibility demands it: prefers-reduced-motion lives here and must be able to override anything below. Detail: Lesson 3.8.

The test of single responsibility

For each layer, ask: "If I delete this layer entirely, what breaks, and can I describe it in one sentence?" If the answer is a short sentence, the layer is doing one job. If the answer sprawls, the layer is doing too much — and that is where the next migration will get stuck.

  • Delete reset → UA defaults come back.
  • Delete tokens → nothing has a value for its custom properties.
  • Delete base → raw HTML elements look unstyled.
  • Delete layout → elements stop being arranged.
  • Delete components → named UI pieces lose their identity.
  • Delete animations → everything is static.

Each description is one clause. That is the shape of a healthy layer.

Why this order specifically

Reset must be the weakest because everything else intentionally overrides it. Tokens sit next because they are pure data — nothing collides with them. Base comes after tokens because base uses tokens. Layout comes after base because layout may need to set, say, display: grid on a section that base already styled. Components come after layout because a component lives inside a layout primitive and may need to adjust its own structural properties. Animations come last because reduced-motion overrides must beat everything.
