Lesson 3.9

Layer Boundaries: The 7 Non-Negotiables

Seven rules. Break any of them and the architecture stops paying you back. Each rule has a visible failure mode. Each one is enforceable in code review in under a minute.

Rule 1 — Every rule lives in exactly one layer

No unlayered rules in a PE7 codebase. None. The unlayered escape hatch exists for legacy migration; a new project never uses it. If a rule does not live in a named layer, the architecture has a blind spot the size of that rule.

Violation example:

/* root.css */
@layer reset, tokens, base, layout, components, animations;

/* UNLAYERED — wrong */
.urgent-banner { background: red !important; }

The unlayered rule will beat every layered rule in the project. Nobody will understand why their overrides fail.

Rule 2 — Tokens contain no selectors that style elements

The tokens layer only sets custom properties. No color, no background, no margin, no font-size applied to an element. Theme switches that set custom properties on a [data-theme] root are still tokens. Anything beyond that is not.

Violation example: @layer tokens { body { background: var(--color-surface); } } — that rule belongs in base.

Rule 3 — Base contains only element selectors

If you write a class, an ID, or an attribute selector (other than accessibility pseudo-classes like :focus-visible) in the base layer, you have leaked component state into base.

Violation example: @layer base { .prose p { max-inline-size: 60ch; } } — the .prose context makes this a component decision, not a base one. Either move it to a component or drop the class and apply to all p.

Rule 4 — Layout sets no colours, fonts, borders, or shadows

Layout arranges. Decoration is always components. This rule is the easiest to violate because it is often tempting to add "just a background" to a layout primitive for visual separation during development. Don't. The visible failure is that every consumer of the primitive gets the background whether they want it or not.

Rule 5 — Components never reach into other components by name

No .card .btn { ... }. No .dialog .form-field { ... }. A component is a sealed unit. If a button needs to look different inside a card, the right move is a modifier on the button (.btn.compact), not a descendant selector from the card.

Violation example:

@layer components {
  .card .btn { padding: .25rem .5rem; } /* WRONG — card is reaching in */
  .btn.compact { padding: .25rem .5rem; } /* RIGHT — button owns its modifier */
}

Rule 6 — No !important outside the reduced-motion override

The only legitimate use of !important in a PE7 codebase is inside @media (prefers-reduced-motion: reduce) in the animations layer. Everywhere else, if you reach for !important, you have chosen the wrong layer. Move the rule up. Reaching for !important is a symptom; the disease is layer placement.

Rule 7 — The declaration line is immutable at runtime

You declare @layer reset, tokens, base, layout, components, animations; on line 1 of the root stylesheet, and then you never add a new top-level layer without a team-wide decision. Sub-layers inside existing layers are fine. A new peer to components is a design change to the architecture — it must be deliberate, documented, and rare.

Enforcement in review

Every one of these rules can be checked in a diff in seconds. "Is this rule inside a layer?" "Does it set a property on an element?" "Does it contain a class selector?" "Is there an !important and is it inside prefers-reduced-motion?" When a rule fails the check, the question is not "does it work" — it is "which layer does it belong in." The architecture tells you.

Illustration — a rule per violation

/* RULE 3 — base contains only element selectors */
@layer base { .prose h2 { font-size: 2rem; } }  /* class in base */
@layer base { h2 { font-size: 2rem; } }          /* element only */

/* RULE 5 — components never reach into other components */
@layer components { .card .btn { padding: .25rem; } }
@layer components { .btn.compact { padding: .25rem; } }

/* RULE 6 — no !important outside prefers-reduced-motion */
@layer components { .btn { color: red !important; } }
@layer components { .btn.danger { color: var(--color-danger); } }

Try it yourself — spot the violations

Mini-exercise

The editor above contains four deliberate violations (rules 1, 2, 3, and 6). Identify each one, then rewrite the stylesheet so every rule lives in its correct layer with no !important and no unlayered rules. Compare your answer with a teammate — if you both reached the same layout, the architecture is doing its job.
