Module 3 · Project

Scaffold a PE7 Stack

Stand up the complete six-layer architecture for a fictional three-page documentation site. Every layer gets a representative rule. Every rule obeys its boundary. The result is a single-file scaffold you could drop into a real project tomorrow.

The brief

You are starting a docs site for an internal API. Three pages: home, reference, changelog. You do not need to implement the full site — you need to stand up the CSS architecture so that every future rule has a correct home before a single page is built. That is the discipline the architecture rewards.

Your deliverable is the single root.css equivalent shown below, populated with enough sample rules in each layer to prove the boundaries. Anything you add later must fit into the existing layers.

The rules of engagement

  1. Every rule lives inside a named layer. No exceptions.
  2. Tokens layer: only custom properties.
  3. Base layer: only element selectors.
  4. Layout layer: only structural classes; no colours or fonts.
  5. Components layer: classes only, scoped custom properties for variants.
  6. Animations layer: transitions, keyframes, and the reduced-motion override.
  7. No !important except inside prefers-reduced-motion.

The contract, one page

Every rule above lives in exactly one of six layers, and you can verify it by reading. Tokens hold only custom properties. Base uses only element selectors. Layout has no colour or typography. Components carry their own variable surface through scoped custom properties. Animations own every transition and the reduced-motion override. Reset is invisible — which is how you know it is doing its job.
