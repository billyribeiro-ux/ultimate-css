Lesson 3.4

@layer tokens

Pure data. No selectors that target elements. No styling. The tokens layer is a dictionary of named design decisions, nothing more — and that restriction is exactly what makes it powerful.

The single responsibility

The tokens layer defines custom properties on root scopes. That is its whole job. If a rule in this layer sets any standard CSS property — color, font-size, margin — on any element, the boundary has been violated. This layer is a lookup table.

Why this purity matters: if tokens can paint, they become indistinguishable from base, and "what value is the brand colour" becomes "well, it depends on which rule fires last." A dictionary that can also paint is not a dictionary.

Primitive vs semantic

PE7 tokens have two tiers. Primitives are the raw values; semantic tokens are the named intentions that reference them.

@layer tokens {
  :root {
    /* Primitives — raw palette */
    --purple-500: oklch(55% 0.22 290);
    --purple-600: oklch(48% 0.22 290);
    --gray-100:   oklch(96% 0.005 264);
    --gray-900:   oklch(14% 0.015 264);

    /* Semantic — what the app means by these values */
    --color-brand:         var(--purple-500);
    --color-brand-hover:   var(--purple-600);
    --color-surface:       var(--gray-100);
    --color-text:          var(--gray-900);
  }
}

Components never reference primitives. They reference semantic tokens. That way, rebranding means changing the semantic aliases, not touching a single component.

The six token categories

  • Color — brand, surface, text, border, status (success, warning, danger).
  • Spacing — a numeric scale (--space-1 through --space-12), often T-shirt aliased (--space-xs, --space-md).
  • Type — family, size scale, weight scale, line-height scale, letter-spacing.
  • Motion — duration scale, easing functions, predefined transitions.
  • Radius — a small scale from --radius-sm to --radius-full.
  • Z-index — named stacking tiers so no component has to guess at magic numbers.

Module 4 covers each category in depth. For now, know that every token in your codebase belongs to exactly one of these six categories. If you invent a seventh, stop and ask whether it is really a token or actually a component decision.

What the tokens layer must not contain

  • No element selectors. body { --color-brand: ... } is tokens. body { background: ... } is base.
  • No class selectors that style something. [data-theme="dark"] { --color-bg: ... } is tokens (it only sets custom properties). .card { --card-bg: ... } is components.
  • No @media wrapping visual changes. A media query that changes token values is fine; a media query that changes layout is layout.

Try it yourself

Mini-exercise

Change --purple-500 to oklch(60% 0.22 25) (red). The h1 turns red without touching a single base rule. Now try to move the h1 { color: ... } rule into the tokens layer. The code still works — but name the architectural property you just violated, and explain in one sentence why future you will regret it.
