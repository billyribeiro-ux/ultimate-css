Lesson 3.5

@layer base

Element selectors, token-powered, accessible by default. The base layer is the answer to "what does raw HTML look like in our design system, before a single component gets involved."

The single responsibility

The base layer styles raw HTML elements. Every rule targets an element selector — body, h1, p, a, button, form controls. No classes. No IDs. No attribute selectors except accessibility-relevant ones like :focus-visible.

The goal: an author can write a plain HTML file with zero classes and get a typographically sensible, on-brand document. Markdown rendered to HTML should work. A blog post should work. A <dialog> element straight from the browser should look coherent.

Only use tokens

Every value in the base layer must reference a token. No magic numbers. No hex colours. No raw pixel values. If you cannot express something with an existing token, you either add the token (tokens layer) or the decision does not belong in base.

@layer base {
  body {
    font-family: var(--font-body);
    font-size:   var(--text-md);
    line-height: var(--leading-normal);
    color:       var(--color-text);
    background:  var(--color-surface);
  }

  h1, h2, h3 {
    font-family: var(--font-display);
    line-height: var(--leading-tight);
    text-wrap:   balance;
  }

  h1 { font-size: var(--text-3xl); }
  h2 { font-size: var(--text-2xl); }
  h3 { font-size: var(--text-xl);  }

  p { max-inline-size: var(--measure-wide); text-wrap: pretty; }

  a {
    color: var(--color-link);
    text-decoration-thickness: 2px;
    text-underline-offset: 0.15em;
  }

  a:focus-visible {
    outline: 2px solid var(--color-focus);
    outline-offset: 2px;
    border-radius: var(--radius-sm);
  }
}

Logical properties, always

PE7 base rules use logical properties (margin-block, padding-inline, inset, max-inline-size) instead of physical ones (margin-top, padding-left, width). This is not dogma — it is the only way to ship a codebase that correctly supports right-to-left languages and vertical writing modes without retrofitting. Physical properties are a liability from day one.

Accessible focus by default

Every interactive element — a, button, input, select, textarea, [tabindex] — gets a visible focus ring in the base layer, keyed on :focus-visible. That way, accessibility is not a component-by-component opt-in; it is the default, and components have to actively opt out if they want custom focus behaviour.

What base must not contain

  • No classes. Ever. Classes live in components.
  • No layout primitives. No .stack, no .grid.
  • No component-specific styling. A card is not an element.
  • No !important. The layer priority is your importance.
  • No hard-coded values. Everything resolves to a token.

Try it yourself

Mini-exercise

Tab to the link and the button in the preview above. You should see the token-driven focus ring on both. Now delete the :focus-visible rule and tab again. The ring disappears everywhere — that is what "accessibility by default in the base layer" buys you. Put the rule back. Then try rewriting margin-block-end: var(--space-3) as margin-bottom: var(--space-3). It works — now name the future language it breaks for.
