Lesson 3.8

@layer animations

The highest layer in the stack. Motion logic, transitions, keyframes — and, critically, the prefers-reduced-motion override that must beat every animation in every component below it.

Why animations is the top layer

Animations are applied on top of an already-styled component. If your button base class sets background: var(--btn-bg), and a hover animation needs to interpolate that background, the animation rule must be able to override the base without fighting it. That is fine within a layer. But the reason animations sits at the very top is accessibility: when a user has prefers-reduced-motion: reduce set, your motion overrides must win, no matter which component tried to schedule a transition.

Transitions and keyframes together

@layer animations {
  /* Keyframes */
  @keyframes fade-in {
    from { opacity: 0; transform: translateY(4px); }
    to   { opacity: 1; transform: translateY(0); }
  }

  @keyframes pulse {
    0%, 100% { opacity: 1; }
    50%      { opacity: .6; }
  }

  /* Component transitions */
  .btn     { transition: background var(--motion-fast) var(--ease-out),
                         transform  var(--motion-fast) var(--ease-out); }
  .btn:hover   { transform: translateY(-1px); }
  .btn:active  { transform: translateY(0); }

  .dialog  { animation: fade-in var(--motion-md) var(--ease-out); }

  .skeleton { animation: pulse 1.2s var(--ease-in-out) infinite; }
}

The reduced-motion override

This is the one place in a PE7 codebase where !important is legitimate, and it is legitimate precisely because the layer is at the top and the accessibility requirement is absolute:

@layer animations {
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration:   0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration:  0.01ms !important;
      scroll-behavior:      auto    !important;
    }
  }
}

Why !important here? Because animations on individual elements can come from inline styles, JS-injected styles, or third-party libraries inside lower layers, and the accessibility default must win against all of them. This is the single exception to the "no !important" rule, and it is documented in every PE7 codebase as the only place it appears.

Motion tokens

Every duration and easing value references a motion token, same principle as colour and spacing. The vocabulary is small:

  • --motion-fast — 150ms, for micro-interactions.
  • --motion-md — 250ms, for most UI transitions.
  • --motion-slow — 400ms, for page-level moves.
  • --ease-out — for things entering the viewport.
  • --ease-in — for things exiting.
  • --ease-in-out — for reversible state changes.

Module 4 covers motion tokens in depth.

What animations must not contain

  • No component shape or colour decisions that the component would otherwise own — only the transitioning of them.
  • No new custom properties for component appearance — those belong in components.
  • No !important outside the reduced-motion override.
