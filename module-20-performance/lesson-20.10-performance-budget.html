Lesson 20.10 · Strategy

Setting a CSS Performance Budget

Performance without measurement is guesswork. A CSS performance budget sets hard limits on file size, render cost, and user-facing metrics — then enforces them in CI. Here are the metrics, the targets, and how PE7 architecture gives you a head start.

The metrics that matter

CSS directly affects four Core Web Vitals and performance metrics:

First Contentful Paint (FCP)

Time until the user sees the first piece of content. CSS blocks rendering — every byte of CSS in <head> delays FCP. Critical CSS inlining (Lesson 20.4) directly reduces this metric.

Largest Contentful Paint (LCP)

Time until the largest visible element renders. Often a hero image or heading. CSS that blocks rendering or causes images to load late hurts LCP. Font loading strategy (Lesson 20.6) and image aspect-ratio (Lesson 20.7) directly improve this.

Cumulative Layout Shift (CLS)

Total visual instability during page load. CSS causes CLS through: font swaps without size-adjust, images without aspect-ratio, dynamically injected styles, and late-loading stylesheets that restyle content.

Total Blocking Time (TBT)

Time the main thread is blocked. CSS contributes through expensive style recalculation (complex selectors + large DOM), forced synchronous layouts (reading layout properties after writing them), and large stylesheet parsing.

Monitoring with Lighthouse CI

Lighthouse CI runs performance audits on every pull request. Configure assertions for CSS-specific metrics:

{
  "assertions": {
    "first-contentful-paint": ["error", {"maxNumericValue": 1800}],
    "cumulative-layout-shift": ["error", {"maxNumericValue": 0.1}],
    "total-blocking-time": ["error", {"maxNumericValue": 300}],
    "unused-css-rules": ["warn", {"maxLength": 0}]
  }
}

PE7 architecture's inherent advantages

The PE7 layered architecture naturally supports performance budgets:

  • Layered loading: Tokens+reset+base can be inlined (critical), components+animations loaded async.
  • Token deduplication: All values are defined once in the tokens layer. No repeated hardcoded values bloating file size.
  • Compositor-only animations: The animations layer uses only transform, opacity, and filter. No layout-triggering animations by design.
  • Modular removal: Unused layers can be removed without cascade side effects. Page-specific bundles are trivial to create.
  • Container queries: Components using container-type get containment for free, reducing reflow scope.

Final exercise

Take a real project and establish a CSS performance budget. (1) Measure current FCP, LCP, CLS, and total CSS size with Lighthouse. (2) Set targets based on the table above. (3) Apply the techniques from this module: inline critical CSS, use compositor-only animations, add content-visibility, set aspect-ratio on images, configure font-display. (4) Re-measure and verify you meet your budget. This is the workflow of a CSS performance engineer.
