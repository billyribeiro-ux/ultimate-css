Lesson 20.5 · Rendering

content-visibility: The 7x Speedup

One CSS property can reduce initial render time from 200ms to 30ms on content-heavy pages. content-visibility: auto tells the browser to skip layout and paint for off-screen elements entirely — rendering them only when they scroll into view.

How content-visibility works

content-visibility: auto applies three containment types to off-screen elements: layout containment, style containment, and paint containment. The browser skips the layout and paint stages entirely for these elements until they approach the viewport. This is not lazy loading — the DOM is still there, the content is still accessible to search — it's just not rendered until needed.

The contain-intrinsic-size requirement

When an element's rendering is skipped, it has zero height. This causes the scrollbar to jump wildly as elements render on scroll. The fix is contain-intrinsic-size:

.section {
  content-visibility: auto;
  contain-intrinsic-size: auto 500px;
}

The auto keyword tells the browser: "Use 500px as the initial estimate, but once this element has been rendered, remember its actual size." This means the first visit uses the estimate, and subsequent scrolls use the real measured height. Much better than a fixed value.

Real-world impact

Consider a documentation page with 50 sections. Without content-visibility, the browser must layout and paint all 50 sections on initial load — even though only 2-3 are visible. With content-visibility: auto, it only renders the visible sections initially. The other 47 are rendered on-demand as the user scrolls.

Measured results on a real documentation site: rendering time dropped from 232ms to 30ms — a 7.7x improvement.

Measuring with Performance panel

  1. Open DevTools Performance panel
  2. Record a page load without content-visibility
  3. Note the total "Rendering" time in the summary
  4. Add content-visibility: auto to off-screen sections
  5. Record again and compare

When NOT to use it

  • Accessibility: Some screen readers may not announce content with content-visibility: hidden. The auto value is generally safe because the browser renders content when it enters the viewport, but test with screen readers.
  • Find-in-page: Content with content-visibility: auto IS searchable with Ctrl+F (the browser handles this). But content-visibility: hidden is not.
  • Anchor links: Jumping to an anchor within a skipped section works — the browser renders it on demand. But the scroll position may be imprecise if contain-intrinsic-size estimates are wrong.

Off-screen sections are skipped entirely. No layout, no paint. Only the contain-intrinsic-size placeholder height is used.

Section 4: API Reference

When you scroll to this section, the browser renders it just-in-time. The transition is seamless to the user.

Section 5: Advanced Usage

Each skipped section saves layout and paint time. With 50 sections, that is 47 sections of work avoided on initial load.

Section 6: Troubleshooting

The auto keyword for contain-intrinsic-size remembers the real height after first render, preventing scroll jumps on repeat visits.

Section 7: Migration Guide

Content-visibility: auto is safe for accessibility — screen readers can still access the DOM, and find-in-page works normally.

Section 8: Performance Tips

Combine content-visibility with lazy-loaded images for maximum savings. Images in skipped sections are not decoded until needed.

Section 9: Changelog

Track rendering improvements in DevTools Performance panel. Look for reduced Layout and Paint events during initial page load.

Section 10: FAQ

The most common question: does it break SEO? No — content is still in the DOM, fully crawlable. Only rendering is deferred.

The CSS

.section { content-visibility: auto; contain-intrinsic-size: auto 500px; }
Note: Always provide contain-intrinsic-size. Without it, off-screen elements collapse to 0px height, causing scrollbar instability.
