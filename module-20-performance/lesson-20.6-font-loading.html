Lesson 20.6 · Loading

Web Font Loading Strategies

Web fonts cause two problems: invisible text while loading (FOIT) and layout shift when they arrive (CLS). The right combination of font-display, size-adjust, preloading, and subsetting eliminates both problems while keeping your typography beautiful.

font-display values

The font-display descriptor in @font-face controls what happens while the font loads:

  • swap — Show fallback immediately, swap when font loads. Best for body text. May cause layout shift.
  • optional — Show fallback immediately. Only use the web font if it loads within ~100ms (likely from cache). Best for repeat visitors. Zero layout shift on slow connections.
  • fallback — Short invisible period (~100ms), then fallback, then swap. A compromise between swap and block.
  • block — Invisible text for up to 3 seconds. Almost never what you want.

Reducing layout shift with size-adjust

When a web font swaps in, it typically has different metrics than the fallback (different x-height, ascenders, descenders). This causes text to reflow — a CLS hit. The fix:

@font-face {
  font-family: "My Font";
  src: url("myfont.woff2") format("woff2");
  font-display: swap;
}

/* Fallback with matching metrics */
@font-face {
  font-family: "My Font Fallback";
  src: local("Arial");
  size-adjust: 106%;
  ascent-override: 92%;
  descent-override: 22%;
  line-gap-override: 0%;
}

The size-adjust, ascent-override, descent-override, and line-gap-override properties tune the fallback font to match the web font's metrics exactly. Tools like fontaine or Google's font-fallback-generator calculate these values automatically.

Preloading fonts

<link rel="preload" href="/fonts/myfont.woff2"
      as="font" type="font/woff2" crossorigin>

This tells the browser to start downloading the font immediately, before it discovers the @font-face rule. The crossorigin attribute is required for fonts even when same-origin.

Font subsetting

A full font file with all Unicode ranges can be 200KB+. Subsetting to Latin-only reduces this to 20-40KB. Google Fonts does this automatically with unicode-range:

@font-face {
  font-family: "Inter";
  src: url("inter-latin.woff2") format("woff2");
  unicode-range: U+0000-00FF, U+0131, U+0152-0153;
}

Variable fonts

Instead of loading 6 separate files (light, regular, medium, semibold, bold, black), a single variable font file covers all weights. One HTTP request instead of six. File size: typically 80-120KB for a variable font vs 6x30KB = 180KB for static files.

The system font stack

font-family: system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", Roboto, sans-serif;

Zero download, zero CLS, zero FOIT. The fastest font is the one already on the user's device. For body text on performance-critical pages, this is often the best choice.

Try it yourself

Mini-exercise

Run a Lighthouse audit on a site that uses web fonts. Check the CLS score and look for "Ensure text remains visible during webfont load" in the diagnostics. Add font-display: swap to the @font-face declaration and re-audit. Then use a tool like fontaine to generate size-adjust values for your fallback font and observe the CLS improvement.
