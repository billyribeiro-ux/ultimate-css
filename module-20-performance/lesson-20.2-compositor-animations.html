Lesson 20.2 · Animation Performance

Compositor-Friendly Animations

The difference between a smooth 60fps animation and a janky mess comes down to one question: does your animation run on the compositor thread or the main thread? Here are the safe properties, the dangerous ones, and the tools that help the browser optimize.

The safe list: compositor-only properties

These properties are handled entirely by the GPU compositor thread. They never trigger layout or paint:

  • transform — translate, rotate, scale, skew
  • opacity — fade in/out
  • filter — blur, brightness, contrast, etc.
  • clip-path — shape clipping (when animating with basic shapes)

These four cover 95% of all animation needs. Movement? Use transform: translate(). Size change? Use transform: scale(). Visibility? Use opacity. Effects? Use filter.

The unsafe list: layout-triggering properties

Animating any of these forces the browser to recalculate layout on every single frame:

  • width, height, min-width, max-height
  • top, left, right, bottom
  • margin, padding, border-width
  • font-size, line-height

The common mistake: animating left instead of transform: translateX(). Both move an element — but left triggers layout+paint+composite while translateX triggers composite only.

will-change: hinting the browser

will-change tells the browser to pre-promote an element to its own compositor layer. This avoids the cost of layer promotion when the animation starts.

/* Good: apply before the animation starts */
.card:hover { will-change: transform; }
.card:active { transform: scale(0.98); }

/* Bad: always-on will-change wastes GPU memory */
.card { will-change: transform; } /* Don't do this */

Every will-change layer consumes GPU memory. On a page with 200 cards, that is 200 extra layers. Use it sparingly and remove it when the animation completes.

contain: isolating reflow

The contain property tells the browser that an element's internals won't affect the rest of the page:

.card {
  contain: layout style paint;
}

contain: layout means layout changes inside this element won't cause reflow outside it. contain: paint means paint is clipped to this element. contain: style isolates counter and quote effects. Together, they dramatically reduce the cost of changes within contained elements.
