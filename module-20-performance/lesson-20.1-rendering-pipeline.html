Lesson 20.1 · Rendering

The Browser Rendering Pipeline

Every pixel on screen passes through a five-stage pipeline: Parse, Style, Layout, Paint, Composite. Understanding this pipeline is the foundation of CSS performance — it tells you exactly why some property changes are free and others cost 16ms of jank.

The five stages

When the browser receives HTML and CSS, it transforms them into pixels through a strict sequence:

  1. Parse — HTML becomes the DOM tree, CSS becomes the CSSOM tree. These two trees are built in parallel.
  2. Style — The browser merges DOM + CSSOM to compute the final styles for every element (the "render tree"). Selectors are matched, specificity is resolved, inheritance is applied.
  3. Layout — The browser calculates the exact position and size of every element. This is where width, height, margin, padding, top, left, and font-size are resolved into pixel coordinates.
  4. Paint — Each element is drawn into layers: backgrounds, borders, text, shadows. The output is a list of "paint commands" (like a GPU instruction set).
  5. Composite — The painted layers are assembled in the correct stacking order and sent to the GPU for final rendering to the screen.

Why this matters for performance

Changing a CSS property forces the browser to redo every stage after the one you triggered. This is the key insight:

  • Changing width triggers: Layout + Paint + Composite (expensive)
  • Changing background-color triggers: Paint + Composite (moderate)
  • Changing transform or opacity triggers: Composite only (cheap)

At 60fps, you have 16.67ms per frame. Layout can easily take 5-10ms on a complex page. Paint can take 3-8ms. Composite typically takes under 1ms. This is why compositor-only properties are the gold standard for animation.

The compositor thread

Modern browsers run compositing on a separate thread from the main thread. This means transform and opacity animations can run at 60fps even while JavaScript is executing on the main thread. This is the single most important performance fact in CSS: compositor-only animations cannot be janked by JavaScript.

Property trigger categories

Every CSS property falls into one of three categories:

  • Layout triggers: width, height, padding, margin, border-width, top, left, font-size, display, position, float
  • Paint triggers: color, background, box-shadow, text-shadow, border-color, border-radius, outline, visibility
  • Composite triggers: transform, opacity, filter, clip-path, will-change

Try it yourself

Mini-exercise

Open DevTools and go to the Performance panel. Record a 3-second trace while both animations are running. Examine the flame chart: the width animation will show repeated "Layout" and "Paint" blocks on every frame. The transform animation will show only "Composite Layers." Calculate the time spent in layout vs composite. This is why we animate transforms.
