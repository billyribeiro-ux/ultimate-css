Lesson 7.2

The Container Primitive

A container is the outer width constraint of any full-width layout. Four lines of CSS — no media queries — give you a responsive, centred, token-configurable container that adapts to any screen size without breakpoints.

The rule

.container {
  inline-size: min(var(--container-max, 72rem), 100%);
  margin-inline: auto;
  padding-inline: var(--container-gap, var(--space-lg));
}

Three lines of declaration. That is the entire primitive.

min() is the trick

min(72rem, 100%) returns whichever is smaller: the maximum width (72rem) on wide screens, or the full parent width (100%) on narrow screens. On a 1920px desktop the container is 72rem; on a 375px phone it is the full viewport minus the padding. No media query, no max-width separate from width, no breakpoints.

margin-inline: auto

Centres the container horizontally in its parent. Logical property, so in vertical writing modes it centres on the correct axis. In LTR and RTL the behaviour is identical — auto margins are symmetrical.

padding-inline

Gutter space between the container's content and the edge of the viewport. On narrow screens this prevents text from touching the edge; on wide screens it is visually absorbed by the min() constraint. Using a token (--space-lg) means the gutter matches your overall spacing scale.

Custom property interface

Both knobs are custom properties with defaults. A component or section can override either without writing a new class:

.narrow-container { --container-max: 40rem; }
.no-gutter { --container-gap: 0; }

/* Or inline in HTML: */
<div class="container" style="--container-max: 50rem">...</div>

Not a max-width

Writing max-width: 72rem; width: 100%; achieves a similar result, but it is two declarations and two concepts. inline-size: min(72rem, 100%) is one declaration that explicitly states "whichever is smaller." The semantic is clearer, and min() nests cleanly inside other calculations.

Containers do not stack

A container inside a container is almost always a mistake. If you need nested width constraints, use a single container and let the inner layout primitives decide their own widths via max-inline-size. The rule: one container per top-level layout section.

Mini-exercise

In your last project, find the wrapper element that constrains main content width. Count how many rules or media queries it uses. Compare with the three lines above. The difference between your existing approach and this primitive is either redundant CSS or a missing min().
