Lesson 7.5

The Sidebar Primitive

Sidebar is the classic "narrow column next to a wide column" layout — and the classic reason people reach for media queries. The PE7 sidebar collapses to one column automatically when space runs out, with no breakpoint specified anywhere. The technique is called the flex-grow-999 trick, and once you see it work you will never write a sidebar media query again.

The rule

.sidebar {
  display: flex;
  flex-wrap: wrap;
  gap: var(--sidebar-gap, var(--space-xl));
}
.sidebar > :first-child {
  flex-basis: var(--sidebar-width, 18rem);
  flex-grow: 1;
}
.sidebar > :last-child {
  flex-basis: 0;
  flex-grow: 999;
  min-inline-size: var(--sidebar-min, 50%);
}

The flex-grow: 999 trick

The sidebar has two children. The first (the "sidebar column") has a natural basis of 18rem and a grow factor of 1. The second (the "main column") has a basis of 0 and a grow factor of 999. Because of those numbers, the main column takes all available extra space whenever both fit on the same row — the sidebar stays at 18rem and the main expands to fill whatever is left.

When there is not enough room for both, flex-wrap: wrap kicks in. The main column's min-inline-size: 50% is the threshold: if the main cannot be at least 50% of the container, it wraps to its own row. Because the sidebar is in the first row alone now, and the main is in the second row alone, they render stacked. No media query.

Why 999 and not 1

With grow factors 1 and 1, flex distributes extra space evenly — both columns grow together. With 1 and 999, the ratio is so extreme that the first column effectively does not grow at all; it sits at its basis. You could use 99 or 9999; the number just needs to be large enough that the ratio is functionally "all for main, none for sidebar."

The collapse threshold

min-inline-size: 50% on the main column defines when the layout collapses. Below that, wrap triggers. Change the threshold by changing the token:

.narrow-sidebar { --sidebar-min: 35rem; }  /* collapse earlier */
.wide-sidebar   { --sidebar-min: 70%; }    /* stay horizontal longer */

It responds to the container, not the viewport

The collapse happens based on the container's inline-size, not the viewport's. That means a sidebar inside a narrow card collapses at the card's width, not at a global breakpoint. A sidebar inside a wide main column stays expanded longer. This is component-aware responsiveness — you get it for free, because the rule is about flex-basis, not about @media.

Composition

The sidebar's children are usually both stacks — a vertical menu in the sidebar column, a vertical article flow in the main column. Sidebar provides the two-column relationship; stack provides the vertical rhythm inside each column. Every complex documentation layout is some nesting of this pair.

Try it yourself

Mini-exercise

Change flex-grow: 999 to flex-grow: 1 on the last child. The two columns now grow in a 1:1 ratio — the sidebar stretches to match the main column's width, which is usually not what you want. Change it back. Then change min-inline-size: 50% to min-inline-size: 80%. The layout collapses much earlier. That one number is your "breakpoint," expressed as content requirement instead of viewport width.
