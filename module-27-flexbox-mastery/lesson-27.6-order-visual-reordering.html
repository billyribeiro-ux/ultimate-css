Order and Visual Reordering

The order property lets you change the visual sequence of flex items without touching the DOM. But visual reordering disconnects what users see from what screen readers read. Understanding the accessibility implications — and the emerging reading-flow fix — is essential for responsible use.

How order works

Every flex item has order: 0 by default. Items are laid out in ascending order value, then by DOM order within the same value:

.item-a { order: 2; }   /* appears third */
.item-b { order: 1; }   /* appears second */
.item-c { order: 0; }   /* appears first (default) */

Negative values are valid: order: -1 moves an item before all default-order items.

Common use cases

  • Mobile-first source order: Put content before sidebar in HTML (better for SEO/screen readers), then use order to place the sidebar first visually on desktop.
  • Pinned items: Give a "pinned" item order: -1 to always show it first.
  • Dynamic reordering: A JavaScript toggle that sets order on filtered items (e.g., sorting a list by date vs. name).

The accessibility problem

Screen readers and keyboard Tab order follow the DOM order, not the visual order. When you use order (or flex-direction: row-reverse), sighted users see one sequence while keyboard users navigate another. This creates a confusing, potentially unusable experience for keyboard and assistive technology users.

WCAG 2.2 Success Criterion 1.3.2

"When the sequence in which content is presented affects its meaning, a correct reading sequence can be programmatically determined." Visual reordering can violate this when the order carries meaning (e.g., navigation items, steps in a process).

The reading-flow fix (CSS 2026)

The reading-flow property (covered in Module 13) instructs the browser to make the Tab order follow the visual layout order instead of DOM order:

.container {
  display: flex;
  reading-flow: flex-visual;
}
/* Now Tab order follows the visual flex order */

Values: normal (default, DOM order), flex-visual (follows flex layout), flex-flow (follows flex-flow direction), grid-rows, grid-columns, grid-order.

When to use order vs. changing DOM

  • Use order: purely decorative reordering (e.g., alternating image/text layout on even rows), combined with reading-flow.
  • Change DOM order: when the sequence carries meaning, when you need Tab order to match visuals in browsers that don't support reading-flow, or when server-rendering.
  • Use flex-direction: row-reverse: for right-to-left visual flow where the logical reading order is still left-to-right (e.g., a "latest first" list).

flex-direction reversal

row-reverse and column-reverse also reorder visually. They have the same accessibility concerns as order. The same reading-flow fix applies.

Practical patterns for order

/* Mobile: image above text. Desktop: text left, image right */
.feature {
  display: flex;
  flex-direction: column;
}
.feature .image { order: -1; }  /* image first on mobile */

@media (min-width: 768px) {
  .feature { flex-direction: row; }
  .feature .image { order: 0; }  /* natural order on desktop */
}

/* Alternating layout: every other feature reversed */
.feature:nth-child(even) {
  flex-direction: row-reverse;
}

/* Priority-based ordering for dashboards */
[data-priority="high"]   { order: -2; }
[data-priority="medium"] { order: -1; }
[data-priority="low"]    { order: 0; }

Order values and stacking

Items with the same order value are laid out in DOM order among themselves. Use integers (not floats) and keep values simple — typically -1, 0, and 1 are sufficient for most patterns.

/* Simple three-value system */
.order-first { order: -1; }
.order-none  { order: 0; }   /* default */
.order-last  { order: 1; }

Try it yourself

Mini-exercise

Create a card grid with 6 cards. Use order to make the "featured" card (3rd in DOM) appear first. Add reading-flow: flex-visual to the container. Test with keyboard Tab: does focus follow visual order? Now remove reading-flow and Tab again — notice focus jumps to the 3rd DOM position, not the visual first.
