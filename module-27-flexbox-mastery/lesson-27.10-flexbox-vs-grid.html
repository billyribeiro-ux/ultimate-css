Lesson 27.10 · Layout

Flexbox vs Grid: The Decision Tree

The question isn't "which is better" — it's "which is right for this layout." Flexbox and Grid solve different problems. This lesson gives you a clear decision framework so you never hesitate between the two again.

The core mental model

  • Flexbox = one-dimensional. Works along a single axis. Items determine the layout (content-out).
  • Grid = two-dimensional. Works across rows AND columns simultaneously. The container determines the layout (layout-in).

The decision flowchart

  1. Is the layout one-dimensional? (items in a row OR a column) → Flexbox.
  2. Is the layout two-dimensional? (items need to align in both rows and columns) → Grid.
  3. Do items determine their own size? (content-out) → Flexbox.
  4. Does the container determine item placement? (layout-in) → Grid.
  5. Is the number of items dynamic/unknown? → Flexbox (especially with wrap).
  6. Is the structure fixed and predictable? → Grid.

Use Flexbox when...

  • Laying out navigation links in a row
  • Building input groups (input + button)
  • Centering a single element
  • Creating a tag cloud that wraps
  • Aligning items in a toolbar
  • Building card internals (icon + text + badge)
  • Pushing elements apart (margin: auto trick)
  • Items should size based on their content

Use Grid when...

  • Building page-level layouts (header/sidebar/main/footer)
  • Creating card grids where cards must align in columns
  • Designing dashboard layouts with different-sized panels
  • Overlapping elements (grid items can occupy the same cell)
  • Creating form layouts with aligned labels and inputs across rows
  • Magazine-style layouts with spanning elements
  • Any layout where you think in terms of "this goes in row 2, column 3"

They work together

The best layouts use both. A typical page:

/* Grid for page structure */
.page {
  display: grid;
  grid-template: "header header" auto
                 "sidebar main" 1fr
                 "footer footer" auto / 250px 1fr;
}

/* Flex for component internals */
.header {
  display: flex;
  align-items: center;
  gap: 1rem;
}

/* Flex for the nav inside the header */
.nav {
  display: flex;
  gap: 1.5rem;
}

/* Grid for the card grid inside main */
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
  gap: 1.5rem;
}

/* Flex for card internals */
.card {
  display: flex;
  flex-direction: column;
}

Common mistakes

  • Using Grid for a simple row of buttons: Overkill. Flexbox handles this perfectly.
  • Using flex-wrap for a card grid: Cards won't align in columns. Grid's auto-fill handles this better.
  • Forcing Grid for everything: Grid adds complexity when you just need items in a line.
  • Nesting Grid inside Grid unnecessarily: Sometimes flex for the inner layout is simpler.

The quick test

Ask yourself: "Am I aligning items in one direction, or placing them on a two-dimensional grid?" If one direction → flex. If two-dimensional → grid. When in doubt, start with flex. Switch to grid when flex starts fighting you.
