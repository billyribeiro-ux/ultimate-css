Flex Wrapping Patterns

When flex items are allowed to wrap, flexbox becomes a powerful tool for responsive layouts without media queries. Tag clouds, card grids, and toolbar overflows all use flex-wrap: wrap as their foundation. But there are gotchas — especially the infamous min-width: 0 problem.

The basics of wrapping

With flex-wrap: wrap, items move to the next line when they exceed the container width. Combined with flex-basis or min-width, you control when wrapping occurs:

.container {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}
.item {
  flex: 1 1 250px;  /* grow, shrink, minimum 250px before wrapping */
}

The flex: 1 1 250px pattern means: "Start at 250px. If there's extra space, grow to fill it. If too tight, shrink — but more likely, wrap." This creates a responsive grid with no media queries.

Pattern: Tag cloud

.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem;
}
.tag {
  flex: none;         /* don't grow or shrink — content-sized */
  padding: 0.25rem 0.75rem;
  border-radius: 9999px;
}

Tags are flex: none because they should be content-sized. They simply wrap to the next line when the row is full.

Pattern: Card grid with flex-wrap

.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 1.5rem;
}
.card {
  flex: 1 1 300px;
  max-width: 400px;
}

Cards grow to fill the row but never exceed 400px. When the container is small, they stack. The max-width prevents a single card from stretching full-width on the last row.

Pattern: Toolbar overflow

.toolbar {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem;
  align-items: center;
}
.toolbar-group {
  display: flex;
  gap: 0.25rem;
  flex: none;
}

Toolbar groups stay together (they're flex: none), but the toolbar itself wraps groups to a new line when space runs out. This is how rich text editors handle narrow viewports.

The min-width: 0 gotcha

Flex items have an implicit min-width: auto, meaning they won't shrink smaller than their content. This causes text overflow:

/* Problem: long text overflows the flex container */
.item {
  flex: 1;
  /* min-width defaults to auto — content determines minimum */
}

/* Fix: allow the item to shrink below its content size */
.item {
  flex: 1;
  min-width: 0;
}

/* Also needed for text truncation inside flex items */
.item {
  flex: 1;
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

This is the most common flexbox bug. Any time text overflows a flex container, min-width: 0 on the flex item is likely the fix.

align-content for wrapped lines

When wrapping creates multiple lines, align-content controls how those lines are distributed in the cross axis. The default stretch gives each line equal height. Use align-content: flex-start to pack lines to the top.
