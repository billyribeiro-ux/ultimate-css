The Holy Grail of Centering

CSS centering used to be notoriously difficult. Today we have at least five reliable techniques. Each has a specific use case where it shines. Here they all are, compared side by side, so you always know which one to reach for.

Pattern 1: Flexbox — the all-rounder

.parent {
  display: flex;
  justify-content: center;   /* horizontal */
  align-items: center;       /* vertical */
}

When to use: centering one or more children inside a container. Works regardless of child dimensions. The default choice for component-level centering.

Pattern 2: Grid place-items — the one-liner

.parent {
  display: grid;
  place-items: center;
}

When to use: identical to flex centering but with fewer lines. Particularly clean when you want all items stacked in the center. Preferred for page-level centering (e.g., a loading spinner).

Pattern 3: Flex + margin: auto — the single-child method

.parent {
  display: flex;
}
.child {
  margin: auto;
}

When to use: centering a single child. margin: auto in a flex container absorbs all available space on both axes. Elegant for cards, modals, and hero CTAs.

Pattern 4: Absolute + translate — the overlay method

.parent {
  position: relative;
}
.child {
  position: absolute;
  top: 50%;
  left: 50%;
  translate: -50% -50%;
}

When to use: when the child must be removed from flow (overlays, tooltips, badges). The translate moves the element back by half its own dimensions. Works even when you don't know the child's size.

Pattern 5: margin: auto on a block — horizontal only

.child {
  width: fit-content;   /* or a fixed width */
  margin-inline: auto;
}

When to use: horizontal centering of a block element. The classic pattern. Does not work for vertical centering — margin-block: auto only works in flex/grid contexts.

The decision tree

  • Need both axes centered? Use Pattern 1 or 2.
  • Single child, both axes? Pattern 3 is cleanest.
  • Child must overlay content? Pattern 4.
  • Horizontal only, normal flow? Pattern 5.
  • Multiple children in a centered stack? Pattern 2 with place-items: center.

Common mistakes

  • Using text-align: center for block centering — it only centers inline/inline-block children.
  • Forgetting height on the parent — vertical centering requires the parent to have more height than the child.
  • Using margin: 0 auto without a width — auto margins collapse to zero when the element is full-width.
  • Using align-items: center without setting a height on the flex container — items are already as tall as the container, so no visible centering occurs.

Centering text vs centering boxes

These are different problems with different solutions:

/* Center text INSIDE an element */
.box { text-align: center; }

/* Center a box WITHIN its parent */
.box { margin-inline: auto; width: fit-content; }

/* Center a box both axes */
.parent { display: flex; justify-content: center; align-items: center; }

Don't confuse them. text-align centers inline content. Flex/grid/margin centers block-level boxes.

The modern default: grid place-items

For new code, display: grid; place-items: center is the recommended default because:

  • It's the fewest lines of code (2 properties).
  • It works on both axes simultaneously.
  • It handles any number of children (they stack centered).
  • No extra properties needed on children.

Use flexbox centering when you need inline (row) arrangement of centered items. Use grid centering when you just need everything centered in a container.

Mini-exercise

Create a full-viewport overlay (position: fixed; inset: 0) with a modal dialog centered using Pattern 3 (flex + margin:auto). Then add a close button positioned at top-right of the modal using Pattern 4 (absolute + translate). Both centering patterns working together in one component.
